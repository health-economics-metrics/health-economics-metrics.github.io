# 可穿戴设备验证

验证指标量化的是一款可穿戴设备的测量结果，与临床金标准（心率对应ECG心电图，睡眠对应多导睡眠图）之间的一致程度：**MAPE（平均绝对百分比误差）**、一致性相关系数、Bland–Altman一致性分析——此外还有把控真实世界数据质量的运营指标：**佩戴时间合规性**与**数据完整性**。

## 为何重要

验证是下游一切工作的前提条件：一款无法证明其测量结果与参照标准一致的设备，无法作为[数字终点](../数字终点与生物标志物/)的支撑，无法支持[远程患者监测计费](../远程患者监测经济学/)，也无法承载任何临床主张。该领域对心率验证公认的阈值为：与ECG相比，**MAPE ≤5%**（严格标准）或**≤10%**（宽松标准）。文献中的参照数据：Oura Gen 3静息心率MAPE为1.67%（CCC为0.97）；Fitbit Charge 6的MAPE约为5.5%——消费级设备如今已横跨临床级标准的边界线，这正是为什么必须按设备、按具体条件分别进行测量的原因所在。

## 计算方法

```
MAPE = (1/n) Σ |实测值_i − 参照值_i| / 参照值_i × 100

CCC（一致性相关系数） = 同时衡量相关性与系统性偏差的一致程度
      （在Pearson相关系数r的基础上，对位置/尺度偏移进行惩罚）

Bland–Altman分析：平均偏差 ± 1.96倍标准差的一致性界限——
      展示误差是否随数值大小而变化

运营层面的关卡指标：
佩戴时间合规性 = 实际佩戴时长 / 协议要求时长 × 100
数据完整性     = 实际观测数据点数 / 预期数据点数 × 100
```

验证结果必须**按活动条件**（静息、运动、睡眠）以及按人群分别报告——PPG光学传感在运动伪影、接触不良以及肤色较深的情况下表现会下降，这是一种已被记录在案、且与公平性相关的失效模式。

## 实例演算

某虚拟病房项目正在挑选一款监测用可穿戴设备。候选A：静息MAPE 2.1%，运动MAPE 11.4%。候选B：静息3.8%，运动6.9%。

```
应用场景：在家中检测病情恶化——警报由持续升高的心率触发，
而这种情况往往发生在活动期间。
候选A的头条数字（2.1%）在宣传册上很好看，但候选B更适合这一
实际应用场景：在与警报相关的条件（运动）下，A方案在心率100时
误差达11.4% = ±11 bpm——这一误差幅度横跨了整个警报阈值区间，
会导致误报升级（每次都意味着一次护士出诊，约£40）或漏报。

误报经济学：500名患者 × 每周2次额外误报 × £40
= 因选错验证数字而产生每年£208万的误差成本。
```

## 与软件工程的联系

工程师在选择传感器时是验证数据的使用者，而在构建测量类功能时则是验证数据的*生产者*——这两种角色需要遵循相同的纪律：应在实际部署条件下测试，而非在演示条件下测试（软件领域的对应说法是：应基于你自己的生产环境工作负载做基准测试，而非供应商自己的）。佩戴时间与数据完整性属于产品工程层面的结果——舒适度、电池续航、充电习惯设计与同步可靠性，共同决定了"30天内16天"这一远程患者监测计费关卡（参见[远程患者监测经济学](../远程患者监测经济学/)）能否达成，也决定了试验数据集是否可供分析。应把缺失数据当作一种有设计意义的信号来对待：从一开始就在数据模式中区分"未佩戴"、"已佩戴但无信号"与"同步失败"这几种情形——一旦被统一压缩成空值，它们会污染下游的每一项分析。

## 陷阱

- **汇总MAPE掩盖了特定条件下的失效**——这正是上述实例演算中的陷阱所在。
- **验证人群 ≠ 部署人群**：年龄、肤色、震颤、肥胖程度，都会改变光学传感器的误差；应核查研究所用的人口统计学特征。
- **在需要一致性的场合，却只报告相关性**：高Pearson相关系数、外加系统性偏差，在绝对阈值判定下依然会造成分类错误——应坚持要求提供CCC/Bland–Altman分析。
- **通过插补虚增完整性**：把被填补的缺口当作实际观测数据来报告。
