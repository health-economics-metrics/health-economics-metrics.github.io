# Рамочная программа стандартов доказательств NICE (РСД)

РСД — это рамка NICE, определяющая **сколько доказательств нужно технологии цифрового здравоохранения, пропорционально её риску**. Это самое близкое к официальному ответу на вопрос «что нам нужно доказать, прежде чем NHS купит наше приложение?»

## Почему это важно

РСД (впервые выпущена в 2019 году, обновлена в 2022 году для охвата ИИ и адаптивных алгоритмов) классифицирует технологии цифрового здравоохранения по уровням по клинической функции, с **кумулятивными** стандартами доказательств — 21 стандарт в 5 группах (факторы дизайна, ценность, производительность/эффективность, экономическое воздействие, развёртывание):

```
Уровень A — системные услуги, без прямого результата для пациента (напр., электронное планирование)
         → базовые стандарты: достоверность, защита данных, техническая гарантия
Уровень B — информирование, простой мониторинг, коммуникация (напр., дневник симптомов)
         → + доказательства пользы для пользователя, соответствующая надёжность
Уровень C — лечение, диагностика или активное руководство клиническим управлением
         → + сравнительные доказательства эффективности высокого качества (в идеале РКИ)
           и экономический анализ
```

Для экономических доказательств [анализ затрат и последствий](../анализ-затрат-и-последствий/) приемлем для большинства уровней; [анализ затрат и полезности](../анализ-затрат-и-полезности/) ожидается при наивысшем риске. РСД определяет вашу **стоимость доказательств для выхода на рынок** — заложите её в бюджет как любую другую стоимость разработки.

## Расчёт

Никаких формул — таблица решений. Оперативный расчёт коммерческий:

```
Требуемая инвестиция в доказательства = f(уровень)
  Уровень A: документация + гарантия ≈ £10тыс–50тыс
  Уровень B: наблюдательное/сравнительное исследование пользы для пользователя ≈ £50тыс–250тыс
  Уровень C: сравнительное исследование уровня РКИ + экономическая модель ≈ £250тыс–2 млн+

Позиционируйте заявления вашего продукта осознанно: заявление «поддерживает
клинические решения» вместо «информирует пациентов» перемещает вас на уровень
и может увеличить счёт в 10 раз.
```

## Разобранный пример

Производитель приложения-напоминания о приёме лекарств рассматривает добавление функции рекомендации по корректировке дозы.

- Как приложение-напоминание: **Уровень B** — достаточно исследования когорты, показывающего улучшение приверженности.
- С рекомендациями по дозе: **Уровень C** — сравнительные доказательства эффективности (вероятно, РКИ против обычной помощи) плюс экономический анализ.

Если РКИ стоит £600тыс, а инкрементальный доход от функции дозы составляет £200тыс/год, функция должна сохранять ценность в течение 3+ лет, прежде чем затраты на доказательства окупятся — продуктовое решение, которое выглядит совершенно иначе, когда учтена цена уровня РСД. Многие команды выпускают продукт Уровня B и поэтапно вводят заявление Уровня C после финансирования.

## Связь с программной инженерией

РСД — самый переносимый паттерн управления в этом репозитории: **требования доказательств, градуированные по риску, для внедрения инструментов**. Внутренняя версия: форматировщику кода нужна демонстрация (Уровень A); инструменту продуктивности, заявляющему сэкономленные часы, нужен измеренный пилот (Уровень B); воротам ИИ, автоматически блокирующим развёртывания или автоматически пишущим клинический код, нужны доказательства уровня контролируемого испытания перед развёртыванием на всю организацию (Уровень C). Пропорциональные доказательства останавливают оба режима отказа — бюрократию, душащую тривиальные инструменты, и интуитивную поставку значимых. См. также [ускоренный путь DiGA](../ускоренный-путь-diga-в-германии/) для дополнения «предварительное внедрение с крайним сроком доказательств».

## Подводные камни

- **Неправильная классификация уровня из-за желаемого мышления** — регуляторы и покупатели классифицируют по тому, что продукт *делает*, а не что говорит маркетинг.
- **Доказательства, построенные после продукта**: переделка РКИ на уже выпущенный продукт без инструментирования или равновесия медленна и часто невозможна.
- **Соответствие РСД и забвение остального**: РСД сидит рядом с DTAC (клиническая безопасность, защита данных, совместимость) и, для ИИ, регуляторным разрешением — см. [регуляторную оценку ИИ](../регуляторная-оценка-ии/).
