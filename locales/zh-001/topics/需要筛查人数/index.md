# 需要筛查人数 (Number Needed to Screen, NNS)

NNS 是为在规定的随访期内预防**一例**不良结局而需要筛查（而不仅仅是治疗）的人数，取决于人群的基线风险，以及早期发现和治疗所实现的相对风险降低。它是 NNT 在筛查项目层面的对应物：NNT 问的是要*治疗*多少人才能预防一例结局；NNS 问的是要有多少人走完整个*筛查再治疗*的路径才能达到这一点。

## 为什么重要

Rembold 在 1998 年提出 NNS，正是为了让筛查项目可以与治疗在同一基础上比较，因为筛查检验的标题相对风险降低数字掩盖了两件治疗不会掩盖的事：实际被邀请参加筛查的人群的基线风险，以及所有接受筛查的人都要承担检验成本和假阳性的负担，而不只是之后受益的那一小部分人。英国国家筛查委员会的成本效果关卡（见[筛查经济学](../筛查经济学/)）就建立在这个区分之上——一个在低基线风险人群中相对风险降低很可观的筛查项目，其 NNS 仍可能达到数千，此时每预防一例结局的项目成本才成为真正的问题。

## 计算方法

```
NNS = 1 / (基线风险 × 相对风险降低)

基线风险       = 随访期内被筛查人群中出现该结局的概率 (0–1)
相对风险降低   = 筛查所使能的早期治疗所实现的风险按比例降低 (0–1)

每预防一例结局的项目成本 = NNS × 每次筛查成本
```

直接与 [NNT](../需治疗人数/) 比较：NNS 把整个“筛查 → 诊断 → 治疗”漏斗的有效性折叠成一个数字，而 NNT 假定患者已经被诊断并开始了治疗。

## 算例

某筛查项目的目标人群在研究期内事件的基线风险为 2%（`基线风险 = 0.02`），早期发现实现了 25% 的相对风险降低（`相对风险降低 = 0.25`）：

```
NNS = 1 / (0.02 × 0.25) = 1 / 0.005 = 200

需要筛查 200 人才能预防一例结局。

每次筛查 £50：
每预防一例结局的项目成本 = 200 × £50 = £10,000
```

这 £10,000 应与结局本身的成本以及它本会造成的 QALY 损失相权衡——这正是[预防经济学](../预防经济学/)对一般预防项目所做的比较。

## 与软件工程的关联

NNS 就是“要有多少用户、事件或请求通过一条检测或分诊流程，才能抓到一个值得行动的真阳性”——与基于告警的监控和分诊系统直接相关，其中低患病率的目标状态会把 NNS 推高，就像它会让阳性预测值崩塌一样（见[筛查经济学](../筛查经济学/)和[临床 AI 评估](../临床AI评估/)）。一条每抓到一次真实命中就要处理 200 个事件的监控规则，只有当这次命中的价值至少是每个事件分诊成本的 200 倍时才值得运行——与上面卫生示例是同样的算术。

## 陷阱

- **忽视对基线风险的依赖**：同一个筛查检验或项目，在高风险和低风险人群中的 NNS——以及成本效果——差别极大。除非指明计算所针对的人群，否则永远不要呈现 NNS。
- **误读分母**：NNS 计的是*接受筛查*的人，而不是检测呈阳性或开始治疗的人——它已经包含了整个漏斗的有效性，所以绝不应与只统计阳性者的指标比较。
- **跨随访期比较**：较短的随访期通常会推高 NNS，因为该窗口内观察到的事件更少。只有按同样的随访时长计算的 NNS 数字才具有可比性。
