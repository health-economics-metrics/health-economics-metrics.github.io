# 急诊就诊避免

急诊就诊避免衡量的是因上游干预（分诊应用、远程监测、虚拟病房、紧急护理分流）而被避免的急诊科就诊与紧急入院。它将"我们更早发现了问题"这句话，转化为一个可核算成本的主张。

## 为何重要

急诊是整个系统中最昂贵的常规医疗场所（按"全国成本采集"/PSSRU数据，一次急诊就诊的单位成本在£250–£400区间；一次紧急入院则达数千英镑），而急诊拥挤会连锁引发救护车延误与择期手术取消。任何能在上游安全化解需求的手段——自我照护建议、当日基层医疗、社区响应——都能在系统压力最大的那个环节买到宝贵的产能。这也是症状自查工具、111式分诊服务，以及[远程患者监测](../远程患者监测经济学/)最常见的标准效益线。

## 计算方法

```
避免的就诊次数 = 人群规模 × (基线发生率 − 干预后发生率)
毛节省额       = 避免的就诊次数 × 每次就诊单位成本
                （+ 避免的入院次数 × 入院成本，需单独计算）

净节省额       = 毛节省额 − 干预成本 − 新增路径使用成本
                （被分流的需求并非零成本：一次111热线通话、
                 一个全科医生诊位、一天虚拟病房，都各自有其单位成本）
```

这一因果主张需要一个对照组：急诊就诊率本身存在趋势变化与季节性波动，单纯的前后对比无法证明任何东西。

## 实例演算

某针对3,000名高风险患者的慢阻肺（COPD）远程监测服务。经匹配对照评估显示，因病情加重导致的急诊就诊率从每患者-年0.9次降至0.7次，紧急入院率从0.5降至0.42。

```
避免的就诊 = 3,000 × 0.2  = 600次 × £300   = £180,000
避免的入院 = 3,000 × 0.08 = 240次 × £3,800 = £912,000
毛节省额合计                                 每年£1,092,000

成本：监测服务£600,000；额外的社区护士响应£150,000
净节省额 ≈ 每年+£342,000——此外还有病情加重被更早治疗所带来的QALY获益。
```

请注意，起主导作用的是"入院避免"这一项：仅凭避免就诊，往往不足以支付一项监测服务的成本；真正的价值所在，是*避免入院*。

## 与软件工程的联系

这正是**事件避免经济学**。可观测性、金丝雀发布与早期预警系统的价值，就是被避免的"急诊就诊"——寻呼告警、作战室、一级严重事件（sev-1），每一次都有其负荷成本（工程师工时 × 费率 + 客户影响）。相同的建模规则同样适用：需扣除新增上游路径本身的成本（警报分诊本身并非零成本）；需警惕替代效应（只制造工作量、却并未真正预防事件的警报，是"健康焦虑"，而非真正的健康）；并需以对照组来证明反事实假设（团队的事件发生率本身也会随时间变化并回归均值，正如急诊就诊率一样）。

## 陷阱

- **均值回归**：因某个糟糕年份而被选中的高风险队列，即便不加干预也会自行好转；匹配对照或阶梯式楔形设计是必不可少的。
- **供给诱导需求**：便捷的数字化分诊可能*增加*总接触量（因为寻求帮助的门槛降低了），同时却降低了急诊科所占的份额——应核算整个系统的总成本。
- **按平均成本为就诊估值**，而急诊的固定成本实际上并不会因此下降——参见[边际成本与平均成本](../边际成本与平均成本/)。
