# اقتصاد وحدة السحابة (FinOps)

اقتصاد وحدة السحابة يترجم إنفاق السحابة الخام إلى **تكلفة لكل وحدة إخراج** - لكل عميل، لكل معاملة، لكل حالة محلولة، لكل رمز (token). هذه هي قدرة FinOps التي تحوِّل "فاتورة AWS لدينا 400 ألف£/شهر" إلى "خدمة مريض واحد تكلّف 0.83£".

## لماذا يهم هذا

أرقام الإنفاق الإجمالي لا تستطيع الإجابة على الأسئلة المهمة: هل يزداد المنتج كفاءة أم يقل؟ هل النمو يحسّن الهامش أم يدمّره؟ ما الذي ينبغي أن نتقاضاه؟ تكاليف الوحدة تجيب على الثلاثة. بالنسبة للصحة الرقمية خصوصًا، "التكلفة لكل حالة محلولة" *هي* تكلفة وحدة خدمة صحية - قابلة للمقارنة مباشرة بأرقام [مجموعة التكلفة الوطنية](../التعريفة-الوطنية-وتكاليف-الوحدة/) التي يستخدمها المُفوِّض لكل خدمة أخرى، ما يجعلها اللغة الطبيعية لتسعير المسارات الرقمية مقابل التقليدية.

## طريقة الحساب

```
تكلفة الوحدة = التكلفة الإجمالية المخصَّصة (شاملة تكاليف المشترك/المنصة) / الوحدات المُقدَّمة

فئتان:
  وحدات كفاءة الموارد: تكلفة/جيجابايت مُخزَّن، تكلفة/ساعة-معالج افتراضي، تكلفة/رمز،
                       تكلفة/دقيقة-بناء
  وحدات الأعمال:        تكلفة/عميل، تكلفة/معاملة، تكلفة/استشارة،
                       تكلفة/حالة-محلولة

انضباط الحدّي مقابل المتوسط يُطبَّق (marginal-vs-average-cost.md):
الإنفاق المُلتزَم به/المحجوز يجعل تكلفة الوحدة الحدّية ≈ 0 حتى خطوة
الالتزام التالية - سعِّر قرارات التوسّع عند الحدّي، اتجاهات الكفاءة
عند المتوسط.
```

## مثال محلول

خدمة فرز رقمية: إنفاق سحابة 62,000£/شهر (حوسبة 30 ألف£، بيانات 18 ألف£، تخصيص منصة مشتركة 14 ألف£)، تعالج 380,000 حالة فرز/شهر:

```
التكلفة المتوسطة لكل حالة = 62,000 / 380,000 ≈ 0.163£

مقارنة المُفوِّض: فرز هاتفي ≈ 8-12£/مكالمة، استشارة طبيب أسرة ≈ 42£
← الحالة الرقمية تعمل بنحو 2% من أرخص بديل بشري - اقتصاد تحويل
القناة في gds-service-metrics.md، من جانب التكلفة.

فحص الاتجاه: العام الماضي 0.21£/حالة عند 240 ألف حالة ← اقتصاد
حجم يتحسّن (تكاليف المنصة الثابتة تُستهلَك)، يستحق عنوانًا في المراجعة الفصلية.
```

## الصلة بهندسة البرمجيات

اقتصاد الوحدة هو حيث تصبح قرارات الهندسة مقروءة ماليًا: بنية تنصّف التكلفة لكل حالة هي ميزة تسعير؛ وبنية تتوسّع فوق-خطيًا هي قنبلة موقوتة لا تُرى إلا في هذا المقياس. الممارسات المنقولة من حساب تكاليف الصحة: **نشر قواعد التخصيص** (التكاليف المشتركة شوّهت أرقام الوحدة حتى وحّد PLICS حساب التكلفة على مستوى المريض - تخصيص تكلفة منصتك يحتاج الصرامة نفسها)؛ **اختر الوحدات التي يفكّر بها المُشتري** (المُفوِّضون يشترون حالات، لا معالجات افتراضية)؛ وأدخل تكاليف الوحدة في كل نموذج [نسبة فعالية التكلفة التزايدية](../نسبة-فعالية-التكلفة-التزايدية/) و[أثر الميزانية](../تحليل-أثر-الميزانية/) كمقام التكلفة الموثوق. لمزايا الذكاء الاصطناعي، الوحدة هي الرمز (token) - انظر [اقتصاد وحدة الاستدلال](../اقتصاد-وحدة-الاستدلال/).

## المزالق

- **تجاهل التكاليف المشتركة**: تكاليف الوحدة المستثنية لتخصيصات المنصة/الأمان/الاستدعاء تُقلِّل التقدير بنسبة 30-50% وتنهار عند التدقيق.
- **مقامات زائفة**: "التكلفة لكل استدعاء API" تُجمِّل؛ "التكلفة لكل حالة مريض مكتملة" تُفيد.
- **تسعير القرارات الحدّية بالتكلفة المتوسطة**: تحميل الفرق تكلفة الوحدة المتوسطة على استخدام حرّ حدّيًا يقود إلى رنجمة تجنّب الهدر (انظر [التعريفة الوطنية](../التعريفة-الوطنية-وتكاليف-الوحدة/) للنسخة الخاصة بـNHS من علّة هذا الحافز).
