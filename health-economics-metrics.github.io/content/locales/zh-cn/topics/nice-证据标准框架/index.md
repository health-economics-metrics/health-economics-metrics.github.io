# NICE 证据标准框架 (NICE Evidence Standards Framework，ESF)

ESF 是 NICE 制定的框架，用于规定**一项数字健康技术需要多少证据，须与其风险相称**。它是"NHS 采购我们的应用之前，我们必须证明什么"这一问题最接近官方答案的东西。

## 为什么重要

ESF（首次发布于 2019 年，2022 年更新以覆盖 AI 和自适应算法）按临床功能把数字健康技术划分为若干层级，并配以**累进式**证据标准——5 个类别共 21 项标准（设计要素、价值、绩效/有效性、经济影响、部署）：

```
A 层 — 系统服务，无直接患者结果（例如电子排班）
       → 基础标准：可信度、数据保护、技术保障
B 层 — 告知、简单监测、沟通（例如症状日记）
       → + 用户获益证据、适当的可靠性
C 层 — 治疗、诊断或主动指导临床管理
       → + 高质量的对照有效性证据（理想情况下为 RCT）
         及经济学分析
```

对经济学证据而言，[成本后果分析](../成本后果分析/)在大多数层级都可接受；在最高风险层级则要求[成本效用分析](../成本效用分析/)。ESF 定义了你的**进入市场所需的证据成本**——应像对待任何其他建设成本一样，为它编列预算。

## 计算方法

没有公式——只有一张决策表。真正的运算是商业层面的：

```
所需证据投入 = f(层级)
  A 层：文档编制 + 保障 ≈ £10k–50k
  B 层：观察性/对照性用户获益研究 ≈ £50k–250k
  C 层：RCT 级对照研究 + 经济学模型 ≈ £250k–£2M+

有意识地设定产品的主张定位：把主张从"辅助患者知情"改为
"支持临床决策"，会把产品提升一个层级，账单可能因此翻十倍。
```

## 算例

某用药提醒应用的开发者考虑增加一项剂量调整建议功能。

- 作为提醒应用：**B 层**——一项显示依从性改善的队列研究即已足够。
- 加入剂量建议：**C 层**——需要对照有效性证据（很可能是与常规照护对比的 RCT）加上经济学分析。

如果这项 RCT 花费 £600k，而剂量功能带来的增量收入为每年 £200k，那么该功能必须能维持 3 年以上的价值，证据成本才能收支平衡——一旦把 ESF 层级的代价计入，这项产品决策会呈现出截然不同的样貌。许多团队会先交付 B 层产品，把 C 层的主张留待获得资金后再逐步展开。

## 与软件工程的关联

ESF 是本仓库中最具可迁移性的治理模式：**按风险分层设定工具采纳所需的证据要求**。内部版本：一个代码格式化工具只需一次演示（A 层）；一个声称节省工时的生产力工具需要一次实测试点（B 层）；一个自动拦截部署或自动编写临床代码的 AI 关卡，在全组织推广之前需要达到对照试验级别的证据（C 层）。与风险相称的证据能同时防止两种失败模式——官僚主义扼杀琐碎工具，以及凭感觉就把后果严重的工具推向全组织。另见[德国 DiGA 快速通道](../德国-diga-快速通道/)，它是"带证据期限的临时采纳"这一互补做法。

## 陷阱

- **出于一厢情愿而误判层级**——监管机构和采购方是按产品*实际做什么*来分类，而不是按营销话术。
- **在产品之后才补建证据**：在没有埋点或没有均势 (equipoise) 的已上线产品上事后补做 RCT，既缓慢又往往不可行。
- **满足了 ESF 却忘了其余要求**：ESF 与 DTAC（临床安全、数据保护、互操作性）并存，对 AI 而言还需监管批准——参见 [AI 监管评估](../ai监管评估/)。
