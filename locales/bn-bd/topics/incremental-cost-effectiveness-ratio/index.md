# বর্ধিত ব্যয়-কার্যকারিতা অনুপাত (ICER)

ICER হলো একটি বিকল্পকে পরবর্তী-সর্বোত্তম বিকল্পের পরিবর্তে বেছে নেওয়ার সময় স্বাস্থ্য প্রভাবের প্রতি অতিরিক্ত এককে অতিরিক্ত ব্যয়। এটি স্বাস্থ্য প্রযুক্তি মূল্যায়নের প্রধান সংখ্যা। (যখন প্রভাব একক QALY হয়, একে বর্ধিত ব্যয়-উপযোগিতা অনুপাত, ICUR-ও বলা হয়।)

## কেন এটি গুরুত্বপূর্ণ

স্বাস্থ্য ব্যবস্থা কখনোই একটি প্রযুক্তিকে বিচ্ছিন্নভাবে মূল্যায়ন করে না — সবসময় *বর্ধিতভাবে*, অন্যথায় যা করা হতো তার বিপরীতে। NICE একটি প্রযুক্তির ICER-কে এর **প্রতি QALY £২০,০০০–£৩০,০০০** থ্রেশহোল্ডের সাথে তুলনা করে; US ICER ইনস্টিটিউট $৫০,০০০–$২০০,০০০/QALY জুড়ে রিপোর্ট করে; কানাডা প্রায় CAD$৫০,০০০/QALY নিয়ে কাজ করে। আপনার পণ্য একটি জাতীয় স্বাস্থ্যসেবার জন্য "মূল্যবান" কিনা তা, আনুষ্ঠানিকভাবে, এর ICER স্থানীয় থ্রেশহোল্ড অতিক্রম করে কিনা তার উপর নির্ভর করে। [প্রদানের ইচ্ছার সীমা](../willingness-to-pay-thresholds/) দেখুন।

## গণিত

```
ICER = (ব্যয়_নতুন − ব্যয়_তুলনাকারী) / (প্রভাব_নতুন − প্রভাব_তুলনাকারী)
     = ΔC / ΔE
```

ব্যাখ্যার নিয়ম:

- ΔC < 0, ΔE > 0: নতুন বিকল্প **আধিপত্য করে** — সস্তা এবং ভালো; কোনো অনুপাত প্রয়োজন নেই।
- ΔC > 0, ΔE > 0: ICER গণনা করুন, থ্রেশহোল্ড λ-এর সাথে তুলনা করুন; ICER < λ হলে গ্রহণ করুন।
- ΔC > 0, ΔE < 0: নতুন বিকল্প আধিপত্যপ্রাপ্ত — প্রত্যাখ্যান করুন।
- ΔE = 0-এর কাছাকাছি অনুপাত খারাপভাবে আচরণ করে — র‍্যাঙ্কিংয়ের জন্য [নিট আর্থিক সুবিধা](../net-monetary-benefit/) পছন্দ করুন।

তুলনাকারী অবশ্যই *পরবর্তী-সর্বোত্তম অ-আধিপত্যপ্রাপ্ত বিকল্প* হতে হবে, "কিছু না করা" নয় — [আধিপত্য এবং দক্ষতা সীমান্ত](../dominance-and-efficiency-frontier/) দেখুন।

## সমাধানকৃত উদাহরণ

হৃদরোগে আক্রান্ত রোগীদের জন্য একটি দূরবর্তী-পর্যবেক্ষণ সেবা, প্রতি ১,০০০ রোগী/বছর, স্বাভাবিক যত্নের বিপরীতে:

```
ব্যয়:  সেবা £900,000; এড়ানো ভর্তি £600,000 সাশ্রয় করে
       ΔC = 900,000 − 600,000 = £300,000
প্রভাব: আগাম হস্তক্ষেপ ২৫ QALY লাভ করে
       ΔE = 25

ICER = 300,000 / 25 = £12,000/QALY
```

£১২,০০০/QALY NICE-এর £২০,০০০ থ্রেশহোল্ডের অনেক নিচে — একটি শক্তিশালী ক্ষেত্র। *নিট* ব্যয় কতটা গুরুত্বপূর্ণ তা লক্ষ্য করুন: £৬০০,০০০ অফসেট ছাড়া ICER হতো £৩৬,০০০/QALY এবং ক্ষেত্রটি সম্ভবত ব্যর্থ হতো। ব্যয় অফসেট এবং তাদের প্রমাণের গুণমানই যেখানে এই বিশ্লেষণগুলো জেতে এবং হারে ([এড়ানো নিম্নধারা ব্যয়](../avoided-downstream-costs/) দেখুন)।

## সফটওয়্যার প্রকৌশলের সাথে সংযোগ

ICER-এর শৃঙ্খলা প্রকৌশল সিদ্ধান্তে সম্পূর্ণভাবে স্থানান্তরযোগ্য:

```
(বিকল্প B-এর ব্যয় − বিকল্প A-এর ব্যয়) / (ফলাফল B − ফলাফল A)
```

— প্রতি অতিরিক্ত ডেপ্লয়ে বর্ধিত ব্যয়, প্রতি সাশ্রয়ী প্রকৌশলী-ঘণ্টায়, প্রতি এড়ানো ঘটনায় — সবসময় কিছু না করার বিপরীতে নয়, পরবর্তী-সর্বোত্তম বিকল্পের বিপরীতে। চুরি করার মতো দুটি অভ্যাস: (১) *তুলনাকারী স্পষ্টভাবে উল্লেখ করুন*; বেশিরভাগ টুল ROI দাবি গোপনে একটি খড়ের পুতুলের সাথে তুলনা করে; (২) *প্রথমে ব্যয় নিট করুন* — একটি টুল যার £১০০ হাজার খরচ কিন্তু বিদ্যমান £৮০ হাজার ব্যয় প্রতিস্থাপন করে তার ΔC = £২০ হাজার।

## ঝুঁকিপূর্ণ দিক

- **তুলনাকারী কারচুপি**: একটি পুরনো বা কৃত্রিমভাবে খারাপ বেসলাইনের সাথে তুলনা করলে ΔE বাড়িয়ে ICER তোষামোদ করে।
- **বর্ধিতের পরিবর্তে গড়**: একটি সম্পূর্ণ কর্মসূচির প্রতি QALY ব্যয় তার সম্প্রসারণ বা গ্রহণের ICER নয়।
- **বিন্দু-অনুমান পূজা**: ICER দুটি অনিশ্চিত পার্থক্যের অনুপাত; [PSA এবং CEAC](../probabilistic-sensitivity-analysis/)-এর মাধ্যমে অনিশ্চয়তা রিপোর্ট করুন।
- **নেতিবাচক ICER অস্পষ্ট** (সস্তা-এবং-ভালো বনাম দামি-এবং-খারাপ একই চিহ্ন দেয়) — কোন চতুর্ভাগে তা না বলে কখনোই নেতিবাচক ICER রিপোর্ট করবেন না।
