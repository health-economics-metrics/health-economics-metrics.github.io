# 流動指標

流動指標衡量工作在交付系統中流動的方式：週期時間、前置時間、吞吐量、在製品數量（WIP）以及流動效率。它們遵循利特爾法則（Little's Law）——與支配醫院床位和等候名單的排隊數學完全相同。

## 為何重要

大多數交付時間並非真正的"工作"——而是"等待"。針對知識工作的流動效率研究一貫發現，任務處於實際被處理狀態的時間通常僅佔其總耗時的**5–15%**；其餘時間都花在了排隊上。這意味著最廉價的提速手段是清除佇列，而非招聘更多人——醫院病患流轉專案在床位問題上發現的恰恰正是這一洞見。對於任何存在[延遲成本](../延遲成本/)的事物而言，流動指標能定位延遲成本究竟累積在何處。

## 計算方法

```
週期時間   = t(完成時刻) − t(開始時刻)
前置時間   = t(交付時刻) − t(請求時刻)     （包含工作開始前的排隊時間）
吞吐量     = 已完成專案數 / 週期
在製品數量 = 已開始但尚未完成的專案數
流動效率   = 實際處理時間 / (實際處理時間 + 等待時間) × 100

利特爾法則：  平均在製品數量 = 吞吐量 × 平均週期時間
             （等價地：週期時間 = 在製品數量 / 吞吐量）
```

利特爾法則正是槓桿所在：在吞吐量固定的情況下，削減在製品數量會按比例縮短週期時間。它同樣支配著醫院的運轉：`佔用床位數 = 每日入院數 × 住院時長`。

## 實例演算

某團隊手頭有40個在製品任務，每週完成10個：週期時間 = 40/10 = 4周。他們設定了在製品數量上限，將在製品削減到15個：週期時間 = 15/10 = **1.5周**——同樣的人員，同樣的吞吐量，交付速度提升62%，全部僅僅來自佇列紀律的改變。

以延遲成本定價：假設每個任務平均每週的延遲成本為£3,000，如今每個任務在佇列中少滯留2.5周：每週10個任務 × 2.5 × 3,000 = **每週消除£75,000的延遲成本**——而這項政策改變本身沒有任何成本。

醫院版本的映象：每日40例入院 × 住院時長6.0天 = 240張床位；若將住院時長內的非臨床等待時間削減至5.6天，則可釋放16張床位（參見[住院時長](../住院時長/)）——同一條法則，同一個槓桿。

## 與軟體工程的聯絡

流動指標是交付工程與醫療營運之間的共同語言：

- **PR子階段基準資料**（LinearB，約800萬條PR資料）：卓越水平的接手時間 < 7小時，評審時間 < 6小時，總週期 < 約26小時——接手時間純粹就是排隊等待，是最先應該著手解決的問題。
- **[等候名單](../等候名單影響/)**就是積壓任務；**[轉診至治療（RTT）](../轉診至治療/)**就是前置時間；**[床位佔用](../節省的床位天數/)**就是在製品數量。改進手段在兩個方向上都可以相互遷移：在製品數量上限 ↔ 入院平滑處理；排隊時間埋點 ↔ 路徑階段追蹤。
- 流動效率低於15%在這兩個領域都屬於常態，且二者都容易將其隱藏起來，因為*人*總是忙碌的，而*工作*卻在等待——應測量"工作"的時鐘，而非"工作者"的時鐘。

## 陷阱

- **崇拜利用率**：將工作者利用率推向100%會使佇列時間呈非線性爆炸式增長（M/M/1模型：等待時間 ∝ ρ/(1−ρ)）——這正是佔用率95%的醫院陷入停滯、以及分配率95%的團隊陷入停滯的原因所在。
- **對偏斜分佈取平均值**：週期時間往往呈重尾分佈；應以百分位數（如p85）預測，而非均值。
- **透過在上游拒絕工作來削減在製品數量，卻將其稱為流動改進**——需求並未消失，它只是排到了測量邊界之外去了（醫院版本的對應情形：救護車在急診科外排隊等候）。
