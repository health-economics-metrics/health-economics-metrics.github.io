# Система стандартов доказательности NICE (NICE Evidence Standards Framework, ESF)

ESF — это система NICE, определяющая **сколько доказательств нужно цифровой медицинской технологии, пропорционально её риску**. Это самый близкий к официальному ответ на вопрос «что мы должны доказать, прежде чем NHS купит наше приложение?».

## Почему это важно

ESF (впервые выпущена в 2019 году, обновлена в 2022 году для охвата ИИ и адаптивных алгоритмов) классифицирует цифровые медицинские технологии по уровням в зависимости от клинической функции, с **накопительными** стандартами доказательности — 21 стандарт в 5 группах (факторы дизайна, ценность, эффективность/результативность, экономическое воздействие, развёртывание):

```
Уровень A — системные сервисы, без прямого исхода для пациента (например, составление графиков дежурств)
         → базовые стандарты: достоверность, защита данных, техническая гарантия
Уровень B — информирование, простой мониторинг, коммуникация (например, дневник симптомов)
         → + доказательства пользы для пользователя, надлежащая надёжность
Уровень C — лечение, диагностика или активное руководство клиническим ведением
         → + высококачественные доказательства сравнительной эффективности (в идеале RCT)
           и экономический анализ
```

Для экономических доказательств [анализ «затраты-последствия»](../анализ-затраты-последствия/) приемлем для большинства уровней; [анализ «затраты-полезность»](../анализ-затраты-полезность/) ожидается на уровне наивысшего риска. ESF определяет ваши **доказательные затраты на выход на рынок** — закладывайте их в бюджет как любые другие затраты на разработку.

## Математика

Формул нет — таблица решений. Действующее вычисление коммерческое:

```
Требуемые инвестиции в доказательства = f(уровень)
  Уровень A: документация + гарантия ≈ £10k–50k
  Уровень B: наблюдательное/сравнительное исследование пользы для пользователя ≈ £50k–250k
  Уровень C: сравнительное исследование уровня RCT + экономическая модель ≈ £250k–£2M+

Формулируйте заявления о продукте осознанно: заявление «поддерживает клинические
решения» вместо «информирует пациентов» переводит вас на уровень выше и может увеличить счёт в 10 раз.
```

## Практический пример

Разработчик приложения-напоминания о приёме лекарств рассматривает добавление функции рекомендации по коррекции дозы.

- Как приложение-напоминание: **Уровень B** — достаточно когортного исследования, показывающего улучшение приверженности.
- С рекомендациями по дозе: **Уровень C** — доказательства сравнительной эффективности (вероятно, RCT против обычной помощи) плюс экономический анализ.

Если RCT стоит £600 тыс., а инкрементальная выручка от функции дозирования — £200 тыс./год, функция должна удерживать ценность более 3 лет, прежде чем затраты на доказательства окупятся — продуктовое решение, выглядящее совершенно иначе, когда учтён уровень ESF. Многие команды выпускают продукт уровня B и откладывают заявку уровня C до появления финансирования.

## Связь с разработкой программного обеспечения

ESF — самый переносимый паттерн управления в этом репозитории: **требования к доказательствам, взвешенные по риску, для принятия инструмента**. Внутренняя версия: форматтеру кода нужна демонстрация (уровень A); инструменту продуктивности, заявляющему сэкономленные часы, нужен измеренный пилот (уровень B); ИИ-шлюзу, автоматически блокирующему деплои или автоматически пишущему клинический код, нужны доказательства уровня контролируемого испытания перед развёртыванием на всю организацию (уровень C). Пропорциональные доказательства останавливают оба режима отказа — бюрократию, душащую тривиальные инструменты, и поставку значимых инструментов на одних ощущениях. См. также [ускоренный путь DiGA](../ускоренный-путь-diga-в-германии/) для дополняющего паттерна «предварительное принятие с дедлайном доказательств».

## Подводные камни

- **Неверная классификация уровня из желаемого мышления** — регуляторы и покупатели классифицируют по тому, что продукт *делает*, а не по тому, что говорит маркетинг.
- **Доказательства, построенные после продукта**: ретроспективное встраивание RCT в уже выпущенный продукт без инструментирования или равновесия обычно медленно и часто невозможно.
- **Выполнение ESF и забвение остального**: ESF сосуществует с DTAC (клиническая безопасность, защита данных, интероперабельность) и, для ИИ, регуляторным допуском — см. [регуляторную оценку ИИ](../регуляторная-оценка-ии/).
