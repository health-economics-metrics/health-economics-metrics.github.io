# 下流のリソース最適化

シニアな医療従事者 — GP、シニアレジストラー、コンサルタント — の1時間を節約することは、しばしば、臨床的な承認を待っている看護師、事務クラーク、セラピストからなる多職種チーム(MDT)全体のボトルネックによる遅延を防ぎます。ボトルネックを解消することの価値は、その下流にいる全員のスループットです。

## なぜ重要か

医療は承認の連鎖の上で動いています:退院はコンサルタントの承認を待ち、治療計画はMDTのレビューを待ち、紹介はトリアージを待ちます。制限となる役割が遅れると、費用は1人の時間ではなく、依存するすべての役割にわたる無為あるいは滞留した時間、加えて宙ぶらりんになる患者の時間です(追加の[病床日](../節約された病床日数/)、より長い[RTT待機](../紹介から治療まで/))。これは、臨床経路に適用された制約理論です:*制約において*節約された1時間は、システム全体の限界スループットの価値があります;他の場所で節約された1時間ははるかに価値が低いのです。

## 数式

```
解消の価値 = Σ 下流の役割にわたる(解放された滞留時間 × 単位費用)
           + 経路のスループット獲得 × 経路完了1件あたりの価値

対比:制限になっていない役割で節約された同じ1時間の価値 ≈ その役割の
容量価値のみ(医療従事者の時間を参照)。
```

制約を実証的に特定してください:どこで作業が最も長くキューになるか?遅延はどの人の受信箱に遡るか?

## 計算例

ある病棟の退院は、毎朝コンサルタントのレビューを必要とします。コンサルタントは、複数のシステムに散らばった情報を集めるのに1日90分を費やしています;レビューは14:00までに終わり、6件の退院がその日には遅すぎて完了せず、それぞれが回避可能な病床日を発生させます。

退院サマリーダッシュボード(検査、投薬、フラグを1つのビューに)は、集約作業を20分に短縮し、レビューは11:30までに終わります:

```
回避された病床日     = 遅れた6件の退院のうち4件 × 365 ≈ 年間1,460病床日
下流の解消:2人の退院コーディネーター+薬局+搬送
          — 以前は毎日午後、無為の後に詰め込まれていた —
          ≈ 1日あたり約3スタッフ時間の滞留が解放 ≈ 年間1,100時間
```

コンサルタント自身の70分は、価値の*最も小さい*部分です — それがこの指標の要点です。病床日は仕組みによって評価し([節約された病床日数](../節約された病床日数/)を参照)、スタッフの時間は容量として評価してください。

## ソフトウェア工学との関連

これはコードレビュー、アーキテクチャの承認、そしてスタッフエンジニアの受信箱です。5人のエンジニアが、設計を承認できる唯一の人物を1日待つとき、費用は5エンジニア日プラス、その作業自体への1日分の[遅延コスト](../遅延コスト/)であり、レビュアー1時間ではありません。制限となる役割のタスクを圧縮するツール(より良いレビューコンテキスト、自動化された事前チェック、承認者が必要とするものを集めるダッシュボード)は、個人の便宜ではなくシステムのスループットを買います。制約における受け取り/待ち時間を測定してください([フローメトリクス](../フローメトリクス/)を参照) — それは14:00の退院の崖のソフトウェア版です。

## 落とし穴

- **制約でないものを最適化すること**:誰も後ろに並んでいない役割のための美しいツールは、システムの価値をほぼゼロしか生み出しません。
- **制約の移動**:コンサルタントを解消すると制約は移動します(薬局へ、搬送へ) — 完全なスループットの獲得を主張する前に*次の*制約をモデル化してください。
- **下流の時間を現金として数えること**:滞留時間の解放は容量であり、通常の[再配置テスト](../現金化可能な節約と非現金化節約/)の対象です。
