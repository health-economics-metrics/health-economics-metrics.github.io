# 住院时长 (Length of Stay，LOS)

住院时长是指从入院到出院之间的天数——这是住院医疗最核心的流程效率指标。英国急症医疗的平均水平约为4–5天；每多出一天，都会占用一张稀缺的床位，并让患者暴露于院内获得性风险之中。

## 为什么重要

住院时长几乎驱动着急症医院经济学的方方面面：床位容量、择期手术吞吐量、急诊流转、人员配置。即便只是把平均住院时长缩短几分之一天，在规模效应下也能释放出巨大的产能（参见[节省的床位天数](../节省的床位天数/)）。住院时长也是一个双向的质量信号——过长往往意味着流程失败（诊断延误、出院文书滞后、社会照护等待）；过短则可能意味着过早出院，其后果会在之后以[再入院](../再入院率/)的形式显现。

## 计算方法

```
单次住院的住院时长 = 出院日期 − 入院日期
平均住院时长        = 占用床位天数 / 出院人数（应同时报告均值与中位数；
                      住院时长因长期住院的异常值而呈明显右偏分布）

进行比较时必须做病例组合调整（年龄、诊断、病情严重程度），
否则你衡量的只是医院收治了什么样的病人，而不是医院表现如何。
```

利特尔法则（Little's Law）把这些流量变量联系在一起：`占用床位数 = 入院速率 × 平均住院时长`——这与支配软件队列的正是同一条定律（参见[流程指标](../流程指标/)）。

## 算例

某信托机构每天收治40名急诊内科患者，平均住院时长6.0天：由此永久占用240张床位（40 × 6）。出院协调软件（任务追踪、药房带药自动化、交通预约）把住院的非临床尾部时间平均缩短0.4天。

```
所需床位 = 40 × 5.6 = 224 → 持续释放16张床位
        = 16 × 365 = 5,840床位天/年
```

按[节省的床位天数](../节省的床位天数/)一文所述的机制（回填/关闭/吸收）为这5,840床位天估值。请注意真正发生变化的是什么：不是医疗本身，而是*等待*——患者在医学上已经达到出院条件，系统却仍在处理文书工作。这是一个排队问题，而软件正擅长解决排队问题。

## 与软件工程的关联

住院时长就是医院的周期时间，其改进方法论与交付流程改进工作完全相同：为各阶段建立观测（入院 → 治疗 → 医学上达到出院条件 → 实际出院），找出时间积压之处（往往是交接环节），移除等待状态，而不是一味增加产能。"医学上已可出院，却仍占用床位"的这批患者，正是医院版的"已批准但未合并的PR"。可直接切入的软件机会包括：出院任务编排、诊断周转、出院用药的电子处方、社会照护转介的系统集成。

## 常见陷阱

- **只报告均值**——异常值会主导均值，均值下降也可能掩盖一条正在增长的长期住院尾部。
- **前后对比未做病例组合调整**：入院门槛会随季节和长期趋势变化。
- **住院时长的缩短以再入院的形式重新出现**——任何关于住院时长的主张都应配套报告30天再入院数据。
