# Анализ затрат и полезности (АЗП)

АЗП — это анализ экономической эффективности с **универсальным результатом, взвешенным по предпочтениям** — почти всегда [QALY](../год-жизни-с-поправкой-на-качество/) (или избежанным [ГЖНИ](../год-жизни-с-поправкой-на-инвалидность/)). Поскольку единица результата универсальна, АЗП может сравнивать вмешательства при совершенно разных заболеваниях.

## Почему это важно

Национальная система здравоохранения должна выбирать между препаратом от рака, приложением психического здоровья и хирургическим роботом из одного бюджета. Натуральные единицы не могут их сравнить; QALY могут. Поэтому АЗП является методом базового случая в NICE и большинстве органов ОМТ: его результат — стоимость на QALY, оцениваемая относительно [порога](../пороги-готовности-платить/) — это ближайшее, что политика здравоохранения имеет к универсальному обменному курсу. Если вы хотите, чтобы ваше ПО финансировалось *вместо чего-то другого*, АЗП — это арена.

## Расчёт

```
ИКПЭ = ΔЗатраты / ΔQALY      (ИКЭЭ с QALY в качестве единицы эффекта)

ΔQALY = Σ (длительность_i × полезность_i)_новая − Σ (длительность_i × полезность_i)_старая
```

Полезности из валидированных инструментов ([EQ-5D](../eq-5d/)); затраты и QALY оба [дисконтированы](../дисконтирование-и-временное-предпочтение/) на 3,5% (базовый случай NICE); неопределённость через [ВАЧ](../вероятностный-анализ-чувствительности/).

## Разобранный пример

Приложение КПТ для умеренной тревожности против листа ожидания на очную терапию, на пациента:

```
Затраты:  лицензия приложения + поддержка        £250
        вытесненная терапия            −£680   (40% пользователей больше не нуждаются в ней)
        ΔЗ = 250 − 680 = −£430 (экономит деньги)

QALY:  6 месяцев при полезности 0,76 вместо 0,68 во время ожидания
        ΔЭ = 0,5 × (0,76 − 0,68) = +0,04 QALY
```

ΔЗ < 0 и ΔЭ > 0: приложение **доминирует** — лучше и дешевле, соотношение не нужно. Если бы предположение о вытеснении терапии было всего 10%, ΔЗ = 250 − 170 = +£80, и ИКПЭ = 80 / 0,04 = **£2000/QALY** — всё ещё значительно ниже £20 000. Кейс выживает даже при резко сокращённом ключевом предположении: вот как выглядит надёжный АЗП (и [диаграмма-торнадо](../анализ-чувствительности/) это доказывает).

## Связь с программной инженерией

Глубокая идея АЗП — *единая составная единица, взвешенная по предпочтениям, для сравнения непохожих вещей* — это шаблон для сравнения непохожих инженерных инвестиций (безопасность против опыта разработчика против надёжности). Честные варианты — это либо обоснованная составная единица (редко), либо явная [таблица затрат и последствий](../анализ-затрат-и-последствий/) (обычно). Против чего предостерегает АЗП — это фальшивый составной показатель: взвешенный «балл воздействия», чьи веса были подогнаны постфактум, чтобы предпочитаемый вариант победил. Экономика здравоохранения потратила десятилетия на стандартизацию получения полезностей именно для того, чтобы веса предшествовали сравнению.

## Подводные камни

- **Выгоды полезности ниже чувствительности инструмента** (см. минимальную клинически значимую разницу в [результатах, сообщаемых пациентами](../результаты-сообщаемые-пациентами/)) — крошечная ΔЭ, умноженная на большие популяции, — классический трюк отмывания.
- **Отсутствие вытеснения компараторного ухода** — крупнейший член затрат для цифровых продуктов часто то, что они заменяют.
- **Сопоставление баллов без предпочтений с полезностями** через невалидированные переходники.
