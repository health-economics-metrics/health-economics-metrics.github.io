# Доля неявок (Did-Not-Attend, DNA rate)

Доля неявок (DNA rate) — это процент забронированных приёмов, на которые пациент не является и которые не отменяет. Клиницист, кабинет и слот оплачены; ничего не происходит. Это самая чистая метрика потерь в здравоохранении — и одна из наиболее легко исправляемых программными средствами.

## Почему это важно

Данные NHS England (2019): пропущенные приёмы у врача общей практики превышают 15 миллионов в год по ~£30 каждый — свыше **£216 млн/год** — а амбулаторные неявки в больницах составляют ~8 млн в год (~6,4% приёмов) при средней стоимости ~**£160** за пропущенный слот. Поскольку предельная стоимость напоминания — копейки, а восстановленная ценность — это полностью укомплектованный клинический слот, снижение доли неявок обладает одной из лучших арифметик ROI в цифровом здравоохранении, поэтому SMS-напоминания, лёгкая перезапись и предиктивное овербукинг стали одними из первых доказанных побед цифрового здравоохранения.

## Математика

```
Доля DNA = число неявок / число забронированных приёмов × 100

Ценность снижения = приёмы × ΔДоля DNA × ценность одного восстановленного слота

ценность одного восстановленного слота: слот либо заполняется заново (ценность
активности / сокращение листа ожидания), либо нет (время персонала частично
используется повторно) — механизм важен, как и в bed-days-saved.md.
```

## Практический пример

Амбулаторное отделение: 200 000 приёмов в год, доля неявок 8%. Сервис напоминаний и перезаписи (SMS с записью в один клик, информацией о транспорте, доступными форматами) снижает неявки до 5,5%.

```
Восстановленные слоты = 200,000 × 0.025 = 5,000/год
Заполнены заново из листа ожидания при средней амбулаторной ценности ~£160:
  5,000 × £160 = £800,000/год восстановленной активности
Стоимость сервиса: 200,000 × £0.40 = £80,000/год

Отдача ≈ 10:1, плюс 5,000 пациентов из листа ожидания приняты раньше
(см. waiting-list-impact.md и referral-to-treatment.md).
```

Величина эффекта (2,5 пункта) реалистична: RCT по напоминаниям стабильно показывают относительное снижение неявок на 25–40%.

## Связь с разработкой программного обеспечения

- **Это проблема систем планирования**: напоминания, самостоятельная перезапись, автозаполнение листа ожидания из отмен, и модели предсказания неявок, управляющие целевым двойным бронированием. Каждая из них — обычная разработка ПО с необычно чётким экономическим кейсом.
- **Инженерная аналогия**: неявки для зарезервированной мощности — забронированные, но простаивающие слоты CI, зарезервированная облачная мощность, переговорные комнаты, собеседовательные панели. Экономика переносится: дешёвый автоматический толчок (или автоматическое освобождение неиспользуемых резервирований) восстанавливает дорогую зафиксированную мощность.
- **Предпросмотр этики предсказаний**: модели неявок, обученные на данных посещаемости, кодируют депривацию и барьеры доступа; использование их для *понижения приоритета* вероятных неявившихся усиливает неравенство, использование их для *поддержки* явки (помощь с транспортом, телефонные альтернативы) снижает его. См. [охват и равенство](../охват-и-равенство/).

## Подводные камни

- **Двойной счёт отменённых-и-перезаписанных как восстановленной ценности.**
- **Оценка восстановленных слотов, которые не были заполнены** — пустой слот с отправленным напоминанием всё равно пуст.
- **Гонка за нулевой неявкой**: последние пункты неявок — это пациенты, сталкивающиеся с реальными барьерами; карательные подходы (выписка после N неявок) снижают метрику, отказываясь от пациентов.
