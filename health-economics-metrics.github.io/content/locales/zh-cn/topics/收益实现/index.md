# 收益实现 (Benefits Realization)

收益实现管理（Benefits Realization Management，BRM）是一门学科，专门负责识别、建立基线、跟踪并*举证*商业论证中所承诺的收益，是否在交付之后真正得以实现。在英国公共投资体系中，它位于HM Treasury（英国财政部）Green Book**五案例模型**（Five Case Model）的框架之内；在医学领域，与之对应的是上市后监测（post-market surveillance）。

## 为何重要

商业论证不过是一份承诺；收益实现才是对这份承诺的审计。对NHS重大数字化项目的多次评估反复发现，预测的收益从未真正实现——而当这些收益并非现金释放型时，它们对信托机构的底线毫无贡献。Green Book的应对之策是：每一份支出论证都必须通过**五个案例**（战略案例、经济案例、商业案例、财务案例、管理案例）的检验，收益实现须在*批准之前*就在管理案例中规划妥当——责任人须指定、基线须采集、测量日期须设定。若缺少这些环节，"这款软件为每位护士节省了30分钟"这类说法就会永远停留在供应商的一面之词上。

## 计算方法

```
实现率 = 已实现的收益 / 预测的收益（按每项收益、每个周期分别计算）

使其可计算所需的机制：
  基线须在上线前完成采集（否则差值就无法测量）
  每项收益须明确：责任人、指标、数据来源、测量周期
  预测须在评估阶段针对乐观偏差进行调整（Green Book的强制要求）
  收益须分类为现金型/非现金型/定性型，并分别跟踪
  （参见cash-releasing-vs-non-cash-releasing.md）
```

## 实例演算

某电子排班系统的商业论证承诺，每年可实现：代理机构支出减少£45万（现金收益）、病房经理工时节省8,000小时（产能收益）、排班达标率提升（定性收益）。上线12个月后：

```
收益项           预测值      实现值      实现率  证据来源
代理机构支出     £450,000    £287,000    64%    台账数据对比基线年度
经理工时         8,000       5,100       64%    时间-动作抽样调查
排班达标率       +10个百分点  +12个百分点  120%   排班系统数据

审查得出的行动（这正是BRM的意义所在）：
代理机构支出缺口追溯发现是两个病房从未完成上线 → 推动其上线；
预测模型存在30%的乐观偏差，此发现已被记录 → 应用于下一份论证。
```

64%的实现率并非失败——而是*知识*。未被测量的案例则永远宣称100%实现。

## 与软件工程的关联

工程机构常常依据预测收益批准平台投资，却几乎从不对其进行审计——这正是BRM所要修正的典型病症。轻量级的移植做法是：任何超过阈值的提案都须指定收益责任人、基线指标，以及T+6个月的复审日期；实现率的反馈会影响机构此后对该团队（或供应商）下一次预测的折扣程度。这也是回应"AI工具怀疑论"的答案所在：[MIT发现约95%的GenAI试点未显示出可测量的损益回报](../ai投资回报率/)，这本身就是一个收益实现层面的结果——那些*确实*产生回报的试点，恰恰拥有可追踪、有明确责任人的收益线。预测 → 测量 → 重新校准，正是按组合投资组合规模运行的[EVPI](../完全信息期望价值/)定价试点所遵循的同一个循环。

## 常见陷阱

- **上线前未建立基线**——这是致命且无法弥补的疏漏。
- **收益无人认领**：没有指定责任人，就没有人采集数据，每次复审都只会说"总体符合预期"。
- **跨项目重复计算收益**：多个项目都声称释放了同一份产能——应在整个投资组合层面维护一份统一的收益登记册。
- **收益实现"作秀"**：只测量容易达成的定性成果，而现金相关的收益线却被悄悄搁置、不予审查。
