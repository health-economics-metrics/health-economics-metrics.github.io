# 效益兑现

效益兑现管理（BRM）是一门学科，用于识别、建立基线、追踪，并*用证据证明*商业论证中所承诺的效益在交付后是否真正兑现。在英国的公共投资体系中，它属于HM Treasury《绿皮书》**五案例模型**的一部分；在医学领域，其对应物是上市后监测。

## 为何重要

商业论证是承诺；效益兑现则是审计。对NHS重大数字化项目的多次评估反复发现：预测的效益从未真正兑现——而当效益并非现金释放型时，它们对信托机构的财务底线毫无作用。《绿皮书》的应对办法是：每一项支出方案都必须通过**五个案例**的检验（战略、经济、商业、财务、管理），并要求在管理案例中于*批准之前*就规划好效益兑现——指定责任人、采集基线数据、设定测量日期。若无此机制，"这套软件为每位护士节省了30分钟"就将永远只是供应商的一面之词。

## 计算方法

```
兑现率 = 已兑现效益 / 预测效益   （按每项效益、每个周期分别计算）

使其可计算的关键机制：
  基线必须在上线前采集（否则差值无法测量）
  每项效益都需明确：责任人、指标、数据来源、测量时间表
  预测值在评审阶段需针对乐观偏差进行调整（《绿皮书》强制要求）
  效益需分类为现金/非现金/定性三类，并分别追踪
  （参见cash-releasing-vs-non-cash-releasing.md）
```

## 实例演算

某电子排班商业论证承诺，每年可实现：£450,000的中介用工支出削减（现金）、8,000小时的病区经理工时（产能）、以及更高的排班达成率合规性（定性）。上线12个月后：

```
效益项         预测值      实际兑现值   兑现率   证据来源
中介支出       £450,000    £287,000     64%     总账数据 对比 基线年度
经理工时       8,000       5,100        64%     时间-动作抽样调查
达成率合规     +10个百分点  +12个百分点  120%    排班系统数据

复核后采取的行动（这正是BRM的意义所在）：
追溯发现中介支出未达预期的原因是有两个病区从未完成系统上线 → 推动其完成上线；
预测模型存在30%的乐观偏差被记录在案 → 应用于下一份商业论证。
```

64%的兑现率并非失败——而是*认知*的获得。未经测量的案例则永远宣称"100%达标"。

## 与软件工程的联系

工程组织常常基于预测效益批准平台投资，却几乎从不对其进行审计——这正是BRM所要修正的典型病症。一个轻量级的移植方案是：任何超过某一门槛的提案，都必须指定效益责任人、基线指标，以及一个T+6个月的复核日期；兑现率则反过来影响组织对该团队（或供应商）下一次预测所打的折扣。这也是对AI工具怀疑论的回应：[麻省理工发现约95%的生成式AI试点未展现出可测量的损益表回报](../AI投资回报率/)，本质上正是一个效益兑现层面的结果——那些*确实*带来回报的试点，都拥有可追踪、有明确责任人的效益线。预测 → 测量 → 重新校准，与按[EVPI](../完美信息期望价值/)定价的试点是同一套循环，只是被放到了整个投资组合的规模上运行。

## 陷阱

- **上线前没有基线**——这是致命且无法弥补的缺失。
- **效益无人认领**：没有明确指定的责任人，意味着没有人收集数据，每次复核都只会说"总体进展正常"。
- **跨项目重复计算效益**：多个项目主张同一份被释放的产能——应在整个投资组合层面维护一份效益登记册。
- **兑现表演**：只测量容易达成的定性成果，而现金相关的效益线却被悄悄搁置、从不审视。
