# SPACEとDevEx

SPACE(満足度と幸福感、パフォーマンス、活動、コミュニケーションと協働、効率とフロー)とDevEx(フィードバックループ、認知負荷、フロー状態)は、開発者の生産性を**多次元的に**測定するためのフレームワークです — 単一のメトリクスが現実との接触に耐えられないという発見に対するこの分野の答えです。

## なぜ重要か

どちらのフレームワークも、医療アウトカム研究が数十年前に学んだ、苦労して得られた同じ教訓を符号化しています:単一の数字(コード行数、血圧)は多次元的な現実を誤って表現し、それを最適化することは改善ではなくごまかしを生み出します。SPACEは、少なくとも3つの次元からのメトリクスを組み合わせ、テレメトリと自己報告を混ぜることを規定しています — これは、[EQ-5D](../eq-5d/)が指数を計算する前に5つの次元をプロファイルする方法、そして[PROM](../patient-reported-outcomes/)が臨床的な測定と並んで存在する理由と構造的に同一です。満足度/幸福感もソフトな添え物ではありません:それは[人材の定着](../workforce-retention/)の経済学に流れ込み、そこでは離職が全負担給与の月数で値付けされます。

## 数式

どちらのフレームワークも公式ではありません;どちらも測定設計です:

```
SPACEのルール:≥3次元、≥1つの知覚的(調査)+≥1つのシステム(テレメトリ)メトリクス

DevExの次元と組み合わせの例:
  フィードバックループ → CI時間(テレメトリ)+「待つのが遅く感じる」(調査)
  認知負荷            → ドキュメントの見つけやすさ、オンボーディング時間+知覚的な労力
  フロー状態          → 会議/中断の密度+自己申告の集中度

派生指数(例:DXのDXI)は調査の複合指標を時間にマッピングします:
ベンダーの主張≈指数1ポイントあたり開発者1人週13分 — これを自然の定数ではなく、
地域で検証すべきベンダーのベンチマークとして扱ってください。
```

## 計算例

あるプラットフォームチームは、300人の開発者向けにDevExへの投資(CI高速化+ドキュメントの刷新)を正当化します:

```
ベースライン:CI p75 = 28分;調査「ビルドを待つ間に集中力を失う」:62%が同意
後:          CI p75 = 9分; 同意24%

取り戻された時間(テレメトリ):1日6回のビルド × 19分 × 使用可能率0.4 = 開発者1人あたり1日約45分
容量の価値:300 × 0.75時間 × 220日 × £60/時 ≈ 年間£297万(非現金化 —
現金化可能な節約と非現金化節約を参照;0.4の使用可能率係数は
医療従事者の時間からの分断の割引です)
知覚的な裏付けが、テレメトリの主張を信頼できるものにします — どちらか一方だけでは
ごまかせますが、両方が揃うと三角測量になります。
```

## ソフトウェア工学との関連

この文書は*まさに*ソフトウェア側であり、転用は医療経済学に向かって流れます。「質調整エンジニア年」 — 標準化された体験指数で重み付けされた時間 — は、[QALY](../quality-adjusted-life-year/)の構成をエンジニアリング容量に適用したものであり、QALYのルールを受け継ぎます:検証済みの測定手法からの重み(一貫した調査、公表されたスコアリング)、比較の*前に*引き出される、決して好ましいツールを実際以上に良く見せるために調整されない。[SF-6D対EQ-5D](../eq-5d/)の教訓も当てはまります:異なる測定手法は体系的に異なる数値を与えるため、ベンダーの測定手法をまたいでDevEx指数を決して比較しないでください。

## 落とし穴

- **単一メトリクスへの縮約**:SPACEを1つのスコアに縮めるダッシュボードは、このフレームワークが防ぐために存在する問題を再現します。
- **アウトカムとしての活動メトリクス**:コミット、PR、ストーリーポイントは「活動」であり、SPACEが明示的に最もごまかされやすいと警告する次元です(医療での類似物:回復ではなく処置の数を数えること)。
- **調査疲れとホーソン効果**:四半期ごとの軽いタッチの手法は、毎週の尋問に勝ります。
- **チームの比較**:症例構成の調整なしの病院リーグテーブルのようなもの — 文脈の違い(ドメイン、レガシーの負荷、オンコール)が支配的です。
