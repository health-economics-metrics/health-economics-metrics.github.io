# NICE證據標準框架（ESF）

ESF是NICE的一套框架，規定了**一項數位健康技術需要與其風險相稱的多少證據**。它是對"在NHS採購我們的應用之前，我們必須證明什麼？"這一問題最接近官方答案的存在。

## 為何重要

ESF（首次釋出於2019年，2022年更新以涵蓋AI與自適應演算法）按臨床功能將數位健康技術劃分為不同層級，並要求提供**累進式**的證據標準——共5大類21項標準（設計要素、價值、效能/效果、經濟影響、部署）：

```
A層 —— 系統服務類，無直接病患結果（例如電子排班）
       → 基本標準：可信度、資料保護、技術保障
B層 —— 提供資訊、簡單監測、溝通類（例如症狀日記）
       → 在A層基礎上加：使用者獲益證據、適當的可靠性
C層 —— 治療、診斷，或主動引導臨床管理
       → 在B層基礎上加：高品質的對照效果證據（理想情況下為隨機對照試驗）
         以及經濟學分析
```

對於經濟學證據，[成本後果分析](../成本後果分析/)對大多數層級而言已屬可接受；而在風險最高的層級，則需要[成本效用分析](../成本效用分析/)。ESF界定的正是你**進入市場所需的證據成本**——應像對待任何其他建設成本一樣，為其編列預算。

## 計算方法

沒有公式——這是一張決策表。真正起作用的計算屬於商業範疇：

```
所需證據投入 = f(層級)
  A層：檔案記錄 + 保障措施 ≈ £10,000–50,000
  B層：觀察性/對照性使用者獲益研究 ≈ £50,000–250,000
  C層：隨機對照試驗級別的對照研究 + 經濟學模型 ≈ £250,000–£200萬以上

應審慎地定位你產品的宣傳主張：聲稱"支援臨床決策"而非
"為病患提供資訊"，會使你被劃入更高一級，賬單可能因此升高10倍。
```

## 實例演算

某用藥提醒應用的開發方，考慮加入一項劑量調整建議功能。

- 作為純提醒類應用：**B層**——一項顯示依從性改善的佇列研究即已足夠。
- 若加入劑量建議：**C層**——需要對照效果證據（很可能是與常規照護對比的隨機對照試驗），外加經濟學分析。

如果該隨機對照試驗成本為£600,000，而劑量功能帶來的增量收入為每年£200,000，那麼該功能必須持續創造價值3年以上，證據成本才能收支平衡——一旦將ESF層級成本計入考量，這項產品決策看起來就會完全不同。許多團隊會先交付B層產品，把C層的宣傳主張暫時擱置，等待資金到位後再補上。

## 與軟體工程的聯絡

ESF是本書中最具可遷移性的單一治理模式：**按風險分級的工具採納證據要求**。其內部版本是：一個程式碼格式化工具只需要一次演示（A層）；一個聲稱節省工時的生產力工具需要一次經過測量的試點（B層）；一個能自動阻止部署、或自動編寫臨床程式碼的AI關卡，在全組織推廣之前，需要達到對照試驗級別的證據（C層）。相稱的證據要求能同時阻止兩種失敗模式——官僚主義扼殺無關緊要的小工具，以及僅憑感覺就推出影響重大的工具。另見[DiGA快速通道](../德國DiGA快速通道/)，作為"附帶證據截止期的臨時採納"這一互補機制。

## 陷阱

- **出於一廂情願而誤判層級**——監管者與採購方是根據產品*實際做什麼*來分類的，而非根據行銷宣傳怎麼說。
- **在產品之後才補建證據**：在一個已上線、且未預先埋點或未保持均勢狀態的產品上事後補做隨機對照試驗，既緩慢又往往根本不可能。
- **滿足了ESF卻忽視了其餘要求**：ESF與DTAC（臨床安全、資料保護、互操作性）並行存在，對於AI而言還需另加監管審批——參見[AI監管評估](../AI監管評估/)。
