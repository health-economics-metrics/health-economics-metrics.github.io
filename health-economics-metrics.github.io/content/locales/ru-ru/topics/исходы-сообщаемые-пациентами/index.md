# Исходы, сообщаемые пациентами (Patient-Reported Outcomes, PROMs, PREMs, MCID)

PROMs — это стандартизированные инструменты, в которых пациенты сообщают о собственном состоянии здоровья (симптомы, функция, качество жизни); PREMs фиксируют *опыт* получения помощи. **MCID** — минимально клинически значимая разница — это наименьшее изменение балла, которое пациенты действительно воспринимают как полезное: планка, которую должно преодолеть любое заявленное улучшение.

## Почему это важно

PROMs — это основная валюта эффикаса для цифрового здравоохранения: приложения редко двигают смертность, но они могут достоверно двигать валидированные баллы симптомов. Значимых и стандартизированных инструментов немного — **PHQ-9** (депрессия, 0–27; диапазоны тяжести на 5/10/15/20), **GAD-7** (тревога, 0–21; диапазоны на 5/10/15), **EQ-5D** (полезность для [QALY](../год-жизни-с-поправкой-на-качество/)) — и регуляторы, органы HTA и плательщики принимают их именно потому, что они сопоставимы между продуктами и испытаниями. MCID — это шлюз честности: MCID PHQ-9 ≈ 5 баллов, GAD-7 ≈ 4, индекс EQ-5D обычно ~0,03–0,08 — статистически значимое изменение PHQ-9 на 1,5 балла на большой выборке *реально, но клинически бессмысленно*, и рецензент доказательств это скажет.

## Математика

```
Расчёт балла PROM: суммы, специфичные для инструмента (например, PHQ-9 = Σ 9 пунктов × 0–3)

Оценка MCID:
  на основе якоря:         изменение балла среди пациентов, сообщивших «немного лучше»
  на основе распределения: ≈ 0.5 × стандартное отклонение исходных баллов (грубая эвристика)

Формулировка доли ответивших (для испытаний и досье):
  ответивший = пациент с улучшением ≥ MCID (или ≥50% по конвенции PHQ-9)
  NNT = 1 / (доля ответивших_лечение − доля ответивших_контроль)
  — см. number-needed-to-treat.md
```

## Практический пример

Приложение поддержки при депрессии, RCT против листа ожидания, 12 недель:

```
Изменение PHQ-9: приложение −6.2 балла, контроль −2.1 → скорректированная разница −4.1
Проверка MCID: 4.1 < 5 → средняя разница ниже MCID; вместо этого отчитываемся по ответившим:
  ответившие (падение ≥5 баллов): приложение 48%, контроль 22% → абсолютное снижение риска 26%
  NNT = 1/0.26 ≈ 4 — четыре пользователя пролечены на один дополнительный клинический ответ

Экономический мост: прирост EQ-5D у ответивших 0.06, устойчивый 6 месяцев
  = 0.03 QALY; на 1,000 пользователей: 260 дополнительных ответивших × 0.03 = 7.8 QALY
  ≈ £156,000–£234,000 ценности здоровья по порогам NICE
```

Формулировка через ответивших/NNT переживает рецензирование там, где средняя разница ниже MCID была бы отклонена.

## Связь с разработкой программного обеспечения

PROMs — это проблема сбора данных, которую ПО уникально способно решить: инструменты внутри приложения получают такие показатели завершения и лонгитюдную плотность, которых бумага никогда не достигала, превращая рутинную телеметрию продукта в доказательства уровня HTA ([EQ-5D](../eq-5d/) — это пять экранов). Инженерные правила: используйте валидированный инструмент *дословно* (перефразирование аннулирует его — применяется лицензирование); планируйте измерение по протоколу, а не по удобству вовлечённости (измерение только активных пользователей — это смещение выживаемости, см. [удержание](../удержание-и-отток/)); и фиксируйте версию данных инструмента, как любую схему, — изменение формулировки в середине исследования — это повреждение данных. PREMs сопоставляются с инструментами в стиле CSAT/NPS, и тот же урок применим: стандартизированное побеждает самодельное везде, где аудитория — плательщик. Об инструменте, специфичном для рабочей продуктивности, см. [WPAI](../рабочая-продуктивность-и-нарушение-активности/).

## Подводные камни

- **Статистическая значимость ниже MCID**, представленная как клиническая польза — самое частое раздувание в этой области.
- **Регрессия к среднему**: пользователи регистрируются на пике симптомов; одноплечевое сравнение «до/после» сильно завышает эффект — компараторы не подлежат обсуждению.
- **Шопинг по инструментам**: прогон PHQ-9, GAD-7 и WHO-5, затем отчёт о том, что сдвинулось — заранее регистрируйте основной инструмент.
- **Давление опроса при цифровом согласии**: подталкивание пользователей к благоприятным ответам портит инструмент (а рецензенты знают базовые уровни).
