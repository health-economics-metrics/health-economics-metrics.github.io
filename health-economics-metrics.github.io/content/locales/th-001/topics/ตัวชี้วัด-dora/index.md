# ตัวชี้วัด DORA

ตัวชี้วัด DORA (DevOps Research and Assessment) วัดประสิทธิภาพของทีมพัฒนาซอฟต์แวร์ผ่านตัวชี้วัดหลัก 4 ตัว: ความถี่ในการปรับใช้ เวลานำส่งการเปลี่ยนแปลง อัตราความล้มเหลวของการเปลี่ยนแปลง และเวลาในการกู้คืน

## ทำไมจึงสำคัญ

ตัวชี้วัด DORA ให้กรอบที่มีหลักฐานเชิงประจักษ์รองรับสำหรับการวัดประสิทธิภาพการพัฒนาซอฟต์แวร์ ซึ่งมีความสัมพันธ์กับผลการดำเนินงานขององค์กร ไม่ใช่แค่ความรู้สึกส่วนตัวว่า "เราเร็วหรือไม่"

## คณิตศาสตร์

```
เวลานำส่งการเปลี่ยนแปลง = เวลาตั้งแต่ commit จนถึงการปรับใช้ในการผลิต
อัตราความล้มเหลวของการเปลี่ยนแปลง = จำนวนการปรับใช้ที่ล้มเหลว / จำนวนการปรับใช้ทั้งหมด × 100%
```

## ตัวอย่างที่คำนวณแล้ว

ทีมที่ปรับใช้ 10 ครั้งต่อวัน ด้วยเวลานำส่งเฉลี่ย 1 ชั่วโมง และอัตราความล้มเหลว 5% จะถูกจัดอยู่ในระดับ "elite" ตามเกณฑ์เปรียบเทียบของ DORA

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

นี่คือตัวชี้วัดของการพัฒนาซอฟต์แวร์เอง ซึ่งถูกใช้ซ้ำๆ ในเอกสารนี้เป็นการเปรียบเทียบกับตัวชี้วัดด้านสุขภาพ (การกลับเข้ารักษาซ้ำ = อัตราความล้มเหลวของการเปลี่ยนแปลง, RTT = เวลานำส่ง)

## ข้อผิดพลาดที่พบบ่อย

- **การเพิ่มประสิทธิภาพตัวชี้วัดเอง แทนที่จะเพิ่มมูลค่าให้กับลูกค้าที่อยู่เบื้องหลัง**
- **การเปรียบเทียบตัวชี้วัดระหว่างทีมที่มีบริบทแตกต่างกันมาก**
