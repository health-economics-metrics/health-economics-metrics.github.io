# 再入院率

30天再入院率是指出院患者中，在30天内以急诊方式重新入院的比例。它是医疗系统衡量*出院质量*的标准指标——并且直接附带财务处罚。

## 为何重要

再入院意味着第一次出院其实没有真正"站住脚"：过早出院、用药交接失败、缺乏随访，或社会支持缺失。支付方对此设有明确的处罚机制——美国的Hospital Readmissions Reduction Program最高可扣减医院3%的Medicare付款；NHS历来对可避免的30天急诊再入院不予支付。因此，避免再入院是少数几个*直接*与提供方现金挂钩、而不仅仅是产能相关的效益类别之一。

## 计算方法

```
再入院率 = 30天内急诊再入院人次 / 首次出院人次 × 100

风险标准化比较会对病例组合进行调整；处罚类项目
则将观察值与同类医院的预期值进行比较。

避免再入院的价值 = 避免的再入院人次 × (每次再入院疗程成本
                  + 每次再入院对应的处罚风险敞口)
```

## 实例演算

某心力衰竭出院支持应用（症状追踪、体重预警、用药提醒、护士升级响应）：每年2,000例出院，基线再入院率18%，试验显示使用该应用后降至14%。

```
避免的再入院 = 2,000 × (0.18 − 0.14) = 每年80例
每次再入院疗程成本约£3,500 → 每年避免£280,000的治疗成本
外加这些疗程对应的处罚/拒付风险敞口。
应用成本：2,000 × £60 = 每年£120,000

净收益 ≈ 每年+£160,000，这还不包括因避免病情恶化而产生的任何QALY主张。
```

真正需要捍卫的数字，是那4个百分点的效应量：它必须来自一项对照比较，因为再入院率本身会随病例组合与季节而波动。

## 与软件工程的联系

再入院正是医疗系统版本的**变更失败率**（参见[DORA指标](../DORA指标/)）：一项已经"交付"却在30天内被打回来的工作。这一类比相当深刻——被重新打开的工单与回归性事件，同样反映出糟糕的"出院质量"（验证不足、过早关闭、交接文档缺失）；处罚式核算方式（由造成问题的团队买单，而非接手的团队）会改变行为；而两个领域都学到了同一个教训：在不投入交接环节的情况下一味追求原始吞吐量（更快出院、更快交付），只会把可见的队列转化为不可见的返工。任何一个以周期时间为荣的团队仪表盘，都应该纳入一项"30天重新打开率"指标。

## 陷阱

- **通过重新编码来操纵指标**：将再入院编码为观察性留院，或编码为新发病症；应审计其定义是否被规避。
- **全因再入院 vs 相关病因再入院**：30天全因再入院会包含一些确实无关的事件；处罚机制通常正是出于"相关病因"容易被操纵这一原因，才采用全因口径。
- **对病例组合视而不见**：一家服务于病情更重、更贫困人群的医院，其再入院率会更高，原因并非任何应用所能解决——比较之前应先做风险调整。
