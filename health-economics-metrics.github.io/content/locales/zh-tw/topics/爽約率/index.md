# 爽約率（DNA率）

爽約率是指已預約的診療中，病患既未到場、也未取消預約的比例。臨床醫師、診室與該時段的成本都已支付，卻什麼都沒有發生。這是醫療領域中最純粹的浪費指標——也是最容易透過軟體解決的浪費之一。

## 為何重要

NHS England的資料（2019年）：每年錯過的全科醫師預約超過1,500萬次，每次約£30——合計超過**每年£2.16億**；醫院門診爽約每年約800萬次（約佔預約總數的6.4%），每次錯過的平均成本約為**£160**。由於一條提醒資訊的邊際成本僅為幾便士，而挽回的價值卻是一個配備齊全的完整臨床時段，因此降低爽約率在數位健康領域擁有數一數二出色的投資回報率算術——這也是為什麼簡訊提醒、便捷改約與預測性超額預約，是最早被證實有效的數位健康成果之一。

## 計算方法

```
爽約率 = 爽約次數 / 已預約次數 × 100

降低帶來的價值 = 預約總數 × Δ爽約率 × 每個挽回時段的價值

每個挽回時段的價值：該時段要麼被重新填滿（活動價值/等候名單縮減），
要麼沒有被填滿（人員時間只能部分再利用）——具體機制至關重要，
與bed-days-saved.md中的道理相同。
```

## 實例演算

某門診科室：每年200,000次預約，爽約率8%。一項"提醒+改約"服務（簡訊提醒配一鍵改約、交通訊息、無障礙格式）將爽約率降至5.5%。

```
挽回的時段數 = 200,000 × 0.025 = 每年5,000個
按門診平均價值約£160，從等候名單中重新填滿：
  5,000 × £160 = 每年£800,000的挽回活動價值
服務成本：200,000 × £0.40 = 每年£80,000

回報比約為10:1，此外還有5,000名等候名單病患得以更早就診
（參見waiting-list-impact.md與referral-to-treatment.md）。
```

這裡的效應量（2.5個百分點）是切合實際的：提醒類隨機對照試驗一貫顯示25–40%的相對爽約率下降。

## 與軟體工程的聯絡

- **這本質上是一個排程系統問題**：提醒資訊、自助改約、從取消預約中自動回填等候名單，以及能驅動精準超額預約的爽約預測模型。每一項都是普通的軟體工程工作，卻擁有異常清晰的經濟學論證。
- **工程領域的對應類比**：預留產能的"未出席"——已預訂但閒置的CI時段、已預留的雲端產能、會議室、面試小組。這套經濟學邏輯同樣適用：一次廉價的自動化提醒（或對未使用預留的自動釋放），就能挽回昂貴的已承諾產能。
- **預測倫理預告**：基於出席資料訓練的爽約預測模型，會內嵌貧困程度與就醫障礙等因素；若用它來*降低*可能爽約者的優先順序，會放大不公平；若用它來*支援*病患按時就診（交通協助、電話替代方案），則會縮小不公平。參見[觸達與公平](../觸達與公平/)。

## 陷阱

- **將"已取消並改約"重複計為挽回價值。**
- **為未被重新填滿的挽回時段計價**——傳送了提醒資訊的空時段，仍然是空的。
- **將爽約率一味壓向零**：最後那部分爽約的病患，往往正面臨著真實存在的障礙；懲罰性做法（爽約N次後即除名）確實能降低這項指標，但代價是拋棄了這些病患。
