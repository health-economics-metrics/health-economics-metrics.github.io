# フローメトリクス

フローメトリクスは、作業がデリバリーシステムをどう移動するかを測定します:サイクルタイム、リードタイム、スループット、仕掛かり作業(WIP)、フロー効率。これらはリトルの法則に支配されています — 病院の病床や待機リストを支配するのと同じキューイングの数学です。

## なぜ重要か

デリバリー時間のほとんどは作業ではなく — 待機です。知的作業のフロー効率の研究は、日常的に、経過時間のうち実際に作業されているのは**5〜15%**だけであることを発見しています;残りはキューです。つまり、最も安価な加速は雇用ではなくキューの除去です — これはまさに、病院の患者フロープログラムが病床について発見した洞察です。[遅延コスト](../遅延コスト/)を持つあらゆるものにとって、フローメトリクスは遅延コストがどこで発生するかを特定します。

## 数式

```
サイクルタイム   = t(完了) − t(開始)
リードタイム     = t(納品) − t(要求)     (前作業のキューを含む)
スループット     = 完了したアイテム数 / 期間
WIP              = 開始されたが未完了のアイテム数
フロー効率       = 稼働時間 / (稼働時間+待機時間) × 100

リトルの法則:平均WIP = スループット × 平均サイクルタイム
            (同等に:サイクルタイム = WIP / スループット)
```

リトルの法則はレバーです:スループットが一定なら、WIPを削減するとサイクルタイムは比例して削減されます。これは病院も動かします:「占有病床数 = 1日あたりの入院数 × 在院日数」。

## 計算例

あるチームは40件の作業を進行中に抱え、週10件を完了します:サイクルタイム = 40/10 = 4週間。WIP制限を課し、WIPを15に削減します:サイクルタイム = 15/10 = **1.5週間** — 同じ人員、同じスループットで、純粋にキューの規律だけから62%速いデリバリーです。

CoDで値付けすると:もしアイテムが平均週£3,000の遅延コストを持つなら、各アイテムは今や2.5週間少なくキューに滞在します:週10アイテム × 2.5 × 3,000 = **週£75,000の遅延コストが解消される** — 何も費用のかからないポリシー変更からです。

病院の鏡像:1日40件の入院 × 6.0日のLOS = 240床;LOS内の非臨床的な待機を5.6日に削減すると16床が解放されます([在院日数](../在院日数/)を参照) — 同じ法則、同じレバーです。

## ソフトウェア工学との関連

フローメトリクスは、デリバリーエンジニアリングと医療運用の間の共通言語です:

- **PRのサブステージのベンチマーク**(LinearB、約800万件のPR):エリートの受け取り時間<7時間、レビュー<6時間、総サイクル<約26時間 — 受け取り時間は純粋なキューであり、最初に取り組むべきものです。
- **[待機リスト](../待機リストへの影響/)**はバックログです;**[RTT](../紹介から治療まで/)**はリードタイムです;**[病床占有](../節約された病床日数/)**はWIPです。改善は双方向に転用できます:WIP制限 ↔ 入院の平準化;キュー時間の計測 ↔ 経路段階の追跡。
- フロー効率15%未満はどちらの領域でも普通であり、どちらもそれを隠します。なぜなら*人々*が忙しい一方で*作業*が待っているからです — 労働者ではなく作業の時計を測定してください。

## 落とし穴

- **稼働率崇拝**:労働者の稼働率を100%に近づけることは、キュー時間を非線形に爆発させます(M/M/1:待ち時間 ∝ ρ/(1−ρ)) — これが95%稼働の病院が行き詰まり、95%割り当てられたチームが停滞する理由です。
- **歪んだ分布にわたる平均**:サイクルタイムは裾が重いです;平均ではなくパーセンタイル(p85)で予測してください。
- **上流で作業を拒否することでWIPを削減し**、それをフローの改善と呼ぶこと — 需要は消えたのではなく、測定境界の外側でキューになっただけです(病院版:ED外で待つ救急車)。
