# 留存与流失 (Retention and Churn)

留存率衡量的是，一个用户队列在开始使用后第 N 天仍处于活跃状态的比例（D1/D7/D30 曲线）；流失率是其补集。数字健康领域残酷的基线现实是：**大约 90% 的健康应用用户会在 30 天内放弃使用**——数字健康的 D30 留存率约为 3%-4%，而所有应用的平均水平约为 6%。

## 为什么重要

Eysenbach 在 2005 年为这一现象命名：**流失定律（law of attrition）**——以高比率流失用户，是电子健康（eHealth）干预措施内在的、结构性的属性，而非实施上的缺陷，电子健康试验中的流失率常规性地超过 50%。其经济后果是全局性的：留存率决定了任何收益得以交付的*治疗窗口*，而[单位经济学](../健康应用单位经济学/)——为一个仅停留 12 天的用户支付的获客成本（CAC），既换不来 LTV，也换不来 QALY。任何未按留存曲线对收益进行加权的消费级健康产品经济模型，描述的其实是一个并不存在的产品。

## 计算方法

```
留存率_Dn = 第 n 天仍活跃的用户数 / 队列总人数 × 100
流失率    = 期间内流失的用户数 / 期初用户数 × 100

收益加权（这是卫生经济学的关键操作）：
  每名获客用户的预期收益 = Σ_t 留存率(t) × 收益率(t)
  ≈ 留存曲线下面积 × 单位时间收益
  ——而非 试验收益 × 100% 的获客用户数

每名 D30 留存用户的成本 = CAC / D30 留存率
  （在 4% 的 D30 留存率下，£5 的 CAC 实际上相当于每名留存用户 £125）
```

## 实例计算

一款心理健康应用：试验显示，完成 8 周疗程的每名用户获得 0.02 QALY。部署队列共 10 万次下载，D7 留存率 25%，D30 留存率 8%，第 8 周留存率 4%：

```
完成者人数           = 100,000 × 0.04 = 4,000
交付的 QALY          = 4,000 × 0.02 = 80（而非 100,000 × 0.02 = 2,000）
按 £20,000/QALY 计算 = £160 万的健康价值（而非 £4,000 万）

每次下载的健康价值 = £16——这才是决定支付方愿为每次下载
支付多少的数字，它仅为天真估算值的 4%。
留存改进案例：将第 8 周完成率从 4% 提升到 6%，
每年可增加 40 个 QALY ≈ £80 万——留存工程本身就是健康产出。
```

## 与软件工程的关联

按照上述算式，留存正是产品工程最直接创造健康价值的指标。能够改善它的做法都很朴素：入职流程到首次获得价值的时间、再激活设计、性能优化，以及至关重要的**计划剂量完成度**——一个设有明确终点（8 周后"毕业"）的项目，应该衡量*完成率*，而非永续性的 DAU，从而使指标与临床模型对齐，而非与广告驱动的注意力模型对齐。生存分析是正确的工具箱（与[获得的生命年](../生命年获益/)所用的 Kaplan-Meier 方法相同）；应按获客渠道对曲线进行分段，因为渠道构成对留存率的影响，往往超过大多数功能改动。

## 常见陷阱

- **意向治疗分析的反向清洗**：试验报告的是完成者数据；部署阶段的经济学必须统计所有获客用户（这正是 Eysenbach 的核心警示）。
- **留存表演**：由通知驱动的"活跃"用户，从未执行过真正的治疗性动作（参见[参与度指标](../参与度指标/)）。
- **跨定义比较曲线**："活跃"定义为打开应用还是执行有意义的动作，会使 D30 数值产生数倍的差异。
- **忽视谁在流失**：如果病情最重的用户流失最快，那么随着留存率在健康用户中提升，人均收益反而会下降——应将曲线与病例组合配合分析（参见[覆盖面与公平性](../覆盖面与公平性/)）。
