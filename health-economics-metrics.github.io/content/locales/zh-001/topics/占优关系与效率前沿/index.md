# 占优关系与效率前沿

如果一个方案的成本更低*且*效果更好，那么另一个方案就被称为**被占优**的。**效率前沿**是剔除掉所有被占优方案之后剩下的部分：在这个集合中，要获得更多效果，就必须付出更多成本。

## 为何重要

在讨论阈值或预算之前，卫生技术评估首先要做的，是剔除掉那些任何人都不应该选择的方案。将每个方案标绘在"成本-效果"平面上并画出前沿线，是一项只需五分钟的练习，却往往能直接淘汰掉候选清单中的一半方案。此后，增量比较（[ICER](../增量成本效果比/)）只在*沿着这条前沿线*进行计算——每个方案都只与紧邻其下、未被占优的次便宜方案比较——而绝不是在存在更好的中间方案时，仍与"什么都不做"相比较。

## 计算方法

```
严格占优：  若 成本_A ≤ 成本_B 且 效果_A ≥ 效果_B（其中至少一项为严格不等式），
           则称A占优于B

扩展占优：  若A与C的某种组合能以更低的每英镑成本实现更多效果，
           则B将被排除——判定方法是：随着沿前沿线向上移动，
           若ICER反而下降，即表明存在扩展占优。有效前沿上的ICER必须递增。
```

操作步骤：按效果对各方案排序；剔除所有严格被占优的方案；计算相邻方案之间的ICER；剔除任何ICER高于其右侧效果更好方案的选项（即扩展占优的情形）；重复此过程，直至ICER呈单调递增。

## 实例演算

针对降低爽约率有四个备选方案（效果 = 每年挽回的预约数）：

```
方案             年成本      挽回预约数
什么都不做        £0          0
短信提醒          £20,000     2,000
电话呼叫          £120,000    2,200
短信+AI分诊       £90,000     3,500
```

电话呼叫方案被"短信+AI分诊"方案**严格占优**（成本更高，挽回数却更少）。有效前沿为：什么都不做 → 短信 → 短信+AI。

```
ICER(短信 相对 什么都不做)   = 20,000 / 2,000  = 每挽回一次预约£10
ICER(短信+AI 相对 短信)      = (90,000 − 20,000) / (3,500 − 2,000) = 每挽回一次预约£46.67
```

ICER递增 → 前沿有效。按每挽回一次医院预约节省约£160计算（参见[爽约率](../爽约率/)），前沿上的这两步都值得采纳；而"电话呼叫中心"这一方案，本就不应该被摆上委员会的会议桌。

## 与软件工程的联系

对任何工具决策都可以绘制同样的图表：一个轴是每年成本，另一个轴是实测结果（节省的工时、避免的事件数、启用的部署次数）。位于前沿左上方的那些方案，在任何人开始讨论预算之前就应被剔除。这能把供应商选型，从围绕功能清单的争论，重塑为"你被占优了，会议到此结束"。它同样能揭示一种常见的企业病症：为一点微小的边际收益，购买最昂贵的方案——只有当组织愿意在明知情况下为那份边际单位收益支付相应边际价格时，这样做才是合理的。

## 陷阱

- **将一切都与基线相比较**，而非与前沿上的相邻方案相比较——这会通过掩盖更便宜的近似等效方案，人为抬高昂贵方案的吸引力。
- **单一维度的效果评分**掩盖了真正重要的信息；如果有两个结果都算数，要么以站得住脚的方式将其合并（参见[成本效用分析](../成本效用分析/)），要么就展示两条前沿线。
- **忽视不确定性**：在[敏感性分析](../敏感性分析/)下，靠近前沿线的方案排序可能会发生互换。
