# 需治疗人数（NNT）

NNT是指在一个规定的时间范围内，需要接受某项干预的患者数量，才能使其中**一名**额外患者获益。它将容易误导人的百分比风险降幅，转化为任何人都能直观理解的"每份获益所需付出的努力"单位。

## 为何重要

"心脏病发作风险降低25%！"听起来极具说服力。但如果基线风险是5年内4%，那么绝对降幅其实只有1个百分点，也就是说**需要100人连续服药5年，才能让其中1人获益**——而这100人都要承担相应的成本与副作用。NNT正是应对相对风险营销话术的解药，这也是循证医学之所以以其为首要指标的原因。以他汀类药物用于一级预防为例：每避免一次心脏病发作，5年内的NNT约为50–100。它的镜像指标**NNH**（需伤害人数）则衡量平均每伤害一人，需要治疗多少人。

## 计算方法

```
ARR（绝对风险降幅） = 对照组事件发生率 − 治疗组事件发生率
NNT                = 1 / ARR

NNH（需伤害人数）   = 1 / (治疗组伤害率 − 对照组伤害率)

经济学桥梁：
每避免一次事件的成本 = NNT × 每个疗程的成本
```

务必同时说明时间范围与基线人群——脱离这两者，NNT毫无意义。

## 实例演算

某医院的跌倒预测系统，标记出高风险患者以进行干预（床垫传感器、复核、加强看护）。试验数据：伴有损伤的跌倒率从入院患者的3.2%降至2.4%。

```
ARR = 0.8个百分点 → NNT = 1/0.008 = 125
   （需要125名患者接受该干预组合，才能预防1次伴有损伤的跌倒）

干预成本约为每名患者£40 → 每避免一次跌倒的成本 = 125 × 40 = £5,000
一次伴有损伤的院内跌倒的成本（额外住院、影像检查、诉讼风险）约为£12,000
净结果：预防措施的投入产出比约为2.4:1——外加额外的QALY获益。
```

请注意NNT是如何确保这一主张保持诚实的："跌倒率降低25%"与"每治疗125名患者可预防1次跌倒"，其实是同一个结果，只是说服力的呈现方式不同。

## 与软件工程的联系

NNT正是任何"对大量项目采取行动、却只捕获少数问题"的关卡或检查机制的恰当计量单位："**需要多少个PR通过AI评审关卡，才能真正捕获一个流向生产环境的缺陷？**"如果该关卡每评审400个PR才能真正捕获一个实际问题（NNT = 400），而每次评审耗费开发者4分钟的注意力，那么每捕获一个问题就要花费约27个开发者-小时——现在可以将这个数字与该问题若真的流入生产环境所造成的事件成本相比较。NNH对应的则是假阳性：每出现一次*误报*要检查多少个PR，每一次误报又耗费了多少注意力与信任成本？筛查类工具（代码检查器、安全扫描器、异常检测）在发布时就应附带NNT/NNH算术——参见[筛查经济学](../筛查经济学/)，了解为何低患病率会使这些数字变得异常残酷。 [需要筛查人数](../需要筛查人数/)是高一层级的对应数字，针对的是整个筛查再治疗的项目，而不只是治疗。

## 陷阱

- **没有时间范围**："NNT = 50"这句话本身毫无意义；"5年内NNT = 50"才是一个完整的主张。
- **基线风险的直接移植**：在高风险试验人群中计算出的NNT，一旦应用到低风险的实际部署人群中就会失真崩溃。
- **忽视NNH**——一个NNT为400、NNH为3的关卡机制，只是一台制造麻烦的机器，而非一套真正的安全系统。
