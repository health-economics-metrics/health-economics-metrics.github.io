# 成本后果分析 (Cost-Consequence Analysis，CCA)

CCA 将成本与**一份未经归并的全部结果清单**——临床的、运营的、体验层面的——并列呈现，而不是把它们压缩成单一的比率或评分。决策者需要明确地权衡这些取舍。

## 为什么重要

在 NICE 的证据标准框架 (Evidence Standards Framework) 下，CCA 是**大多数数字健康技术的首选经济学呈现格式**。数字化产品会产生异质性的效果（节省的时间、满意度、爽约率下降、微小的临床获益），很难诚实地归并成一个 QALY 数字。CCA 没有强行构造一个脆弱的复合指标，而是展示完整的账目。对大多数软件商业论证而言，这既是最诚实的格式，也是最有说服力的格式，因为每一位利益相关方都能在其中找到与自己决策相关的那一行。

## 计算方法

这里刻意不设归并公式。输出是一张表：

```
                          干预方案       对照方案     差异
成本（年度）                £X             £Y           ΔC
结果 1（原生单位）          …              …            Δ1
结果 2                     …              …            Δ2
定性结果                    只作描述，不评分
```

每一行都保留自己的单位。规则：所有结果都须预先设定（不得在得到结果后挑选有利的呈现）；全程使用相同的[视角](../分析视角/)和[时间周期](../时间周期/)；每一行都要标注不确定性。

## 算例

数字化术前评估平台 vs 电话流程，按年计算，某一家信托机构：

```
                              数字化        电话        差异
运行成本                      £180,000      £95,000     +£85,000
用于评估的护士工时             6,200         11,800      −5,600 小时
当日手术取消数                 92            174         −82
患者满意度（CSAT）             4.5/5         3.9/5       +0.6
评估丢失/未完成率               1.2%          4.8%        −3.6 个百分点
```

没有单一评分——但这个决策却很容易推理：£85,000 换来了 5,600 护士工时（约合每小时 £15，远低于任何用工成本）、82 例避免的取消（每例都会浪费一个价值约 £1,200 的手术档期），以及更好的体验。委员会也能清楚地看到自己*没有*得到什么：没有声称任何 QALY 或死亡率方面的效果。

## 与软件工程的关联

CCA 是一套良好的平台提案本就在使用的平衡计分卡的正式版本：成本与 DORA 指标、开发者体验 (DevEx) 评分、事故数量并列，不作归并。值得补充的卫生经济学纪律是：**预先设定各行内容**（在试点开始前就决定哪些指标算数，这样就不能在某项指标变差后悄悄把它去掉），以及**展示不利的行**——一份只有好消息的 CCA 就是营销材料。当不存在站得住脚的复合指标时使用 CCA——而对开发者工具而言，这几乎总是如此。

## 陷阱

- **挑选有利结果**——该格式的完整性取决于事先的预先设定。
- **偷偷塞入归并**：用颜色编码或"总体评分"重新引入了 CCA 本就旨在避免的任意权重。
- **决策瘫痪**：CCA 需要一位愿意权衡取舍的决策者；应配以明确的建议及其理由。
