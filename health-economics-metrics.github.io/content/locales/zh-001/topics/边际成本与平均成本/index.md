# 边际成本与平均成本

平均成本是总成本除以产出单位数。边际成本则是多生产一个*额外*单位所需的成本。决策应当依据边际成本来做——但已发布的单位成本数字几乎总是平均成本。

## 为何重要

数字健康商业论证中最常见的一个错误，就是按**平均**成本为节省下来的资源估值，而实际的节省其实是**边际**成本。一个医院床位天的平均（全额分摊）成本超过£400，但释放一个床位天并不能节省£400——建筑、供暖以及大部分人力成本仍会照常发生。除非释放的床位足够多、能够关闭一整个病区，否则实际释放出的现金可能只有£50–£150。

## 计算方法

```
平均成本：  AC = TC / Q
边际成本：  MC = dTC/dQ   （多生产/少生产一个单位所需的成本）

TC = 总成本，Q = 数量
```

固定成本的存在，使得在产能削减场景下MC < AC，而当存在闲置产能时，MC甚至可能趋近于零。关于节省的主张应采用：

```
真实节省 = ΔQ × MC          （小幅变动时）
真实节省 = TC的阶跃变化      （跨越产能阈值的大幅变动，例如关闭一个病区）
```

## 实例演算

你的软件缩短了平均住院时长，为某信托机构每年释放出1,000个床位天。

- **朴素主张**：1,000 × £400平均成本 = **节省£400,000**。这是错的。
- **边际主张**：每个床位天的可变成本（餐食、洗涤、耗材，以及部分弹性护理人力）约为£120。节省额 = 1,000 × £120 = **£120,000**，*外加*若这些释放出的床位被用于择期等候患者，还有相应的产能价值（按活动付费机制下的收入，或等候名单的缩减）。
- **阶跃变化主张**：如果该信托机构每年能释放7,300个床位天（相当于一个20张床位的病区），就可以真正关闭这个病区：人员配置+运营成本合计约每年£150万的真实现金。此时，按平均成本计算得出的数字，反而更接近真实情况。

同一项干预措施，会得出三个各自都站得住脚的数字，具体取决于这一变化是否跨越了某个产能阶梯。

## 与软件工程的联系

云计算经济学本身就是边际成本的天然领域：

- 在已预留产能上多运行一次CI，其边际成本约为£0，而每次运行的平均成本（平台总支出 ÷ 运行次数）却可能高达数英镑。按平均成本收费的内部计费系统，会驱使团队不敢充分使用那些在边际上其实是免费的共享产能。
- 反过来，"我们节省了30%的算力"，只有在实例真正被终止、或预留资源真正被削减时，才能真正释放现金——这正是软件版本的"床位天陷阱"。参见[现金释放型与非现金释放型节省](../现金释放型与非现金释放型节省/)。

## 陷阱

- **按平均成本为产能估值，并将其呈现为现金**（这是最经典的错误）。
- **假设边际成本是恒定不变的。**它会在产能边界处出现阶跃（病区关闭、许可分级、预留实例承诺）。
- **在同一份论证中，扩容决策用边际成本、缩容决策却用平均成本**——应根据实际所面对的决策类型来选择。
