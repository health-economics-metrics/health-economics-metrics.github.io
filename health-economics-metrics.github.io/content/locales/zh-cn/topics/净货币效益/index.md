# 净货币效益 (Net Monetary Benefit，NMB)

NMB把一个成本效果结果转化为单一的货币数值：按支付意愿阈值为健康获益定价，再减去成本。它的孪生指标净健康效益（Net Health Benefit，NHB）以健康单位表达同一条规则。

## 为什么重要

比率（[ICER](../增量成本效果比/)）用起来很别扭：它们在效果趋近于零时会发散，无法在不确定性抽样之间取平均，也无法干净利落地对三个及以上方案排序。NMB解决了所有这些问题——它是线性的，因此你可以对各方案排序、对蒙特卡洛抽样取平均、并可以分解贡献来源。它也是每一位工程师早已熟知的那种健康经济学算术的形式：*价值减去成本*。

## 计算方法

```
NMB = (ΔE × λ) − ΔC
NHB = ΔE − (ΔC / λ)

ΔE = 增量效果（例如QALY）
ΔC = 增量成本
λ  = 支付意愿阈值（参见willingness-to-pay-thresholds.md）

决策规则：若NMB > 0则采纳（等价于NHB > 0）。
多方案之间：选择NMB最高的方案。
```

NMB > 0 ⇔ ICER < λ（当ΔE > 0时），因此两条规则是一致的——只是NMB的行为表现更好。

## 算例

针对某糖尿病服务的三个方案，按每1,000名患者计，λ = 每QALY £20,000：

```
方案             ΔC          ΔE（QALY）   NMB = 20,000×ΔE − ΔC
App + 辅导       £400,000    30           600,000 − 400,000 = £200,000
仅App            £150,000    12           240,000 − 150,000 = £90,000
增设门诊         £700,000    32           640,000 − 700,000 = −£60,000
```

"增设门诊"获得的QALY最多，但在这一阈值下却损毁了价值（NMB < 0）。"App + 辅导"胜出。请注意，NMB可以让你*一次性对全部三个方案排序*——两两比较ICER则需要用到[占优与效率前沿](../优势与效率前沿/)中的前沿方法，最终会得到相同的答案。

胜出方案的NHB视角：30 − 400,000/20,000 = 30 − 20 = **净10个QALY**——这是同样这笔钱若花在别处本可产生的健康效益之外、额外获得的健康收益。

## 与软件工程的关联

`（节省的工时 × 负荷时薪） − 工具成本`——这个日常的工具类商业论证——本质上就是一次λ取值为负荷工程师成本的NMB计算。卫生经济学在此基础上增加了两点升级：

- **把λ当作一个变量，而不是常数。** 把NMB相对于λ（"一个工程师小时的价值"）画成曲线，展示决策在何处翻转；不同的利益相关方就可以套用自己的估值，而无需重做你的计算。
- **NHB式思维**："这个平台节省了5,000个工程师小时，但所消耗的预算原本可以买到3,000个工程师小时的外包产能——净得2,000小时"，这种表述会强制用产能单位进行机会成本比较。参见[机会成本](../机会成本/)。

## 常见陷阱

- **隐藏阈值**：不说明λ，NMB就毫无意义；应同时按£20k与£30k两档报告NMB，或直接画出曲线。
- **用NMB为微小效果"洗白"**：庞大的人群乘以一个微不足道的人均效果，也能得出一个可观的NMB数字——应同时报告人均效果。
- **忘记NMB会继承ΔC与ΔE中的所有不确定性**——应配合[概率敏感性分析](../概率敏感性分析/)一起报告。
