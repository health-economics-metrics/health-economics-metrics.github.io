# 远程患者监测经济学 (Remote Patient Monitoring Economics)

在家中监测患者的报销与成本抵消经济学：在美国，这是一套明确定义的 CPT 代码收入体系；在国家医疗服务体系中，这体现为避免入院和虚拟病房（virtual ward）经济学，直至完全实现**居家医院（hospital-at-home）**替代。

## 为什么重要

RPM（远程患者监测）是设备数据转化为可计费医疗服务的地方。美国 Medicare 体系（2025 年全国平均水平）异常明确：

```
99453  设置与患者教育           ~$19.73  一次性收费（16 天数据之后）
99454  设备提供 + 数据传输      ~$43.03  每 30 天——要求 30 天内
                                          至少有 ≥16 天的读数
99457  每月前 20 分钟管理       ~$47.87  要求 ≥20 分钟的记录时长
99458  每增加 20 分钟           ~$38.49
```

一个合规的患者-月大致累计为**每患者每月约 $90-130（PMPM）**。在成本抵消方面，居家医院项目（CMS 的居家急症医疗豁免计划：300 多家医院参与）显示，相比住院治疗，每例平均可节省约 $1,800-$3,000，且再入院率和感染率更低——这是监测加虚拟护理能够替代系统中最昂贵资源（有护理人员配置的病床）的最清晰证明。

## 计算方法

```
RPM 收入（美国）= 已注册人数 × 计费合规比例 × 代码堆叠 PMPM
  ——16 天规则使佩戴依从率（wearable-validation.md）
    成为一个收入变量，而 20 分钟规则则使临床时间
    记录成为一项工程需求

NHS 式价值   = 避免的入院数 × 边际入院成本
             + 被替代的住院天数 × （住院日成本 − 虚拟病房日成本）
             − 服务成本（设备、平台、监测人员）
  （关于归因和边际成本规则，参见 emergency-attendance-avoidance.md
   和 bed-days-saved.md）
```

## 实例计算

一家美国诊所为 400 名高血压患者提供服务；典型月份中 70% 达到 16 天阈值；60% 记录了管理分钟数：

```
月收入 ≈ 400 × [0.70 × 43.03 + 0.60 × 47.87] = 400 × 58.84 ≈ $23,500
年收入 ≈ $282,000；服务成本（设备每月 $12，人员 0.8 FTE）≈ $180,000
利润 ≈ 每年 $100k——请注意，这些杠杆都是工程杠杆：
将 16 天合规率从 70% 提升到 85%，可增加约每年 $31k
（设备舒适度、同步可靠性、提醒设计）。
```

NHS 版本对照：一个拥有 50 张床位、占用率 80% 的虚拟病房，替代住院天数每天净节省 £150 ≈ 50 × 0.8 × 365 × 150 ≈ **每年 £219 万**毛节省——需扣除平台、设备以及负责运营的社区护理团队成本。

## 与软件工程的关联

RPM 平台是少数几种**正常运行时间和同步可靠性能直接转化为收入**的产品之一（一周同步失败就会让某个队列跌破 16 天门槛），也是审计级时间追踪（20 分钟规则）作为一等特性而非事后补充的产品。应围绕以下方向构建：能在合规月份仍可挽救时提前标记风险的按患者计费合规仪表盘；带时间戳、防篡改的数据轨迹（支付方审计是常规操作）；以及警报经济学调优——每一条警报都消耗监测团队的分钟数，而这些分钟数既是可计费单位，也是稀缺资源（[筛查经济学](../筛查经济学/)决定了该阈值的选择）。

## 常见陷阱

- **注册人数 ≠ 收入**：合规比例才是关键数字；应对其建模，而非假设它。
- **将美国代码体系直接移植到 NHS 场景**——国家医疗服务体系购买的是避免入院，而非 CPT 代码堆叠；应运行第二套模型。
- **按平均成本主张抵消收益**，而固定成本本身并未随之消失的入院情形（参见[边际成本与平均成本](../边际成本与平均成本/)）。
- **监测团队的饱和问题**：警报量随注册人数增长而增长；人员配置这一项，是大多数模型都遗漏的约束条件。
