# Анализ «затраты-полезность» (Cost-Utility Analysis, CUA)

CUA — это анализ затратной эффективности с **универсальным исходом, взвешенным по предпочтениям** — почти всегда это [QALY](../год-жизни-с-поправкой-на-качество/) (или предотвращённый [DALY](../год-жизни-с-поправкой-на-инвалидность/)). Поскольку единица исхода универсальна, CUA может сравнивать вмешательства при совершенно разных заболеваниях.

## Почему это важно

Национальная система здравоохранения должна выбирать между онкологическим препаратом, приложением для психического здоровья и хирургическим роботом из одного бюджета. Натуральные единицы не позволяют их сравнить; QALY позволяют. Поэтому CUA — референсный метод в NICE и большинстве органов HTA: её результат — стоимость за QALY, оцениваемая относительно [порога](../пороги-готовности-платить/) — это самое близкое к универсальному обменному курсу, что есть в политике здравоохранения. Если вы хотите, чтобы ваше ПО финансировалось *вместо чего-то другого*, CUA — это та арена, на которой это решается.

## Математика

```
ICUR = ΔЗатраты / ΔQALY      (ICER, где в качестве единицы эффекта используется QALY)

ΔQALY = Σ (длительность_i × полезность_i)_новое − Σ (длительность_i × полезность_i)_старое
```

Полезности (utilities) получают из валидированных инструментов ([EQ-5D](../eq-5d/)); и затраты, и QALY [дисконтируются](../дисконтирование-и-временные-предпочтения/) на 3,5% (референсный кейс NICE); неопределённость оценивается через [PSA](../вероятностный-анализ-чувствительности/).

## Практический пример

Приложение КПТ (когнитивно-поведенческой терапии) при умеренной тревожности против листа ожидания на очную терапию, на пациента:

```
Затраты:  лицензия на приложение + поддержка       £250
          вытесненная терапия                      −£680   (40% пользователей больше в ней не нуждаются)
          ΔC = 250 − 680 = −£430 (экономия средств)

QALY:     6 месяцев при полезности 0.76 вместо 0.68 в период ожидания
          ΔE = 0.5 × (0.76 − 0.68) = +0.04 QALY
```

ΔC < 0 и ΔE > 0: приложение **доминирует** — лучше и дешевле, коэффициент не нужен. Если бы допущение о вытеснении терапии составляло всего 10%, ΔC = 250 − 170 = +£80, а ICUR = 80 / 0,04 = **£2 000/QALY** — всё ещё далеко ниже £20 000. Кейс выживает даже при резком урезании ключевого допущения: именно так выглядит устойчивый CUA (и [торнадо-диаграмма](../анализ-чувствительности/) это доказывает).

## Связь с разработкой программного обеспечения

Глубокая идея CUA — *единая композитная единица, взвешенная по предпочтениям, для сравнения непохожих вещей* — это шаблон для сравнения непохожих инженерных инвестиций (безопасность против опыта разработчика против надёжности). Честные варианты — это либо защитимая композитная единица (редкость), либо явная [таблица «затраты-последствия»](../анализ-затраты-последствия/) (обычный случай). Против чего предостерегает CUA, так это против фальшивого композита: взвешенный «показатель влияния», чьи веса были подогнаны постфактум, чтобы победил предпочтительный вариант. Экономика здравоохранения потратила десятилетия на стандартизацию извлечения полезностей именно для того, чтобы веса предшествовали сравнению.

## Подводные камни

- **Выигрыши полезности ниже чувствительности инструмента** (см. минимально клинически значимую разницу в [исходах, сообщаемых пациентами](../исходы-сообщаемые-пациентами/)) — крошечная ΔE, умноженная на большие популяции, — классический трюк отмывания.
- **Пропуск вытеснения помощи компаратора** — крупнейшая статья затрат для цифровых продуктов часто именно то, что они заменяют.
- **Сопоставление шкал, не основанных на предпочтениях, с полезностями** через неваллидированные переходные таблицы (crosswalks).
