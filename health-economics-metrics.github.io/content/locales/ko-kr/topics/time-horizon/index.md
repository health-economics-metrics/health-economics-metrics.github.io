# 평가 기간

평가 기간은 분석이 비용과 효과를 계산하는 기간입니다. 비교되는 옵션들 사이의 모든 의미 있는 차이를 포착할 만큼 충분히 길어야 합니다.

## 왜 중요한가

짧은 기간을 선택하면 늦게 나타나는 편익(예방)이나 늦게 나타나는 비용(유지보수)을 놓치게 됩니다. 너무 긴 기간은 모든 것을 불확실성에 묻어버립니다. 보건기술평가는 사망률에 영향을 미치는 치료에 대해 종종 **평생** 기간을 사용합니다. [예산영향분석](../budget-impact-analysis/)은 그 질문이 가치가 아니라 감당 가능성이기 때문에 의도적으로 **1–5년**의 짧은 기간을 사용합니다.

## 수식

```
순현재가치 = Σ (t = 0 … T) [ (편익_t − 비용_t) / (1 + r)^t ]

T = 평가 기간(년)
r = 할인율
```

## 계산 예시

전자 처방 시스템은 도입에 200만 파운드, 운영에 연간 £200,000이 듭니다. 이는 연간 £600,000 상당의 투약 오류를 예방합니다.

```
1년 기간:  −£1,600,000
5년 기간:  £0
10년 기간: +£2,000,000
```

이 시스템은 5년 미만의 어떤 기간에서도 "실패"하고 10년에서는 "성공"합니다. 어느 쪽도 진짜 답이 아닙니다.

## 소프트웨어 공학과의 연관성

- **1 스프린트로 측정된 도구 평가**는 학습 곡선의 하락을 체계적으로 놓칩니다.
- **계약 기간 ≠ 편익의 평가 기간.**
- **레거시 교체 사례**는 오래된 시스템의 신뢰할 수 있는 수명 종료 시점까지 추정되어야 합니다.

## 함정

- **기간 쇼핑**: 자신의 옵션이 이기는 평가 기간을 선택하기.
- 동일한 비교 내에서 **옵션마다 다른 평가 기간** 사용하기.
- **할인이나 불확실성 분석 없는 평생 기간.**
