# 遠隔患者モニタリングの経済学

患者を自宅でモニタリングすることの償還と費用相殺の経済学:米国では定義されたCPTコードの収益積み上げ;国の医療サービスでは、完全な**病院代替在宅ケア**までの入院回避とバーチャル病棟の経済学。

## なぜ重要か

RPMは、機器のデータが請求可能な医療になる場所です。米国のメディケアの構造(2025年の全国平均)は異例なほど明示的です:

```
99453  設定と患者教育          約19.73ドル  1回限り(16日分のデータの後)
99454  機器の供給+送信         約43.03ドル  30日ごと — 30日中16日以上の
                                          測定値が「必要」
99457  月あたり最初の20分の管理 約47.87ドル  20分以上のログが必要
99458  追加20分ごと             約38.49ドル
```

コンプライアンスのある患者1か月分は、おおよそ**PMPM90〜130ドル**に積み上がります。費用相殺の側では、病院代替在宅ケアプログラム(CMS Acute Hospital Care at Home waiver:300以上の病院)は、入院ケアと比較して受診1件あたり約1,800〜3,000ドルの節約を示しており、再入院と感染症も少なくなっています — これは、モニタリングとバーチャルケアが、システムの中で最も高価なリソースである人員配置された病床を代替できることの最も明確な実証です。

## 数式

```
RPM収益(米国)  = 登録者数 × 請求コンプライアンスのある割合 × コード積み上げPMPM
  — 16日ルールは、装着時間コンプライアンス(ウェアラブルの検証を参照)を
    収益変数にし、20分ルールは臨床時間のログをエンジニアリング上の
    要件にする

NHS式の価値  = 回避された入院数 × 限界入院費用
             + 代替された病床日数 × (入院日費用 − バーチャル病棟日費用)
             − サービス費用(機器、プラットフォーム、モニタリングスタッフ)
  (帰属と限界費用のルールについては救急受診の回避と節約された病床日数を参照)
```

## 計算例

ある米国の診療所が400人の高血圧患者を登録します;典型的な月では70%が16日の閾値を満たします;管理時間は60%についてログされます:

```
月間収益 ≈ 400 × [0.70 × 43.03 + 0.60 × 47.87] = 400 × 58.84 ≈ 23,500ドル
年間 ≈ 282,000ドル;サービス費用(機器月12ドル、スタッフ0.8FTE) ≈ 180,000ドル
利益 ≈ 年間10万ドル — そしてこのレバーはエンジニアリングのレバーであることに
注目してください:16日コンプライアンスを70%→85%に上げると年間約3.1万ドルが
追加されます(機器の快適さ、同期の信頼性、リマインダーの設計)。
```

NHSの鏡像:80%の稼働率にある50床のバーチャル病棟が、入院日を1日あたり£150の正味節約で代替:50 × 0.8 × 365 × 150 ≈ **年間£219万**の総額 — プラットフォーム、機器、そしてそれを支える地域看護チームに対してです。

## ソフトウェア工学との関連

RPMプラットフォームは、**稼働率と同期の信頼性が直接収益に変換される**(1週間の同期失敗はコホートの16日ゲートを破ります)、そして監査グレードの時間追跡(20分ルール)が後付けではなく第一級の機能である、まれな製品です。以下のために構築してください:回復可能なうちにリスクのある請求月を浮かび上がらせる患者ごとのコンプライアンスダッシュボード;タイムスタンプ付きで改ざん検出可能なデータの痕跡(支払者の監査は日常的です);そしてアラート経済性の調整 — すべてのアラートはモニタリングチームの分数を消費し、それは請求可能な単位であると同時に希少な資源でもあります([スクリーニングの経済学](../screening-economics/)が閾値の選択を左右します)。

## 落とし穴

- **登録≠収益**:コンプライアンスのある割合が重要な数字です;それを想定するのではなくモデル化してください。
- **NHSのケースに移植された米国のコード** — 国の医療サービスはCPTの積み上げではなく入院回避を買います;2つ目のモデルを実行してください。
- 固定費が残る入院に対する**平均費用での相殺の主張**([限界費用と平均費用](../marginal-vs-average-cost/)を参照)。
- **モニタリングチームの飽和**:アラート量は登録者数に応じてスケールします;人員配置の項目は、ほとんどのモデルが省略する拘束制約です。
