# Дефицит QALY и модификаторы тяжести (QALY Shortfall and Severity Modifiers)

Дефицит QALY измеряет, сколько будущего здоровья заболевание отнимает у пациентов по сравнению с общей популяцией. NICE использует его для применения **модификаторов тяжести**: чем больнее популяция, тем дороже стоит каждый приобретённый QALY — вплоть до 1,7× от стандартного порога.

## Почему это важно

Начиная с руководства NICE 2022 года, тяжесть заболевания — это явный множитель ценности выигрышей здоровья, заменивший старую премию конца жизни. Технология для тяжёлого состояния оценивается относительно эффективного порога до ~£51 000/QALY вместо £30 000. Если ваше ПО служит тяжело затронутой популяции (продвинутая сердечная недостаточность, тяжёлое психическое заболевание), модификатор тяжести может стать разницей между финансируемым и нефинансируемым экономическим кейсом — и вам нужна математика дефицита, чтобы его заявить.

## Математика

Два показателя, вычисляемые за оставшуюся жизнь при текущем стандарте помощи:

```
Абсолютный дефицит       = QALY_общая_популяция − QALY_с_заболеванием
Пропорциональный дефицит = Абсолютный дефицит / QALY_общая_популяция
```

Веса NICE 2022 (применяется тот показатель, который даёт более высокий вес):

```
Вес ×1.0: абсолютный < 12 и пропорциональный < 0.85
Вес ×1.2: абсолютный ≥ 12 или пропорциональный ≥ 0.85
Вес ×1.7: абсолютный ≥ 18 или пропорциональный ≥ 0.95
```

Вес умножает ΔE (или, эквивалентно, порог): эффективная λ становится £24 тыс.–£36 тыс. при ×1,2 и £34 тыс.–£51 тыс. при ×1,7.

## Практический пример

Пациенты с агрессивным заболеванием, средний возраст 60 лет. Общая популяция в 60 лет ожидает 14,2 дисконтированных QALY; с заболеванием при текущей помощи — 2,1.

```
Абсолютный дефицит       = 14.2 − 2.1 = 12.1  (≥ 12 → соответствует ×1.2)
Пропорциональный дефицит = 12.1 / 14.2 = 0.852 (≥ 0.85 → также ×1.2)
```

ICER вашей платформы мониторинга составляет £26 000/QALY — выше стандартной срединной оценки £20 тыс.–£30 тыс., пограничный случай. С весом ×1,2: эффективный ICER = 26 000 / 1,2 ≈ **£21 700/QALY** — уверенно финансируем. Вычисление дефицита только что переломило решение.

## Связь с разработкой программного обеспечения

Взвешивание по тяжести — формальная версия того, что инженерные организации делают инстинктивно: тратят больше на единицу улучшения на самых неблагополучных системах. Переносимый паттерн — вычислите «дефицит SLO» каждого сервиса (насколько ниже ожидаемой здоровой базовой линии он работает, абсолютно и пропорционально), и взвешивайте ценность исправления соответственно. Это обосновывает арифметикой, а не спорами, почему горящая legacy-система получает больше инвестиций на сэкономленный час, чем здоровая. Это также несёт тот же урок управления: публикуйте веса *до* совещания по приоритизации, иначе каждая команда будет заявлять о своей тяжести.

## Подводные камни

- **Вычисление дефицита относительно неверной базовой линии**: он измеряется при *текущем стандарте помощи*, а не при нелеченом естественном течении.
- **Чувствительность к возрасту**: дефицит сильно зависит от возраста популяции (у более молодых пациентов больше QALY, которые можно потерять → выше абсолютный дефицит); используйте фактическое распределение возраста леченой популяции.
- **Допущение, что модификатор применяется везде** — это механизм NICE (Англия); другие органы HTA обрабатывают тяжесть иначе (или вообще никак).
