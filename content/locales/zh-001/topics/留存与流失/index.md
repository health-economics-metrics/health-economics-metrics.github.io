# 留存与流失

留存率衡量的是，一个用户队列在开始使用后第N天，仍保持活跃的比例（D1/D7/D30曲线）；流失率则是其对立面。数字健康领域一个残酷的基线数据是：**约90%的健康应用用户会在30天内放弃使用**——数字健康类应用的D30留存率约为3–4%，而全部应用的平均水平约为6%。

## 为何重要

Eysenbach在2005年为这一现象命名：**损耗定律（law of attrition）**——以高比例流失用户，是电子健康干预措施内在的、结构性的特征，而非某次具体实施的失误，电子健康试验中的损耗率经常超过50%。其经济学后果是全局性的：留存决定了任何效益能够被交付的*治疗窗口期*，而[单位经济学](../健康应用单位经济学/)也随之受制——为一个只坚持使用12天的用户支付的获客成本，既换不来LTV，也换不来QALY。任何一个消费级健康产品的经济学模型，如果不按留存曲线对效益进行加权，描述的其实是一个并不存在的产品。

## 计算方法

```
留存_Dn = 第n天仍活跃的用户数 / 队列总人数 × 100
流失率  = 该周期内流失的用户数 / 该周期起始时的用户数 × 100

效益加权（健康经济学的关键操作）：
  每名获取用户的期望效益 = Σ_t 留存率(t) × 单位时间效益率(t)
  ≈ 留存曲线下面积 × 单位时间效益
  ——而绝不是"试验效益 × 100%的已获取用户"

每名D30留存用户的成本 = CAC / D30留存率
  （在D30留存率4%的情况下，£5的CAC实际相当于每名留存用户£125）
```

## 实例演算

某心理健康应用：试验显示，每名完成8周使用的用户获得0.02 QALY。部署队列共10万次下载，D7留存率25%，D30留存率8%，第8周留存率4%：

```
完成者人数         = 100,000 × 0.04 = 4,000
交付的QALY         = 4,000 × 0.02 = 80  （而非100,000 × 0.02 = 2,000）
按每QALY £20,000计算 = £160万的健康价值（而非£4,000万）

每次下载对应的健康价值 = £16——这个数字才应该用来
设定支付方愿意为每次下载支付多少，它仅相当于朴素主张的4%。
留存改善的论证案例：将第8周完成率从4%提升到6%，每年可
增加40个QALY ≈ £800,000——留存工程本身就是健康生产。
```

## 与软件工程的联系

按照上述算术，留存正是产品工程最直接创造健康价值的那个指标。能撬动它的做法都很平常：引导流程的首次价值实现时间、重新唤起参与的设计、性能表现，以及至关重要的**计划性剂量完成**——一个有明确终点（8周后"毕业"）的项目，应当衡量*完成率*，而非永续的DAU，这能使该指标与临床模型对齐，而非与广告驱动的注意力模型对齐。生存分析正是恰当的工具箱（与[获得的生命年](../获得的生命年/)所用的Kaplan-Meier数学方法相同）；应按获客渠道对曲线分段，因为渠道组合对留存的影响，往往超过大多数功能改动。

## 陷阱

- **反向的意向性治疗式"洗数据"**：试验报告的是完成者；而部署阶段的经济学核算，必须计入所有被获取的用户（这正是Eysenbach最核心的警示）。
- **留存表演**：那些由通知驱动、却从未真正执行治疗性动作的"活跃"用户（参见[参与度指标](../参与度指标/)）。
- **跨越不同定义比较曲线**："活跃"被定义为"打开应用"还是"执行有意义的动作"，会使D30数字相差数倍。
- **忽视究竟是谁在流失**：如果病情最重的用户流失得最快，那么随着留存率在健康用户中不断改善，人均效益反而会下降——应将留存曲线与病例组合一并分析（参见[触达与公平](../触达与公平/)）。
