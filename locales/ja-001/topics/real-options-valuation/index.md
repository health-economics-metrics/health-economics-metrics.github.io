# リアルオプション評価

リアルオプション評価は、金融オプションの価格づけの論理を、(金融市場ではない)実物の投資判断に適用するものです。具体的には、成功した場合に、義務を負うことなく後でプロジェクトを拡張できる*拡張オプション*に対してです。単純化した1期間の二項モデル(Cox、Ross、Rubinstein、1979年)は、この柔軟性を直接評価し、「小さく出して様子を見よう」を勘から価格づけされた数値に変えます。

## なぜ重要か

静的なNPV計算は、プロジェクトを全か無かの賭けとして価格づけします。今日の規模で、永久に、資金を出すか出さないかです。実際のプロジェクト、特に段階的なデジタルヘルスの展開は、そのように賭けられることはまれです。保健システムは小さなパイロットに資金を出し、何が起こるかを見守り、うまくいった場合にだけさらに資金を投じられます。その柔軟性には本物の価値があり、それを無視すると、段階的な投資が一括の投資に比べて体系的に過小評価されます。これは、より安全に見える段階的な提案に報いる調達プロセスにとって、全くの逆です。リアルオプション評価は柔軟性そのものを価格づけするため、段階的な提案は、素朴なNPVの行では小さく見えるからと不利に扱われることなく、全面的にコミットする代替案と公平に比較できます。

## 数式

```
「上昇」状態のリスク中立確率:
  p = ((1 + 無リスク金利) − 下降係数) / (上昇係数 − 下降係数)

各状態での拡張ペイオフ(ゼロで下限 — 拡張は任意):
  ペイオフ_上昇 = max(プロジェクト価値 × 上昇係数 − 拡張コスト, 0)
  ペイオフ_下降 = max(プロジェクト価値 × 下降係数 − 拡張コスト, 0)

オプション価値(割引後の期待ペイオフ):
  オプション価値 = (p × ペイオフ_上昇 + (1 − p) × ペイオフ_下降) / (1 + 無リスク金利)

拡張後NPV = 静的NPV + オプション価値
```

プロジェクトの価値は、次の意思決定時点までに上昇(`上昇係数`)するか下降(`下降係数`)します。拡張はその状態で採算が合う場合にのみ実行されます。ペイオフをゼロで下限とすることが、これを義務ではなく真の*オプション*にしています。後で拡張するオプションではなく、先に情報を集めるオプションの価格づけについては、[完全情報の期待価値](../expected-value-of-perfect-information/)を参照してください。その意思決定を待つことのコストについては、[遅延コスト](../cost-of-delay/)を参照してください。

## 計算例

`プロジェクト価値 = £1,000,000`のデジタルサービスのパイロットで、次の意思決定時点までに1.5倍に上昇するか0.5倍に下降する可能性があり、無リスク金利は8%、拡張コストは£600,000です。

```
p = (1.08 − 0.5) / (1.5 − 0.5) = 0.58

ペイオフ_上昇 = max(1,000,000 × 1.5 − 600,000, 0) =  900,000
ペイオフ_下降 = max(1,000,000 × 0.5 − 600,000, 0) = max(−100,000, 0) = 0

下限が重要: 市場が期待外れの場合、このオプションは行使されない —
£600,000の拡張コストは、下降状態でプロジェクトが持つ£500,000の
価値を上回る。

オプション価値 = (0.58 × 900,000 + 0.42 × 0) / 1.08
              = 522,000 / 1.08
              ≈ £483,333.33
```

オプションの価値を静的NPVのベースラインである£200,000に加えると、拡張後NPV = 200,000 + 483,333.33 ≈ **£683,333.33**です。このオプション価値を含めず、静的NPVの£200,000だけを報告すれば、段階的なプロジェクトの真の価値を2倍以上過小評価することになります。

## ソフトウェア工学との関連

これは「今は最小限のバージョンを出して、軌道に乗ればさらに投資するオプションを残しておく」の正式版であり、デジタルヘルス製品の段階的な展開に直接関連します。[遅延コスト](../cost-of-delay/)や[WSJF/CD3](../wsjf-and-cd3/)の不確実性下での順序づけの枠組みと構造的に並行し、[完全情報の期待価値](../expected-value-of-perfect-information/)や[標本情報の期待価値](../expected-value-of-sample-information/)を補完します。この3つはいずれも、不確実性のもとでの柔軟性や情報を、異なる角度から価格づけします。

## 落とし穴

- **依拠する取引資産の仮定なしにリスク中立の価格づけを借りること**: リアルオプションのモデルは、金融オプションの価格づけからリスク中立確率を借りており、基礎となる価値が*取引される*資産であることを前提としています。本当に取引されない実物プロジェクトにとって、これはモデル化上の便宜であり、文字どおりの市場上の事実ではありません。
- **`上昇係数`/`下降係数`を自由なパラメータとして扱うこと**: 二項の上昇/下降の入力自体が正当化を必要とする仮定であり、望む答えを出すように選べる自由なパラメータではありません。
- **オプション価値だけを報告すること**: リアルオプションの価値は、単独のプロジェクトの静的NPVに*加算される*ものです。よくある誤りは、基本ケースを落としてオプション価値だけを報告することで、静的NPVが負なら案件を過大に、(上の計算例のように)静的NPVを完全に除外すれば過小に見せてしまいます。
