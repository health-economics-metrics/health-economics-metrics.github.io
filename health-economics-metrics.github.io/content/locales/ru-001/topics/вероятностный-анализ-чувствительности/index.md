# Вероятностный анализ чувствительности (ВАЧ)

ВАЧ присваивает распределение вероятностей каждому неопределённому параметру, отбирает их все одновременно тысячи раз (Монте-Карло) и сообщает *вероятность* того, что вариант является наилучшим выбором — вместо единой точечной оценки.

## Почему это важно

Референсный кейс NICE *требует* ВАЧ. Детерминированный анализ отвечает на вопрос «что если один параметр неверен?»; ВАЧ отвечает на вопрос «учитывая всё, чего мы не знаем одновременно, насколько вероятно, что мы принимаем правильное решение?» Его знаковый вывод, **кривая приемлемости экономической эффективности (КПЭЭ)**, отображает вероятность того, что вариант экономически эффективен, против порога готовности платить — превращая «ИКЭЭ составляет £24 000/QALY» в «есть 78%-ная вероятность, что это правильный выбор при £30 000/QALY».

## Расчёт

```
Для каждого из N розыгрышей (N ≈ 10 000):
  отобрать каждый параметр θ из его распределения
    (затраты ~ Гамма, вероятности ~ Бета, полезности ~ Бета, эффекты ~ Нормальное/логНормальное)
  вычислить ЧДВ_j(θ) = λ × Эффект_j(θ) − Затраты_j(θ) для каждого варианта j

КПЭЭ_j(λ) = доля розыгрышей, в которых вариант j имеет наивысшую ЧДВ при пороге λ
```

См. [чистую денежную выгоду](../чистая-денежная-выгода/) для ЧДВ и [пороги готовности платить](../пороги-готовности-платить/) для λ.

## Разобранный пример

Бизнес-кейс миграции платформы. Три неопределённых параметра:

```
Стоимость миграции      ~ Гамма,  среднее £800тыс, СО £200тыс
Годовая выгода          ~ Нормальное, среднее £350тыс, СО £150тыс
Длительность выгоды     ~ Равномерное, 3–6 лет
```

Для каждого из 10 000 розыгрышей вычисляется чистая выгода = длительность × годовая − стоимость (дисконтирование опущено для ясности). Иллюстративные результаты:

```
Средняя чистая выгода:     £775тыс
Вероятность чистая > 0:    0,86
5-й–95-й процентиль:      −£180тыс … +£1,9млн
```

Точечная оценка говорила «очевидно да». ВАЧ говорит «86% да, с реальным хвостом, где мы теряем £180тыс+» — именно это реально нужно владельцу портфеля, и это оценивает кейс для проведения предварительного исследовательского спайка (см. [ОЦПИ](../ожидаемая-ценность-полной-информации/)).

## Связь с программной инженерией

Инженеры уже доверяют Монте-Карло для прогнозирования поставки (выборка пропускной способности превосходит точечные оценки). Расширьте тот же механизм на деньги: распределения по внедрению, сэкономленному времени и зарплате, затем сообщайте «вероятность того, что эта платформенная инвестиция чиста-положительна» вместо ложно-точного ROI. Кривая в стиле КПЭЭ — вероятность быть наилучшим вариантом как функция того, как организация оценивает инженеро-час — это подлинно лучший артефакт для комитета финансирования, чем любое единственное число.

## Подводные камни

- **Мусорные распределения**: ВАЧ с выдуманными стандартными отклонениями — это детерминированный анализ в лабораторном халате. Основывайте разбросы на данных или структурированном экспертном заключении.
- **Игнорирование корреляции** между параметрами (высокое внедрение обычно коррелирует с высоким сэкономленным временем); независимая выборка занижает хвостовой риск.
- **Отчёт только о среднем** симуляции — весь смысл заключается в распределении и вероятности решения.
