# 内製か購入か

内製か購入かは、割引された[TCO](../total-cost-of-ownership/)、デリバリー時間、リスクにわたる、カスタム開発と商業的取得の構造化された比較です。実証的な事前分布は一方的です:**実際の構築費用は典型的には予測を30〜40%上回り**、購入したソリューションは40〜60%速く展開され、MITの2025年のGenAI研究は、購入されたAIツールが約67%の確率で成功した一方、社内構築が成功したのはその約3分の1の頻度であったことを発見しました。

## なぜ重要か

医療システムは常にこの意思決定に直面しており(NHSの言葉では「内製か委託か」)、エンジニアリング組織は体系的に構築の方向で判断を誤ります — なぜなら、構築者は[TCO](../total-cost-of-ownership/)ではなく構築を見積もるからであり、構築の方が楽しいからです。経済的な枠組みは正直な比較を強制します:両方の選択肢を同じ評価期間で価格設定し、両方をリスク調整し、そして*時間の差を[遅延コスト](../cost-of-delay/)として価格設定*します — これは最も頻繁に答えを決定し、最も頻繁に省略される項です。

## 数式

```
同じ3〜5年の評価期間で割引して比較する:

NPV_選択肢 = PV(便益、価値実現までの時間でシフト) − PV(TCO)

リスク調整(グリーンブックの「楽観バイアス」パターン):
  構築費用 × 1.3〜1.4        (超過の事前分布)
  構築の価値実現までの時間 +40〜60%(展開遅延の事前分布)
  購入:代わりに統合の現実チェックと撤退費用を加える

意思決定を左右する要因、通常決定する順に:
  1. 差別化 — この機能はあなたの製品なのか、それとも配管なのか?
  2. 価値実現までの時間 × CoD
  3. リスク調整済みTCO
```

## 計算例

あるトラストがe同意システムを必要としています。購入:年間£15万のSaaS、3か月で稼働。構築:見積もり£60万+年間£12万の保守、12か月で稼働。

```
リスク調整後の構築:600k × 1.35 = £81万;価値実現までの時間≈18か月
5年TCO:  購入 = 150k × 5 = £75万
        構築 = 810k + 120k × 5 = £141万
遅延の項:同意のデジタル化は月£2.5万を節約;構築は15か月遅れて到着
        → CoD = 15 × 25k = £37.5万

実効的な比較:£75万 対 £178.5万 — 購入が約£100万の差で勝ち、
構築自体の次に大きな単一の項は、誰も価格設定していなかった遅延コストです。
```

その機能が差別化要因である場合(あなたの製品の中核アルゴリズム)、どのベンダーも厳格な制約(臨床的安全性、データの所在地)を満たさない場合、あるいはベンダーロックインのリスクが深刻で価格設定されている場合、構築は依然として正しい選択です。

## ソフトウェア工学との関連

転用できる医療経済学の規律は3つあります:**事前分布に基づくリスク調整**(30〜40%の超過の引き上げは、ソフトウェア版のグリーンブックの楽観バイアスです — それを機械的に適用し、そこから議論するのではなく例外について議論してください);**比較対象の正直さ**(構築の代替は「何もしない」ではなく、利用可能な最良の購入です — [機会費用](../opportunity-cost/)を参照);そして**費用比較の前の同等性テスト**(購入と構築が本当に同じ仕様を満たすなら、これは[費用最小化分析](../cost-minimization-analysis/)であり、安い方が勝ちます;そうでなければ、アウトカムの差は主張されるのではなく評価されなければなりません)。

## 落とし穴

- **ベンダーの定価をリスク調整されていない構築の見積もりと比較すること** — 構築を二重に有利に見せます。
- **無料と値付けされた社内労働**(「チームはすでにここにいる」)。
- **双方向で値付けされていないロックイン**:ベンダーの撤退費用だけでなく、構築のバスファクターと保守の継続性も。
- **アイデンティティ主導の構築**:「これは私たちにとって中核だ」が配管に対して主張されること — 差別化を、顧客が気づくかどうかでテストしてください。
