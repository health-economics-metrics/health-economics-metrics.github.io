# Анализ затрат и последствий (АЗП)

АЗП представляет затраты наряду с **дезагрегированной таблицей всех результатов** — клинических, операционных, связанных с опытом — не сводя их к единому соотношению или баллу. Лицо, принимающее решение, взвешивает компромиссы явно.

## Почему это важно

АЗП — это **предпочитаемый экономический формат NICE для большинства технологий цифрового здравоохранения** в рамках Рамочной программы стандартов доказательств. Цифровые продукты производят гетерогенные эффекты (сэкономленное время, удовлетворённость, снижение неявок, небольшие клинические выгоды), которые сопротивляются честному агрегированию в единую цифру QALY. Вместо того чтобы навязывать хрупкий составной показатель, АЗП показывает полный реестр. Для большинства программных бизнес-кейсов это одновременно самый честный и самый убедительный формат, потому что каждая заинтересованная сторона может найти свою собственную релевантную для решения строку.

## Расчёт

Намеренно нет формулы агрегирования. Результат — это таблица:

```
                          Вмешательство   Компаратор   Разница
Затраты (годовые)          £X             £Y           ΔC
Результат 1 (натуральные единицы)  …      …            Δ1
Результат 2                 …             …             Δ2
Качественные результаты     описаны, не оценены баллами
```

Каждая строка сохраняет собственные единицы. Правила: каждое последствие заранее определено (без выборочного подхода после результатов); одна и та же [перспектива](../перспектива-анализа/) и [горизонт](../временной-горизонт/) везде; неопределённость по строкам.

## Разобранный пример

Цифровая платформа предоперационной оценки против телефонного процесса, в год, один траст:

```
                              Цифровая     Телефонная  Разница
Эксплуатационные затраты      £180 000     £95 000     +£85 000
Часы медсестёр на оценки      6200         11 800      −5600 ч
Отмены операций в тот же день  92           174         −82
Удовлетворённость пациентов (CSAT)   4,5/5        3,9/5       +0,6
Утерянные/неполные оценки  1,2%         4,8%        −3,6 пп
```

Никакого единого балла — но решение легко обосновать: £85 000 покупают 6200 часов медсестёр (≈ £15/час, намного ниже любых затрат на персонал), 82 избежанные отмены (каждая тратит впустую операционный слот стоимостью ~£1200) и лучший опыт. Комитет также может точно увидеть, чего он *не* получает: никаких заявленных QALY или эффекта смертности.

## Связь с программной инженерией

АЗП — это формальная версия сбалансированной системы показателей, которую уже использует хорошее предложение по платформе: затраты наряду с метриками DORA, баллами DevEx, количеством инцидентов — не агрегированные. Дисциплина экономики здравоохранения, которую стоит добавить: **заранее определяйте строки** (решите, что учитывается, до пилота, чтобы нельзя было тихо убрать метрику, которая ухудшилась), и **показывайте неблагоприятные строки** — АЗП только с хорошими новостями — это маркетинг. Используйте АЗП, когда не существует обоснованного составного показателя, что для инструментов разработчиков — почти всегда.

## Подводные камни

- **Выборочные последствия** — целостность формата зависит от предварительного определения.
- **Скрытая агрегация**: цветовое кодирование или «общие баллы» вновь вводят произвольные веса, для избежания которых существует АЗП.
- **Паралич решения**: АЗП нужен человек, принимающий решение, готовый взвешивать компромиссы; сочетайте с рекомендацией и обоснованием.
