# 贴现与时间偏好 (Discounting and Time Preference)

贴现将未来的成本与收益折算为现值,因为今天获得的收益比五年后获得同样的收益更有价值。

## 为什么重要

每一项健康经济学评估、每一份严谨的公共部门商业论证,都会对多年期的现金流进行贴现。英国财政部 (HM Treasury) 的《绿皮书》(Green Book) 规定社会时间偏好率为每年 3.5%;NICE 的参考方案对成本和健康效果均按每年 3.5% 贴现(对于获益期超过 30 年以上的近治愈性疗法,采用 1.5% 的非参考方案贴现率)。如果你的软件商业论证声称"10 年内节省 500 万英镑",财务审核人员会立即要求提供贴现后的数字。

## 计算方法

未来金额的现值:

```
PV = FV / (1 + r)^t

PV = 现值
FV = 第 t 年的未来价值
r  = 贴现率(NICE/绿皮书:0.035)
t  = 距今年数
```

对于 n 年内每年恒定的收益 B(年金):

```
PV = B × [1 − (1 + r)^(−n)] / r
```

## 实例演算

你的软件为某 NHS 信托机构每年节省 10 万英镑,持续 5 年,从上线后第一年开始。

未贴现总额:50 万英镑。

按 3.5% 贴现:

```
第 1 年:100,000 / 1.035^1 = £96,618
第 2 年:100,000 / 1.035^2 = £93,351
第 3 年:100,000 / 1.035^3 = £90,194
第 4 年:100,000 / 1.035^4 = £87,144
第 5 年:100,000 / 1.035^5 = £84,197

现值总计 ≈ £451,505
```

诚实的头条数字约为 45.1 万英镑,比朴素求和低约 10%。现在假设交付延迟一年:每一项都相应后移一年,现值降至约 43.6 万英镑——这正是[延迟成本](../延迟成本/)的贴现视角。

## 与软件工程的关联

- **技术债偿还与平台迁移**承诺的是多年后才兑现的收益流;在与本季度即可回本的工作比较之前,必须先对其贴现。
- **前期投入重、后期收益晚**是迁移项目的标准形态。贴现正确地惩罚了这种形态:它为"现在投入产能、未来才获得价值"这一无风险时间成本定价。
- **"第 5 年才见效"的说法**应当受到双重质疑——它们既被大幅贴现,又高度不确定(参见[敏感性分析](../敏感性分析/))。

## 常见误区

- **只贴现成本而不贴现收益**(或反之)——参考方案要求以相同的贴现率对两者都进行贴现。
- **在公共部门案例中使用商业贴现率(8%–12%)**,或在风投支持的案例中使用 3.5%。贴现率应与决策者的性质相匹配。
- **将贴现与通货膨胀混淆。**贴现作用于*实际*(经通胀调整后)价值;不要对同一笔金额同时隐性叠加两者。
