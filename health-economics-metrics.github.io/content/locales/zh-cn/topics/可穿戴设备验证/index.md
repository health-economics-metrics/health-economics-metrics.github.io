# 可穿戴设备验证 (Wearable Validation)

验证指标用于量化一台可穿戴设备的测量值与临床金标准（心率对应 ECG，睡眠对应多导睡眠监测）之间的一致程度：**MAPE（平均绝对百分比误差）**、一致性相关系数，以及 Bland–Altman 一致性分析——此外还有用于把关真实世界数据质量的运营指标：**佩戴时间依从率**与**数据完整性**。

## 为什么重要

验证是下游一切工作的前提条件：一台无法证明与参考测量一致的设备，无法支撑[数字终点](../数字终点与生物标志物/)，无法支持 [RPM 计费](../远程患者监测经济学/)，也无法承载任何临床主张。业界对心率公认的阈值：相对 ECG，**MAPE ≤5%**（严格标准）或 **≤10%**（宽松标准）。文献中的参考数据点：Oura Gen 3 静息心率 MAPE 为 1.67%（CCC 0.97）；Fitbit Charge 6 的 MAPE 约为 5.5%——消费级设备如今已横跨临床级的边界，这正是为何必须按每台设备、每种条件分别进行测量的原因。

## 计算方法

```
MAPE = (1/n) Σ |测量值_i − 参考值_i| / 参考值_i × 100

CCC（一致性相关系数）= 同时衡量相关性与系统性偏倚的一致程度
      （Pearson 相关系数 r，按位置/尺度偏移做惩罚）

Bland–Altman：均值偏倚 ± 1.96 倍标准差的一致性界限——用于显示
      误差是否随数值大小而变化

运营把关指标：
佩戴时间依从率 = 佩戴时长 / 方案要求时长 × 100
数据完整性    = 实际观测数据点数 / 预期数据点数 × 100
```

验证必须**按活动条件**（静息、运动、睡眠）以及按人群分别报告——PPG 光学传感在存在运动伪影、接触不良和肤色较深时会出现性能下降，这是一个已被记录、涉及公平性的失效模式。

## 算例

某虚拟病房项目正在挑选一款监测用可穿戴设备。候选 A：静息 MAPE 2.1%，运动 MAPE 11.4%。候选 B：静息 3.8%，运动 6.9%。

```
使用场景：在家中检测病情恶化的患者——告警是在心率持续升高时触发的，
而这往往发生在活动期间。
候选 A 的宣传数字（2.1%）在宣传册上最亮眼，但真正适合该使用场景的
是候选 B：在与告警最相关的条件（运动）下，A 在心率 100 时的 11.4%
误差 = ±11 bpm——这一误差范围横跨了整个告警阈值区间，
会导致误报升级（每次都需要护士出动，约 £40）或漏报。

误报的经济账：500 名患者 × 每周多出 2 次误报 × £40
= 因选错验证数字而产生的每年 £2.08M 错误成本。
```

## 与软件工程的关联

工程师在选择传感器时是验证数据的使用者，在构建测量类功能时又是验证数据的*生产者*——这两个角色都需要同样的纪律：在部署条件下测试，而非在演示条件下测试（软件领域的对应做法：基于你自己的生产工作负载做基准测试，而不是供应商的）。佩戴时间与数据完整性本质上是产品工程层面的结果——舒适度、电池续航、充电仪式的设计，以及同步可靠性，共同决定了"30 天中 16 天"这一 RPM 计费门槛能否达成（参见[远程患者监测经济学](../远程患者监测经济学/)），也决定了试验数据集是否可供分析。应把数据缺失当作一种被设计出来的信号来对待：从第一天起，就在数据模式中区分"未佩戴"、"已佩戴但无信号"和"同步失败"——一旦全部坍缩为空值，就会污染下游的每一项分析。

## 陷阱

- **聚合 MAPE 掩盖了特定条件下的失效**——算例中的陷阱正是如此。
- **验证人群 ≠ 部署人群**：年龄、肤色、震颤、肥胖都会改变光学传感器的误差；须核查研究的人口学构成。
- **在需要一致性的场合却只报告相关性**：即使 Pearson 相关系数 r 很高，若存在系统性偏倚，在绝对阈值下依然会导致误判——应坚持要求 CCC/Bland–Altman 分析。
- **靠插补拉高完整性**：把被填补的缺口当作实际观测数据来报告。
