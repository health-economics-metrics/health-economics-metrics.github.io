# Стоимость задержки (Cost of Delay, CoD)

Стоимость задержки — это экономическая ценность, теряемая за единицу времени, пока функция, продукт или услуга *не* поставлены. Это самый прочный мост между метриками поставки ПО и экономикой здравоохранения: он превращает «мы задержали поставку» в валюту — или в QALY.

## Почему это важно

Правило Рейнертсена: «Если вы измеряете только одну вещь, измеряйте стоимость задержки». Большинство организаций знают, сколько стоит проект, но не знают, сколько стоит месяц задержки, поэтому они оптимизируют бюджеты, истекая кровью по временной ценности. Для медицинского ПО ставки буквальны: каждая неделя задержки улучшения пути означает, что пациенты дольше ждут в худшем состоянии здоровья. CoD — самая мощная математическая рамка для представления заинтересованным лицам NHS, потому что она оценивает *отсутствие* вашего ПО.

## Математика

```
CoD = выгода за единицу времени, упущенная, пока продукт не поставлен   (£/неделю или QALY/неделю)

Общие потери от задержки = CoD × длительность задержки

Для приоритизации см. wsjf-and-cd3.md: CD3 = CoD / длительность.
```

Для клинического ПО оценивайте и в здоровье, и в деньгах:

```
CoD_здоровье = число пациентов, затронутых в неделю × прирост QALY на пациента
CoD_деньги   = CoD_здоровье × λ (порог готовности платить, £20k–30k/QALY)
               + упущенная операционная экономия в неделю
```

## Практический пример

**Операционный пример**: ПО экономит £200 на пациента на одном пути; трест обрабатывает 50 таких пациентов/неделю.

```
CoD = 200 × 50 = £10,000/неделю
Задержка закупки на 10 недель обходится в 200 × 50 × 10 = £100,000 избегаемых потерь.
```

**Клинический пример**: улучшение сортировки устраняет 5 недель ожидания (полезность 0,68 → 0,80 раньше) для 100 пациентов/неделю:

```
Прирост QALY на пациента = (5/52) × 0.12 ≈ 0.0115
CoD_здоровье = 100 × 0.0115 = 1.15 QALY/неделю
CoD_деньги   = 1.15 × £20,000 ≈ £23,000/неделю ценности здоровья
```

Задержка развёртывания на 6 месяцев «стоит» ~30 QALY — аргумент, переформулирующий срыв запуска IT-системы как клиническое событие. (Бенчмарк для масштаба: знаменитый анализ Maersk от Black Swan Farming обнаружил отдельные функции с CoD ≈ $200 тыс./неделю, которые ждали 38 недель.)

## Связь с разработкой программного обеспечения

CoD — это метрика, делающая [время выполнения DORA](../метрики-dora/) и [эффективность потока](../метрики-потока/) финансово понятными: время выполнения × CoD = деньги (или здоровье), сожжённые в очередях. Применения:

- **Приоритизация**: ранжируйте работу по CoD/длительности ([WSJF/CD3](../wsjf-и-cd3/)) вместо самого громкого заинтересованного лица.
- **Экономика процесса**: двухнедельный цикл релизов имеет ожидаемую стоимость задержки ~1 неделя × CoD на функцию в сравнении с непрерывной поставкой — оцените партию.
- **Закупки**: циклы закупок NHS длиной 6–18 месяцев имеют свою CoD; демонстрация этого меняет разговоры о срочности (см. [анализ бюджетного воздействия](../анализ-бюджетного-воздействия/) для аналога доступности).

## Подводные камни

- **Допущение линейной CoD**: некоторые работы имеют ценность формы дедлайна (регуляторные даты — бесконечная CoD после даты, ноль до неё) или убывающую ценность (окна первопроходца). Классифицируйте профиль срочности перед умножением.
- **CoD для выпуска, который никому не нужен**: задержка стоит денег, только если вещь имеет ценность; задержанный мусор бесплатен.
- **Двойной счёт задержки и дисконтирования**: [дисконтирование](../дисконтирование-и-временные-предпочтения/) уже оценивает время на многолетних горизонтах; CoD — это операционная версия внутри горизонта. Используйте CoD для недель/месяцев, сдвиг NPV — для лет.
