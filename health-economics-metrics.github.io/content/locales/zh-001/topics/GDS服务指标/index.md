# GDS服务指标

英国政府数字服务局（GDS）《服务手册》要求每一项政府数字服务都必须报告四项KPI：**每笔交易成本、用户满意度、完成率，以及数字化使用率**。这四项指标共同构成了一项公共数字服务最基本的经济学框架——也是NHS数字服务所继承的模板。

## 为何重要

GDS的这些指标，正是支撑了过去十年政府数字化建设的"渠道转移"商业论证的具体化：《数字效率报告》发现，数字化交易的成本约为电话渠道的1/20，约为面对面渠道的1/50（地方政府数据：网页£0.15，电话£2.83，面对面£8.62）。但这些节省只有在人们*真正完成*数字化流程（完成率）、*且*选择该渠道而非昂贵渠道（使用率）时才能真正实现——这四项KPI构成的是一个单一的经济学模型，而非四块互不相关的仪表盘。

## 计算方法

```
每笔交易成本 = 服务总成本 / 已完成交易数
完成率       = 已完成交易数 / 已开始交易数 × 100
数字化使用率 = 数字化交易数 / 全渠道交易总数 × 100
用户满意度   = 满意+非常满意的占比（5分制，服务内调查）

渠道转移节省 = 交易量 × 使用率转移幅度 × (旧渠道成本 − 数字渠道成本)
… 再减去失败需求成本：(1 − 完成率) × 回退渠道成本
```

## 实例演算

某NHS预约管理服务：每年200万笔交易，目前70%通过电话（£3.20/通）、30%通过数字渠道（£0.25）。一次重新设计将数字化使用率提升至55%，完成率从84%提升至93%：

```
使用率转移带来的节省 = 200万 × 0.25 × (3.20 − 0.25) = 每年£1,475,000

失败需求节省：失败的数字化流程会回退到电话渠道
  改造前：200万 × 0.30 × 0.16 × £3.20 = £307,200
  改造后：200万 × 0.55 × 0.07 × £3.20 = £246,400
  净节省£60,800/年——完成率的改善保护住了使用率提升所带来的收益

满意度是一项先行指标：不满意的用户会退回电话渠道，
因此满意度的下降，会在使用率下滑出现之前就提前预示这一趋势。
```

## 与软件工程的联系

这四项KPI是一个生产级别的[成本后果表](../成本后果分析/)范例：一项成本指标，三项结果指标，从不被压缩为单一分数。对产品工程师而言，其中的运营启示是：**完成率本质上是一个漏斗埋点问题**（每一个流失点都是可以被找到并修复的）；**每笔交易成本**本质上就是[云单位经济学](../云单位经济学/)再加上人工辅助渠道的成本；**使用率其实是一项伪装过的公平性指标**——那些无法或不愿转换渠道的用户，往往不成比例地集中在老年人、残障人士与困难群体之中，因此激进的渠道关闭会把"节省"直接转化为可及性伤害（参见[触达与公平](../触达与公平/)）。将这些KPI公开发布（GOV.UK就是按服务逐项公开的）本身就是一种约束机制：透明度对预测起到的规范作用，正如[效益兑现](../效益兑现/)审计一样。

## 陷阱

- **靠强制手段提升使用率**：关闭电话线路确实能拉升数字化使用率，却把失败需求转嫁给了一线员工；应测量整个系统的总成本。
- **从第2页才开始测量完成率**：在流失点之后才开始计算漏斗，会人为美化完成率数字。
- **计算每笔交易成本时忽略辅助数字化支持**以及失败需求的处理成本。
- **只在成功完成时才发放满意度调查**——不满意的用户大多根本走不到调查这一步。
