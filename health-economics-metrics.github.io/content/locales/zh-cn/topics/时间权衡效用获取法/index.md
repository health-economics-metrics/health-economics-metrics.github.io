# 时间权衡效用获取法 (Time Trade-Off Utility Elicitation, TTO)

TTO 是直接从受访者那里获得某一健康状态的效用值、而不是凭空编造的标准方法。它是获取方法之一——与标准博弈法和离散选择实验并列——这些方法产生了 [EQ-5D](../eq-5d/) 等工具背后的价值集（value sets），因而也在大多数下游的 [QALY](../质量调整生命年/) 计算背后。

## 为什么重要

进入 QALY 计算的每一个效用权重都必然来自某处。TTO 就是那个“怎么来”：对于被认为好于死亡的状态，问受访者在完全健康状态下的多少年 `X` 相当于在受损状态下的 `T` 年（`X < T`）；效用为 `X / T`。对于一些受访者认为比死亡更糟的状态，标准公式不再适用（它无法干净地表示低于零的效用），因此使用扩展的 TTO。把效用权重当作给定输入、却不知道得到它需要一套经过验证的获取方案的软件工程师或分析师，距离一个在被质疑时无法辩护的数字只有一步之遥。

## 计算方法

```
标准 TTO（好于死亡的状态）：
  效用 = 完全健康的时间 / 受损状态的时间

扩展 TTO（比死亡更糟的状态）：
  效用 = −用于换取死亡的时间 / (总时长 − 用于换取死亡的时间)
```

`完全健康的时间` / `受损状态的时间`——被认为等价于受损状态下 `T` 年的完全健康 `X` 年。`用于换取死亡的时间` / `总时长`——在比死亡更糟的情境设定中，在 `T` 年余生里，受访者愿意用来换取立即死亡的年数 `a`，即宁可选择 `T − a` 年完全健康后死亡，也不愿在比死亡更糟的状态下度过 `T` 年。结果为负，锚定为死亡 = 0。

## 算例

**标准**：受访者处于受损状态 10 年，认为与 7 年完全健康无差异：效用 = 7 / 10 = **0.7**。

**比死亡更糟**：在 10 年余生中，受访者愿意用 2 年换取立即死亡——他宁可选择 8 年完全健康后死亡，也不愿在比死亡更糟的状态下度过 10 年：效用 = −2 / (10 − 2) = −2 / 8 = **−0.25**。

## 与软件工程的关联

DevEx 或敬业度调查在请人们对某事在未经验证的 0–10 量表上打分时遇到的同一个问题，在这里反过来适用：TTO 之所以存在，恰恰因为“只是请人们打分”本身并不是经过验证的获取方法。在基于自评数字构建综合指数——DevEx 得分、敬业度指数、倦怠量表——之前，应当问这个数字是怎么获取的，该方法是否经过验证；这与卫生经济学家在效用权重进入 QALY 之前问它的是同一个问题。

## 陷阱

- **由单个数值推而广之**：TTO 值是从公众（或患者）的一个*样本*获取的，而不是从正在为其护理做决定的那个人获取的——把一位受访者的 TTO 值当作可以推广来使用，是抽样错误。
- **状态设问方式不对**：标准 TTO 公式假定该状态明确好于死亡；把它用到一些受访者会认为比死亡更糟的状态上，而不切换到扩展设问方式，会悄悄给出错误的（正的）效用。
- **时长不可比**：在比死亡更糟的比较中，用不同余生 `T` 获取的 TTO 值不能直接比较，除非核实研究设计保持了 `T` 不变。
