# 自建与外购

自建与外购是一种结构化比较，基于贴现后的[总拥有成本（TCO）](../总拥有成本/)、交付时间与风险，对定制开发与商业采购两条路径进行比较。经验性的先验证据是一边倒的：**实际自建成本通常超出预测30–40%**，采购的解决方案部署速度快40–60%，而麻省理工2025年的生成式AI研究发现，采购的AI工具成功率约为67%，而内部自建工具的成功率大约只有其三分之一。

## 为何重要

医疗系统频繁面临这一决策（NHS的说法是"自制 vs 委托"），而工程组织系统性地偏向自建方向，且往往做错——因为自建者估算的是"建造"本身，而非[总拥有成本](../总拥有成本/)；也因为建造本身更有乐趣。经济学视角强制推行诚实的比较：两个选项都按同一时间范围定价，都经过风险调整，并且*把时间差价格化为[延迟成本](../延迟成本/)*——这一项往往才是最终决定答案的关键，却也最常被遗漏。

## 计算方法

```
在相同的3–5年时间范围内进行贴现比较：

方案净现值 = 现值(效益，按价值实现时间偏移) − 现值(总拥有成本)

风险调整（《绿皮书》"乐观偏差"模式）：
  自建成本 × 1.3–1.4        （超支先验系数）
  自建价值实现时间 + 40–60%  （部署延迟先验系数）
  外购：改为加入集成现实性核查成本与退出成本

决策驱动因素，按其通常起决定作用的顺序：
  1. 差异化程度——这项能力是你产品的核心，还是基础管道？
  2. 价值实现时间 × 延迟成本
  3. 经风险调整后的总拥有成本
```

## 实例演算

某信托机构需要一套电子知情同意系统。外购：SaaS方案每年£150,000，3个月内上线。自建：预估£600,000 + 每年£120,000维护费，12个月上线。

```
经风险调整的自建成本：600,000 × 1.35 = £810,000；价值实现时间约为18个月
5年总拥有成本：外购 = 150,000 × 5 = £750,000
             自建 = 810,000 + 120,000 × 5 = £1,410,000
延迟项：知情同意数字化每月节省£25,000；自建方案晚15个月上线
       → 延迟成本 = 15 × 25,000 = £375,000

实际比较结果：£750,000 对比 £1,785,000——外购胜出约£100万，
而在自建成本本身之外，最大的单项因素正是那笔此前无人计价的延迟成本。
```

当该能力具有差异化意义（你产品的核心算法）、没有任何供应商能满足硬性约束（临床安全、数据驻留要求），或供应商锁定风险严重且已被定价时，自建仍然是正确选择。

## 与软件工程的联系

可迁移的健康经济学纪律有三点：**基于先验的风险调整**（30–40%的超支上浮系数就是软件版的《绿皮书》乐观偏差——应机械地应用它，为例外情形提出论证，而非从例外情形出发论证）；**对比对象的诚实性**（自建的替代方案不是"什么都不做"，而是可获得的最佳外购方案——参见[机会成本](../机会成本/)）；以及**在比较成本之前先做等效性检验**（如果外购与自建在规格上确实等效，这就是[成本最小化分析](../成本最小化分析/)，更便宜的一方胜出；如果不等效，那么结果上的差异必须被赋予价值，而非仅凭断言）。

## 陷阱

- **将供应商标价与未经风险调整的自建估算相比较**——这是双重偏向自建的做法。
- **零定价的内部人力**（"反正团队已经在这里了"）。
- **双向均未定价的锁定风险**：供应商退出成本固然存在，但自建方案自身的"巴士系数"与维护延续性同样是风险。
- **出于身份认同而驱动的自建决策**："这对我们而言是核心"这种说法，其实往往只是基础管道——应以"客户是否会注意到"来检验其差异化程度是否成立。
