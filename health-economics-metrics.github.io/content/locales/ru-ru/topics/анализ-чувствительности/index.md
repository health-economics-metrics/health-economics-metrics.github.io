# Анализ чувствительности (Sensitivity Analysis)

Детерминированный анализ чувствительности (DSA) варьирует одно допущение за раз в правдоподобном диапазоне, чтобы увидеть, выживает ли вывод. Стандартная визуализация — торнадо-диаграмма: параметры ранжированы по тому, насколько сильно они качают результат.

## Почему это важно

Каждая экономическая модель построена на оценках — сэкономленном времени, внедрении, удельных затратах. Оценка медицинских технологий отказывается принимать точечную оценку («ROI составляет 340%») без доказательств того, что вывод устойчив к разумным разногласиям по поводу входных данных. Торнадо-диаграмма показывает лицу, принимающему решение, *какое допущение стоит подвергнуть сомнению*: если кейс работает только тогда, когда самый спорный параметр находится на своём оптимистичном краю, все видят это немедленно.

Это самая переносимая привычка из экономики здравоохранения в программные бизнес-кейсы.

## Математика

Для каждого параметра p с правдоподобным диапазоном [p_low, p_high]:

```
Результат_низкий  = модель(p = p_низкий,  все остальные в базовом случае)
Результат_высокий = модель(p = p_высокий, все остальные в базовом случае)
Размах(p)         = |Результат_высокий − Результат_низкий|
```

Ранжируйте параметры по размаху; постройте горизонтальные полосы вокруг базового результата. Варианты: двусторонний DSA (варьирование двух параметров на сетке), пороговый анализ (найти значение параметра, при котором решение переворачивается).

## Практический пример

ИИ-ассистент кодирования для 200 разработчиков. Базовый случай: лицензия £39/разработчик/месяц; экономия 30 мин/разработчик/день; полная стоимость £60/час; 220 рабочих дней.

```
Годовая выгода в базовом случае  = 200 × 0.5ч × 220 × £60 = £1,320,000
Годовая стоимость                = 200 × £39 × 12         = £93,600
Чистая величина в базовом случае = £1,226,400
```

Торнадо (по одному параметру за раз):

```
Сэкономленное время 0.1–1.0 ч/день: чистая = £170,400 … £2,546,400   (размах £2.38M) ← доминирует
Полная стоимость часа £40–£80/ч:    чистая = £786,400 … £1,666,400   (размах £0.88M)
Рабочие дни 200–240:                чистая = £1,106,400 … £1,346,400 (размах £0.24M)
Лицензия £30–£50/мес:               чистая = £1,248,000 … £1,200,000 (размах £48k)
```

Пороговый анализ: чистая выгода достигает нуля при экономии примерно **2,1 минуты/день**. Решение нечувствительно к цене лицензии и полностью зависит от оценки сэкономленного времени — так что измеряйте именно её, а не остальное. (И помните, что результат — это мощность, а не деньги — см. [экономию, высвобождающую и не высвобождающую денежные средства](../экономия-высвобождающая-и-не-высвобождающая-денежные-средства/).)

## Связь с разработкой программного обеспечения

Инженеры уже делают это инстинктивно как «а что если мы ошибаемся насчёт X?» — DSA просто делает это систематическим и видимым. Помещайте торнадо-диаграмму в каждое предложение по инструментарию, план мощностей и анализ build-vs-buy. Она превращает споры о том, чьё чутьё правильнее, в соглашения о том, какой параметр стоит пойти и измерить — часто через пилот, ценность которого можно оценить самостоятельно (см. [ожидаемую ценность совершенной информации](../ожидаемая-ценность-совершенной-информации/)).

## Подводные камни

- **Диапазоны, выбранные ради лести**: ±10% вокруг каждого входа независимо от фактической неопределённости. Оценки сэкономленного времени заслуживают ±80%; цены лицензий — ±10%.
- **Изменение по одному параметру упускает взаимодействия** — коррелированные параметры (внедрение и сэкономленное время) нуждаются в двустороннем анализе или полном [вероятностном анализе чувствительности](../вероятностный-анализ-чувствительности/).
- **Проведение анализа и его игнорирование**: если торнадо говорит, что кейс зависит от одной мягкой цифры, следующий шаг — измерение, а не одобрение.
