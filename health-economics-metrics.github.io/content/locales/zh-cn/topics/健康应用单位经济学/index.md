# 健康应用单位经济学 (Health App Unit Economics)

消费级健康产品的商业算术：获客成本（CAC）、客户终身价值（LTV）、每用户平均收入（ARPU）、按人头月费（PMPM）定价，以及雇主市场中 **ROI 与 VOI**（投资价值，value on investment）之间的区别。

## 为什么重要

健康应用面临一种结构性挤压：获客成本高昂（受监管的宣称、信任门槛、合规成本），而留存率却是所有软件垂直领域中最差的（30天内约90%的用户会流失——参见[留存与流失](../留存与流失/)）。因此，标准的可行性检验——**LTV:CAC ≥ 3:1**——在消费级健康领域极难达成，这正是该行业转向B2B2C模式的原因：由雇主、保险公司和卫生系统按人头以PMPM方式为人群付费，此时买方不再是那个会流失的个人。

## 计算方法

```
CAC   = 销售与营销支出 / 新增付费客户数
ARPU  = 收入 / 活跃用户数（按周期计）
LTV   = ARPU × 平均生命周期  =  ARPU / 流失率
可行性标准：LTV : CAC ≥ 3，回本周期 ≤ 12–18个月

每位留存用户的有效CAC = CAC / 留存率(t)
  ——在第30天留存率为4%的情况下，每次安装£5 = 每位30天留存用户£125

PMPM收入 = 费率 × 参保成员数 × 月数
  供应商利润率 = PMPM − 每位成员每月服务成本
  ——参与度会反转符号：在B2C订阅模式下，参与度驱动收入；
    而在PMPM模式下，活跃参与的成员比不活跃的成员服务成本更高，
    而按结果付费的合约又会把这一逻辑再次反转回来
```

## 算例

一款B2C睡眠应用：£6.99/月，月流失率18%，综合CAC为£38。

```
LTV = 6.99 / 0.18 ≈ £38.8 → LTV:CAC ≈ 1.0 —— 不可行

转向雇主PMPM模式：£1.20 PMPM × 40,000名参保人 = £48k/月
服务成本：基础设施£0.15 + 支持£0.10 + 内容£0.05
  每位成员约£0.30 → 利润率约75%，销售周期虽长，但流失是
  合约层面的（按年），而非用户层面的（按天）

雇主关注的问题改变了衡量指标：硬性的ROI（理赔减少、缺勤率下降）
对健康促进类产品而言很少能被证实——业内的应对方式是VOI：
生产力、招聘吸引力、参与度——但这种说法只有在被明确标注为VOI、
而非被包装成ROI时才算诚实（参见return-on-investment.md与
social-return-on-investment.md）。
```

## 与软件工程的关联

工程决策决定了这个比率的两端：**服务成本**取决于架构（[云单位经济学](../云单位经济学/)——PMPM利润率的生死取决于每位成员的基础设施成本），而**LTV**则取决于留存工程（每一个流失百分点都对应着明确的收入算术——[留存](../留存与流失/)一文中的QALY数学有其精确的收入镜像）。对于健康类产品而言，单位经济学仪表盘在LTV与CAC之外，还应有第三条线：**每位获客用户的健康价值**（按留存加权的QALY × 阈值）——因为支付方和DiGA式市场正越来越多地按此定价，而且一款商业单位经济学与临床单位经济学相互背离的产品（盈利但对健康无益，或有效但无法获得资助）需要知道自己面对的究竟是哪一种问题。

## 常见陷阱

- **用早期队列的流失率推算LTV**：流失率会逐步下降；但也存在幸存者偏差——早期采用者的留存往往优于规模化后的受众。应使用队列已成熟的数据。
- **跨渠道混合计算CAC**：付费社交渠道的CAC与临床医生转介渠道的CAC可相差10倍，且留存特征截然相反——应分渠道计算，否则会被误导。
- **PMPM未设使用上限**：极端高参与度的成员可能反转利润率；应对分布建模，而非只看均值。
- **向CFO把VOI包装成ROI**——这正是雇主健康促进行业耗费十年才换来的信誉教训。
