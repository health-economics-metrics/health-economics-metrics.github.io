# 流动指标

流动指标衡量工作在交付系统中流动的方式：周期时间、前置时间、吞吐量、在制品数量（WIP）以及流动效率。它们遵循利特尔法则（Little's Law）——与支配医院床位和等候名单的排队数学完全相同。

## 为何重要

大多数交付时间并非真正的"工作"——而是"等待"。针对知识工作的流动效率研究一贯发现，任务处于实际被处理状态的时间通常仅占其总耗时的**5–15%**；其余时间都花在了排队上。这意味着最廉价的提速手段是清除队列，而非招聘更多人——医院患者流转项目在床位问题上发现的恰恰正是这一洞见。对于任何存在[延迟成本](../延迟成本/)的事物而言，流动指标能定位延迟成本究竟累积在何处。

## 计算方法

```
周期时间   = t(完成时刻) − t(开始时刻)
前置时间   = t(交付时刻) − t(请求时刻)     （包含工作开始前的排队时间）
吞吐量     = 已完成项目数 / 周期
在制品数量 = 已开始但尚未完成的项目数
流动效率   = 实际处理时间 / (实际处理时间 + 等待时间) × 100

利特尔法则：  平均在制品数量 = 吞吐量 × 平均周期时间
             （等价地：周期时间 = 在制品数量 / 吞吐量）
```

利特尔法则正是杠杆所在：在吞吐量固定的情况下，削减在制品数量会按比例缩短周期时间。它同样支配着医院的运转：`占用床位数 = 每日入院数 × 住院时长`。

## 实例演算

某团队手头有40个在制品任务，每周完成10个：周期时间 = 40/10 = 4周。他们设定了在制品数量上限，将在制品削减到15个：周期时间 = 15/10 = **1.5周**——同样的人员，同样的吞吐量，交付速度提升62%，全部仅仅来自队列纪律的改变。

以延迟成本定价：假设每个任务平均每周的延迟成本为£3,000，如今每个任务在队列中少滞留2.5周：每周10个任务 × 2.5 × 3,000 = **每周消除£75,000的延迟成本**——而这项政策改变本身没有任何成本。

医院版本的镜像：每日40例入院 × 住院时长6.0天 = 240张床位；若将住院时长内的非临床等待时间削减至5.6天，则可释放16张床位（参见[住院时长](../住院时长/)）——同一条法则，同一个杠杆。

## 与软件工程的联系

流动指标是交付工程与医疗运营之间的共同语言：

- **PR子阶段基准数据**（LinearB，约800万条PR数据）：卓越水平的接手时间 < 7小时，评审时间 < 6小时，总周期 < 约26小时——接手时间纯粹就是排队等待，是最先应该着手解决的问题。
- **[等候名单](../等候名单影响/)**就是积压任务；**[转诊至治疗（RTT）](../转诊至治疗/)**就是前置时间；**[床位占用](../节省的床位天数/)**就是在制品数量。改进手段在两个方向上都可以相互迁移：在制品数量上限 ↔ 入院平滑处理；排队时间埋点 ↔ 路径阶段追踪。
- 流动效率低于15%在这两个领域都属于常态，且二者都容易将其隐藏起来，因为*人*总是忙碌的，而*工作*却在等待——应测量"工作"的时钟，而非"工作者"的时钟。

## 陷阱

- **崇拜利用率**：将工作者利用率推向100%会使队列时间呈非线性爆炸式增长（M/M/1模型：等待时间 ∝ ρ/(1−ρ)）——这正是占用率95%的医院陷入停滞、以及分配率95%的团队陷入停滞的原因所在。
- **对偏斜分布取平均值**：周期时间往往呈重尾分布；应以百分位数（如p85）预测，而非均值。
- **通过在上游拒绝工作来削减在制品数量，却将其称为流动改进**——需求并未消失，它只是排到了测量边界之外去了（医院版本的对应情形：救护车在急诊科外排队等候）。
