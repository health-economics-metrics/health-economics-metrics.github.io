# 評価期間

評価期間とは、分析が費用と効果を数える期間のことです。比較対象となる選択肢間の意味あるすべての違いを捉えられるだけの長さが必要です。

## なぜ重要か

短い期間を選ぶと、遅れて現れる便益(予防)や遅れて現れる費用(保守)を見逃します。長すぎる期間を選ぶと、すべてが不確実性に埋もれてしまいます。医療技術評価では、死亡率に影響する治療について**生涯**にわたる期間がよく使われます。[予算影響分析](../予算影響分析/)は、その問いが価値ではなく支払い可能性であるため、意図的に**1〜5年**という短い期間を使います。評価期間は明示的なモデリング上の選択であり、期間の不一致は比較を操作する典型的な手口です。

## 数式

評価期間は、あらゆる評価における合計の上限です:

```
正味現在価値 = Σ (t = 0 … T) [ (便益_t − 費用_t) / (1 + r)^t ]

T = 評価期間(年)
r = 割引率(discounting-and-time-preference.mdを参照)
```

結果は評価期間を明記して報告すべきであり、理想的には複数の期間で示すべきです。

## 計算例

ある電子処方システムは、導入に£200万、運用に年間£200,000かかります。年間£600,000相当の投薬ミス(回避された害の治療コスト)を防ぎます。

期間ごとの正味便益(わかりやすさのため割引前):

```
期間1年:  −2,000,000 − 200,000 + 600,000  = −£1,600,000
期間3年: −2,000,000 + 3 × 400,000        = −£800,000
期間5年: −2,000,000 + 5 × 400,000        =  £0
期間10年:−2,000,000 + 10 × 400,000       = +£2,000,000
```

このシステムは、5年未満のどの期間で見ても「失敗」し、10年では「成功」します。どちらも真の答えではありません。誠実な報告とは、損益分岐点を示し、システムの寿命(交換までどれくらいか)によって評価期間を正当化することです。

## ソフトウェア工学との関連

- **1スプリントで測定されたツール評価**は、学習曲線の落ち込み(前倒しの費用)と長期的な保守(後倒しの費用)を系統的に見逃します。2週目に測定されたAIコーディングアシスタントのパイロットは、定常状態ではなく新奇性のピークを捉えているにすぎません。
- **契約期間 ≠ 便益の評価期間。** 現実的に更新が見込まれるなら、1年間のSaaS契約でも5年間で評価してかまいません — ただし、それを明示してください。
- **レガシー置き換えのケース**は、任意の切りの良い数字ではなく、旧システムの信頼できる寿命終了時点まで見積もるべきです。

## 落とし穴

- **期間のショッピング**:自分の選択肢が勝つ評価期間を選ぶこと。結果を計算する前に評価期間を事前登録してください。
- **同じ比較の中で、選択肢ごとに異なる評価期間**を使うこと。
- **割引や不確実性分析のない生涯期間** — 30年目の便益を額面通りに受け取るのはフィクションです。長い評価期間には[感度分析](../感度分析/)を組み合わせてください。
