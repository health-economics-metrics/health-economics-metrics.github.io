# 转诊至治疗 (Referral to Treatment, RTT)

转诊至治疗是指从全科医生转诊到专科顾问主导治疗开始之间所经过的时间。《NHS 宪章》设定了标准：**92% 的患者应在 18 周内开始治疗**。RTT 是英格兰 NHS 中政治上最受关注的单一运营指标。

## 为什么重要

未能达到 RTT 目标的信托机构（trust）会面临监管审查、干预和声誉损害；全国候诊名单是会登上头版的数字。患者每多等一周，就意味着健康的损失（在更差的健康状态下等待——参见下文的 QALY 计算），往往也意味着成本的增加（病情会恶化；参见[更早介入](../更早干预/)）。任何能在转诊至治疗路径的任一环节节省时间的软件——分诊、诊断周转、门诊产能、排程——都能直接缓解未达标带来的运营和财务后果，这正是为什么 RTT 影响在 NHS 数字化商业论证中是一等重要的收益条目。

## 计算方法

```
RTT 表现 = 18 周内接受治疗的患者数 / 治疗总人数 × 100
每位患者的等待健康成本 = 等待时长 × （治疗后效用值 − 等待期效用值）

路径视角：RTT = Σ 各阶段耗时（转诊分诊 → 首次门诊 →
诊断检查 → 决策 → 治疗）——应改善最长的排队环节，
而非最繁忙的阶段（参见 flow-metrics.md）。
```

## 实例计算

某专科每年治疗 5,000 名路径患者；平均等待 24 周；等待期效用值 0.68，治疗后 0.80。

数字分诊加上直接检查（straight-to-test）流程，消除了 5 周的纯排队等待时间：

```
获得的 QALY = 5,000 × (5/52) × (0.80 − 0.68) = 每年 57.7 QALY
按每 QALY £20,000-£30,000 货币化（参见 willingness-to-pay-thresholds.md）：
  ≈ 每年 £115 万-£173 万的健康价值
```

——此外，该信托机构也从未达标转变为达到 18 周标准，这带来的治理价值是任何电子表格都无法完全体现的。

## 与软件工程的关联

RTT 是一项**跨越多阶段队列的交付周期（lead time）指标**——相当于医院版本的从提交到生产环境的交付周期（参见 [DORA 指标](../dora-指标/)）。改进方法完全相同：对每个阶段进行埋点测量，找出日历时间积压在哪里（几乎总是在交接和排队环节，而非临床工作本身），并消除等待状态。典型的软件改进举措包括：以小时而非以周为批次路由转诊的电子分诊、以推送方式发送诊断结果而非安排随访预约、以及自动化的直接检查判定标准。用以 QALY/周计价的[延迟成本](../延迟成本/)来为这项改进定价。

## 常见陷阱

- **改进了并非瓶颈的阶段**——在诊断队列不断增长的同时缩短首次门诊等待时间，只是把积压转移了位置。
- **数据博弈**：路径重置和时钟暂停可以在不让任何人更早获得治疗的情况下改善上报的 RTT 数字；应审查其背后的真实分布。
- **将整条路径的改进归功于单一工具**，而实际上是多项变更同时落地——归因需要一个对照组。
