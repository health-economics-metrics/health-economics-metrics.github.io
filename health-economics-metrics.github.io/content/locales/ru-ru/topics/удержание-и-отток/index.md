# Удержание и отток (Retention and Churn)

Удержание измеряет, какая доля когорты пользователей всё ещё активна через N дней после начала (кривые D1/D7/D30); отток — её дополнение. Жестокая базовая линия цифрового здравоохранения: **примерно 90% пользователей медицинских приложений отказываются от использования в течение 30 дней** — удержание D30 в цифровом здравоохранении составляет ~3–4% против среднего по всем приложениям ~6%.

## Почему это важно

Айзенбах назвал это в 2005 году: **закон истощения (law of attrition)** — потеря пользователей высокими темпами — это внутреннее, структурное свойство eHealth-вмешательств, а не баг реализации, причём истощение в испытаниях eHealth регулярно превышает 50%. Экономическое последствие тотально: удержание определяет *терапевтическое окно*, в пределах которого может быть доставлена любая выгода, а [юнит-экономика](../юнит-экономика-медицинского-приложения/) — CAC, заплаченный за пользователя, который остаётся на 12 дней, не даёт ни LTV, ни QALY. Любая экономическая модель для потребительского медицинского продукта, не взвешивающая выгоды по кривой удержания, описывает продукт, которого не существует.

## Математика

```
Удержание_Dn = активные пользователи на день n / размер когорты × 100
Отток        = потерянные пользователи за период / пользователи на начало периода × 100

Взвешивание выгоды (ход экономики здравоохранения):
  ожидаемая выгода на привлечённого пользователя = Σ_t удержание(t) × ставка_выгоды(t)
  ≈ площадь под кривой удержания × выгода за единицу времени
  — А НЕ выгода из испытания × 100% привлечённых пользователей

Стоимость на удержанного-к-D30 пользователя = CAC / удержание D30
  (при 4% D30 CAC в £5 на самом деле составляет £125 на удержанного пользователя)
```

## Практический пример

Приложение психического здоровья: испытание показало 0,02 QALY, приобретённых на пользователя, завершившего 8 недель. Когорта развёртывания из 100 000 загрузок, удержание D7 25%, D30 8%, 8-я неделя 4%:

```
Завершившие           = 100,000 × 0.04 = 4,000
Доставлено QALY       = 4,000 × 0.02 = 80  (а не 100,000 × 0.02 = 2,000)
При £20,000/QALY      = £1.6M ценности для здоровья (а не £40M)

Ценность для здоровья на загрузку = £16 — цифра, которая должна задавать, сколько
плательщик заплатит за загрузку, и это 4% от наивного заявления.
Кейс улучшения удержания: перемещение завершения на 8-й неделе с 4% → 6% добавляет
40 QALY/год ≈ £800k — инженерия удержания ЕСТЬ производство здоровья.
```

## Связь с разработкой программного обеспечения

Удержание — это метрика, в которой продуктовая инженерия наиболее напрямую производит ценность здоровья, согласно арифметике выше. Практики, двигающие её, обычны: время до первой ценности при онбординге, дизайн повторного вовлечения, производительность и, критически, **запланированное завершение дозы** — программа с определённым концом (8 недель, затем «выпуск») должна измерять *завершение*, а не вечный DAU, согласуя метрику с клинической моделью вместо модели внимания, финансируемой рекламой. Анализ выживаемости — правильный инструментарий (та же математика Каплана-Мейера, что и [приобретённые годы жизни](../приобретённые-годы-жизни/)); сегментируйте кривые по каналу привлечения, поскольку микс каналов меняет удержание сильнее, чем большинство функций.

## Подводные камни

- **Отмывание анализа intention-to-treat в обратную сторону**: испытания отчитываются по завершившим; экономика развёртывания должна считать всех привлечённых (основное предупреждение Айзенбаха).
- **Театр удержания**: «активные» пользователи, движимые уведомлениями, которые никогда не выполняют терапевтическое действие (см. [метрики вовлечённости](../метрики-вовлечённости/)).
- **Сравнение кривых при разных определениях**: «активный», определённый как открытие приложения против значимого действия, сдвигает D30 в разы.
- **Игнорирование того, кто уходит**: если самые больные уходят быстрее всех, выгода на пользователя падает по мере улучшения удержания среди здоровых — сопоставляйте кривые с миксом случаев (см. [охват и равенство](../охват-и-равенство/)).
