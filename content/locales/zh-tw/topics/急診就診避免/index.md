# 急診就診避免

急診就診避免衡量的是因上游介入（分診應用、遠端監測、虛擬病房、緊急護理分流）而被避免的急診科就診與緊急入院。它將"我們更早發現了問題"這句話，轉化為一個可核算成本的主張。

## 為何重要

急診是整個系統中最昂貴的常規醫療場所（按"全國成本採集"/PSSRU資料，一次急診就診的單位成本在£250–£400區間；一次緊急入院則達數千英鎊），而急診擁擠會連鎖引發救護車延誤與擇期手術取消。任何能在上游安全化解需求的手段——自我照護建議、當日基層醫療、社群回應——都能在系統壓力最大的那個環節買到寶貴的產能。這也是症狀自查工具、111式分診服務，以及[遠端病患監測](../遠端病患監測經濟學/)最常見的標準效益線。

## 計算方法

```
避免的就診次數 = 人群規模 × (基線發生率 − 介入後發生率)
毛節省額       = 避免的就診次數 × 每次就診單位成本
                （+ 避免的入院次數 × 入院成本，需單獨計算）

淨節省額       = 毛節省額 − 介入成本 − 新增路徑使用成本
                （被分流的需求並非零成本：一次111熱線通話、
                 一個全科醫師診位、一天虛擬病房，都各自有其單位成本）
```

這一因果主張需要一個對照組：急診就診率本身存在趨勢變化與季節性波動，單純的前後對比無法證明任何東西。

## 實例演算

某針對3,000名高風險病患的慢阻肺（COPD）遠端監測服務。經匹配對照評估顯示，因病情加重導致的急診就診率從每病患-年0.9次降至0.7次，緊急入院率從0.5降至0.42。

```
避免的就診 = 3,000 × 0.2  = 600次 × £300   = £180,000
避免的入院 = 3,000 × 0.08 = 240次 × £3,800 = £912,000
毛節省額合計                                 每年£1,092,000

成本：監測服務£600,000；額外的社群護士回應£150,000
淨節省額 ≈ 每年+£342,000——此外還有病情加重被更早治療所帶來的QALY獲益。
```

請注意，起主導作用的是"入院避免"這一項：僅憑避免就診，往往不足以支付一項監測服務的成本；真正的價值所在，是*避免入院*。

## 與軟體工程的聯絡

這正是**事件避免經濟學**。可觀測性、金絲雀釋出與早期預警系統的價值，就是被避免的"急診就診"——尋呼告警、作戰室、一級嚴重事件（sev-1），每一次都有其負荷成本（工程師工時 × 費率 + 客戶影響）。相同的建模規則同樣適用：需扣除新增上游路徑本身的成本（警報分診本身並非零成本）；需警惕替代效應（只製造工作量、卻並未真正預防事件的警報，是"健康焦慮"，而非真正的健康）；並需以對照組來證明反事實假設（團隊的事件發生率本身也會隨時間變化並回歸均值，正如急診就診率一樣）。

## 陷阱

- **均值迴歸**：因某個糟糕年份而被選中的高風險佇列，即便不加介入也會自行好轉；匹配對照或階梯式楔形設計是必不可少的。
- **供給誘導需求**：便捷的數位化分診可能*增加*總接觸量（因為尋求幫助的門檻降低了），同時卻降低了急診科所佔的份額——應核算整個系統的總成本。
- **按平均成本為就診估值**，而急診的固定成本實際上並不會因此下降——參見[邊際成本與平均成本](../邊際成本與平均成本/)。
