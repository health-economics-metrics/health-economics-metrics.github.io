# 시간교환(TTO) 효용 도출

TTO는 건강 상태의 효용값을 만들어 내는 대신 응답자로부터 직접 도출하는 표준 방법입니다. 스탠더드 갬블, 이산선택실험과 함께 [EQ-5D](../eq-5d/) 같은 도구 뒤에 있는 가치 집합을 만들어 내는 도출 방법 중 하나이며, 따라서 대부분의 하류 [QALY](../질보정-생존연수/) 계산의 배후에 있습니다.

## 왜 중요한가

QALY 계산에 들어가는 모든 효용 가중치는 어딘가에서 와야 했습니다. TTO가 그 방법입니다. 죽음보다 낫다고 여겨지는 상태에 대해, 응답자는 장애 상태에서의 `T`년과 동등하다고 여기는 완전한 건강 상태에서의 연수 `X`(`X < T`)를 질문받으며, 효용은 `X / T`입니다. 일부 응답자가 죽음보다 나쁘다고 여기는 상태에서는 표준 공식이 깨지므로(0 미만의 효용을 깔끔하게 표현할 수 없음), 대신 확장 TTO를 적용합니다. 효용 가중치를 그것을 만들어 내는 데 검증된 도출 프로토콜이 필요했다는 것을 모른 채 주어진 입력으로 취급하는 소프트웨어 엔지니어나 분석가는, 이의가 제기될 때 방어할 수 없는 숫자에서 한 걸음 떨어져 있을 뿐입니다.

## 수식

```
표준 TTO(죽음보다 나은 상태):
  효용 = 완전한 건강에서의_시간 / 장애_상태에서의_시간

확장 TTO(죽음보다 나쁜 상태):
  효용 = −죽음과_맞바꾼_시간 / (총_기간 − 죽음과_맞바꾼_시간)
```

`완전한 건강에서의_시간` / `장애_상태에서의_시간` — 장애 상태에서의 `T`년과 동등하다고 판단되는 완전한 건강에서의 연수 `X`. `죽음과_맞바꾼_시간` / `총_기간` — 죽음보다 나쁜 상태의 정식화에서, `T`년의 남은 수명 중 응답자가 즉각적인 죽음과 맞바꿀 연수 `a`로, 응답자는 죽음보다 나쁜 상태에서 `T`년을 보내기보다 완전한 건강에서 `T − a`년을 보낸 뒤 죽는 쪽을 선호합니다. 결과는 음수이며, 죽음 = 0이 되도록 고정되어 있습니다.

## 계산 예시

**표준**: 응답자가 장애 상태로 10년을 지내며, 완전한 건강에서의 7년과 무차별합니다. 효용 = 7 / 10 = **0.7**.

**죽음보다 나쁜 상태**: 남은 수명 10년 중 응답자는 즉각적인 죽음과 2년을 맞바꿉니다. 죽음보다 나쁜 상태에서의 10년보다 완전한 건강에서의 8년과 뒤이은 죽음을 선호합니다. 효용 = −2 / (10 − 2) = −2 / 8 = **−0.25**.

## 소프트웨어 공학과의 연관성

DevEx나 참여도 설문이 검토되지 않은 0–10 척도로 무언가를 평가하라고 요청할 때 맞닥뜨리는 것과 같은 문제가 여기서는 반대로 적용됩니다. TTO는 "그냥 사람들에게 평가해 달라고 하면 된다"가 그것만으로는 검증된 도출 방법이 아니기 때문에 존재합니다. 자가 평가한 숫자 위에 종합 지수(DevEx 점수, 참여도 지수, 번아웃 척도)를 쌓기 전에, 무엇이 그것을 도출했는지, 그 방법이 검증되었는지 물어보세요. 보건경제학자들이 효용 가중치가 QALY에 들어가기 전에 던지는 것과 같은 질문입니다.

## 함정

- **개인 값의 일반화**: TTO 값은 치료가 결정되는 개인이 아니라 일반 대중(또는 환자)의 *표본*에서 도출됩니다. 한 응답자의 TTO 값을 마치 일반화되는 것처럼 쓰는 것은 표집 오류입니다.
- **상태에 맞지 않는 정식화**: 표준 TTO 공식은 상태가 죽음보다 분명히 낫다고 가정합니다. 일부 응답자가 죽음보다 나쁘다고 여길 상태에 확장 정식화로 바꾸지 않고 적용하면, 조용히 잘못된(양의) 효용이 나옵니다.
- **비교할 수 없는 기간**: 죽음보다 나쁜 상태의 비교에 서로 다른 남은 수명 `T`를 사용해 도출한 TTO 값은, 연구 설계가 `T`를 일정하게 유지했는지 확인하지 않고는 직접 비교할 수 없습니다.
