# 机会成本 (Opportunity Cost)

机会成本是指当你把一项资源投入某处时，所放弃的最佳替代用途的价值。在一个预算固定的卫生系统中，把 £1 百万花在一件事上，就意味着有 £1 百万的健康*没有*在其他地方产生。

## 为什么重要

机会成本是卫生经济学中最深刻的理念，也是软件工程师最常忽略的一个。卫生预算在任何给定年份都是固定的，因此一项新技术从来不是用"多出来的"钱来资助的——它挤出的是其他东西。付费方真正问的问题不是"这个东西好不好？"，而是"它是否比同样这笔钱目前所购买的东西更好？"

这正是成本效益阈值之所以存在的原因：该阈值本质上是对"这笔钱在当前系统的边际上能买到多少健康"的一种估计。参见[支付意愿阈值](../支付意愿阈值/)。

## 计算方法

这里没有单一公式；机会成本是一种比较纪律：

```
选择 A 的机会成本 = 被放弃的最佳替代方案 B 的价值
A 的净收益 = 价值(A) − 价值(B)
```

实证基准：Claxton 等（2015 年）估计，NHS 在边际上大约花费 **£13,000** 就能产生一个 QALY。因此，把 £13,000 花在一项产生不到一个 QALY 的技术上，即便这项技术本身"有效"，也会让整个国家变得*更不*健康。

## 算例

某 NHS 信托机构的转型预算恰好只能资助以下两项之一：

- **方案 A**：电子排班软件——每年节省 £400,000 的中介用工支出。
- **方案 B**：出院协调软件——每年节省 2,000 个床位日。按每个实际腾出的床位日边际成本约 £150 计算，即每年 £300,000，此外还为候诊患者带来更早的治疗。

资助 A 就意味着放弃 B。A 的机会成本就是 B 的 £300,000 加上患者获益；A 真正的*净*论证只是这个差额，而不是 A 表面上宣称的 £400,000。任何把一项提案与"什么都不做"而非最佳替代方案相比较的商业论证，都高估了自身的价值。

## 与软件工程的关联

工程产能同样是一笔固定预算——只是单位是路线图名额，而不是英镑。一个平台团队如果去资助能以每小时 £500 节省工程师工时的工具 A，而工具 B 能以每小时 £200 达到同样效果，那就是在摧毁产能——正如一个卫生系统资助一种每 QALY £40,000 的药物，会挤出每 QALY £13,000 的照护一样。这套纪律可以直接迁移：

- 始终明确点出比较对象（"与什么相比？"）。
- 按工程师时间原本能产出什么来为其估值，而不仅仅按薪资估值。
- 把"我们还有预算"当作分析的起点，而不是终点。

## 陷阱

- **与"什么都不做"相比较。** 正确的比较对象是这笔钱的次优用途，而这几乎从来都不是"什么都不做"。
- **假设节省的时间机会成本为零。** 节省的时间只有在被重新投入有价值的事情上时才有价值——参见[现金释放型 vs 非现金释放型节约](../现金释放型-vs-非现金释放型节约/)。
- **忽视挤出效应。** "预算会自动扩大来容纳它"这种说法，在一个国家卫生服务体系的当年度预算中几乎从不成立。
- **忽视由哪种方法为被挤出的资源估值。** 尤其是对因疾病、残疾或员工离职而损失的生产率——见[人力资本法与摩擦成本法](../人力资本法与摩擦成本法/)，这是该思想在生产率成本上的专门版本。
