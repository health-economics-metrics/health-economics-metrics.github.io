# 延迟成本 (Cost of Delay，CoD)

延迟成本是指某项功能、产品或服务*未能*交付的每单位时间内所损失的经济价值。它是软件交付指标与卫生经济学之间最强有力的一座桥梁：它把"我们交付晚了"转化为货币——或转化为 QALY。

## 为什么重要

Reinertsen 的法则："如果你只量化一件事，那就量化延迟成本。"大多数组织知道一个项目要花多少钱，却不知道延误一个月要花多少钱，于是它们在优化预算的同时,却在大量流失时间价值。对医疗软件而言，代价是字面意义上的：一条路径改进每延迟一周，患者就要在更差的健康状态下多等一周。CoD 是向 NHS 利益相关方展示的最有力的数学框架，因为它为你软件的*缺席*本身定了价。

## 计算方法

```
CoD = 未交付期间每单位时间放弃的效益   (£/周 或 QALY/周)

总延迟损失 = CoD × 延迟时长

关于优先级排序，参见 wsjf-and-cd3.md：CD3 = CoD / 时长。
```

对临床软件而言，应同时以健康和货币计量：

```
CoD_健康 = 每周受影响的患者数 × 每位患者的 QALY 获益
CoD_货币 = CoD_健康 × λ (支付意愿阈值，£20k–30k/QALY)
          + 每周放弃的运营节约
```

## 算例

**运营层面**：某软件在一条路径上为每位患者节省 £200；一家信托机构每周处理 50 名此类患者。

```
CoD = 200 × 50 = £10,000/周
一次 10 周的采购延迟将造成 200 × 50 × 10 = £100,000 的可避免浪费。
```

**临床层面**：一项分诊改进为每周 100 名患者减少了 5 周等待（效用值 0.68 → 更早达到 0.80）：

```
每位患者的 QALY 获益 = (5/52) × 0.12 ≈ 0.0115
CoD_健康 = 100 × 0.0115 = 1.15 QALY/周
CoD_货币 = 1.15 × £20,000 ≈ £23,000/周的健康价值
```

6 个月的部署延迟"耗费"约 30 个 QALY——这一论证把一次 IT 上线延误重新定义为一起临床事件。（作为规模参照：Black Swan Farming 著名的马士基 (Maersk) 分析发现，单个功能的 CoD 可达约 $200k/周，且已等待了 38 周。）

## 与软件工程的关联

CoD 是让 [DORA 交付前置时间](../dora-指标/)和[流程效率](../流程指标/)变得财务可读的指标：前置时间 × CoD = 在队列中被消耗掉的金钱（或健康价值）。用途包括：

- **优先级排序**：按 CoD/时长（[WSJF/CD3](../wsjf-与-cd3/)）而非"谁嗓门最大"来排序工作。
- **流程经济学**：相较于持续交付，一个 2 周的发布节奏，每个功能的预期延迟成本约为 1 周 × CoD——为批量交付定价。
- **采购**：NHS 6–18 个月的采购周期本身就有 CoD；把它展示出来会改变关于紧迫性的对话（可负担性方面的对应内容参见[预算影响分析](../预算影响分析/)）。

## 陷阱

- **假定 CoD 是线性的**：有些工作的价值呈"截止日期"形态（监管日期——过期后 CoD 无穷大，之前为零），或呈衰减形态（先发窗口期）。在相乘之前先对紧迫性画像进行分类。
- **对没人想要的产出计算 CoD**：只有当东西本身有价值时，延迟才有代价；延迟交付垃圾是免费的。
- **重复计算延迟成本与贴现**：[贴现](../贴现与时间偏好/)已经为跨多年周期的时间定了价；CoD 是周期*内*的运营版本。周/月尺度用 CoD，年尺度用 NPV 的变化。
