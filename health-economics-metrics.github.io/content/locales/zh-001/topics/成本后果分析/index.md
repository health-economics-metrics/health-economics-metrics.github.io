# 成本后果分析（CCA）

成本后果分析将成本与一份**未经聚合的全结果分解表**并列呈现——临床、运营、体验各方面的结果都独立列出，而不将其压缩为单一比值或分数。决策者需明确地对各项权衡取舍进行判断。

## 为何重要

在NICE的证据标准框架下，成本后果分析是**大多数数字健康技术的首选经济学呈现格式**。数字化产品往往产生多种异质性效果（节省时间、满意度、爽约率下降、微小的临床获益），这些效果很难诚实地聚合为单一的QALY数字。成本后果分析不强行构造一个脆弱的复合指标，而是展示完整的账目清单。对于大多数软件商业论证而言，这既是最诚实的呈现格式，也是最具说服力的格式，因为每一位利益相关方都能在其中找到与自己决策相关的那一行。

## 计算方法

这里刻意不设聚合公式。输出结果是一张表：

```
                          干预方案      对照方案     差值
成本（年度）               £X            £Y          ΔC
结果1（自然单位）           …             …           Δ1
结果2                      …             …           Δ2
定性结果                    以文字描述，不打分
```

每一行都保留其自身的计量单位。规则如下：所有结果指标须事先设定（不得在结果出来后再挑拣有利数据）；应全程保持相同的[视角](../分析视角/)与[时间范围](../时间范围/)；每一行都需报告其不确定性。

## 实例演算

某信托机构的数字化术前评估平台，对比电话评估流程，按年度计算：

```
                              数字化平台    电话流程     差值
运营成本                       £180,000      £95,000      +£85,000
护士评估工时                   6,200         11,800       −5,600小时
当日手术取消例数                92            174          −82
患者满意度（CSAT）              4.5/5         3.9/5        +0.6
评估遗漏/未完成率                1.2%          4.8%         −3.6个百分点
```

没有单一分数——但这份数据足以让决策变得清晰易懂：£85,000换来了5,600护士工时（约合£15/小时，远低于任何用人成本）、82例被避免的手术取消（每例都会浪费一个价值约£1,200的手术室时段），以及更好的患者体验。委员会同样能清楚看到这份方案*没有*提供的东西：没有主张任何QALY或死亡率方面的效果。

## 与软件工程的联系

成本后果分析正是一份优秀平台提案早已在使用的"平衡计分卡"的正式版本：成本与DORA指标、DevEx开发者体验分数、事件数量并列呈现——不作聚合。值得补充的健康经济学纪律是：**事先设定好所有行项目**（在试点开始前就决定哪些指标算数，这样你就无法在某项指标变差后悄悄将其剔除），以及**展示不利的行项目**——一份只有好消息的成本后果分析报告，不过是营销材料。当不存在站得住脚的复合指标时（对开发者工具而言，这几乎总是如此），就应使用成本后果分析。

## 陷阱

- **挑拣有利结果**——这一格式的公信力完全依赖于事先设定。
- **偷偷夹带聚合**：颜色编码或"总体评分"会重新引入成本后果分析原本旨在避免的那种武断权重。
- **决策瘫痪**：成本后果分析需要一位愿意权衡取舍的决策者；应搭配一条明确的建议及其推理过程。
