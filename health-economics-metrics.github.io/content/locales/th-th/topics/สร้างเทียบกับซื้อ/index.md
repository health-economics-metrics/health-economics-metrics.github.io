# สร้างเทียบกับซื้อ

การวิเคราะห์สร้างเทียบกับซื้อเปรียบเทียบต้นทุนและความเสี่ยงของการซื้อโซลูชันที่มีอยู่แล้วกับการสร้างโซลูชันที่ปรับแต่งเองภายในองค์กร

## ทำไมจึงสำคัญ

นี่เป็นหนึ่งในการตัดสินใจด้านเทคโนโลยีที่พบบ่อยที่สุดและมีความเสี่ยงสูงที่สุดที่องค์กรต้องทำ ซึ่งส่งผลต่อต้นทุน ความเร็วในการเข้าสู่ตลาด และความยืดหยุ่นในระยะยาว

## คณิตศาสตร์

```
เกณฑ์การตัดสินใจ: TCO ของการสร้าง + มูลค่าเชิงกลยุทธ์ เทียบกับ TCO ของการซื้อ + ความเสี่ยงจากการพึ่งพา
```

## ตัวอย่างที่คำนวณแล้ว

การสร้างระบบจัดการผู้ป่วยที่ปรับแต่งเองมีค่าใช้จ่าย £2 ล้านและใช้เวลา 18 เดือน ในขณะที่การซื้อโซลูชันที่มีอยู่มีค่าใช้จ่าย £200,000/ปี แต่จำกัดการปรับแต่ง — การตัดสินใจขึ้นอยู่กับว่าการปรับแต่งมีความสำคัญเชิงกลยุทธ์หรือไม่

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

นี่คือกรอบการตัดสินใจของการพัฒนาซอฟต์แวร์เอง ซึ่งเชื่อมโยงอย่างใกล้ชิดกับ [ต้นทุนรวมของการเป็นเจ้าของ](../ต้นทุนรวมของการเป็นเจ้าของ/)

## ข้อผิดพลาดที่พบบ่อย

- **การประเมินต้นทุนการสร้างต่ำเกินไป โดยไม่คำนึงถึงการบำรุงรักษาอย่างต่อเนื่อง**
- **การเพิกเฉยต่อความเสี่ยงของการล็อกอินกับผู้ขายและการเปลี่ยนแปลงราคาในอนาคตของโซลูชันที่ซื้อ**
