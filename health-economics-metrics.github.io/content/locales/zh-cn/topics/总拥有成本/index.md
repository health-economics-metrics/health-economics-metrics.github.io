# 总拥有成本 (Total Cost of Ownership，TCO)

TCO 是一个系统在其整个生命周期内的全部成本：采购或建设、集成、运营、维护、支持、培训以及退役。一个令人不安的基线事实：**维护占软件 TCO 的 50–80%**——大约四分之三的全生命周期成本发生在*上线之后*。

## 为什么重要

卫生技术评估很早就认识到，一种药物的价格并不等于它的成本——给药、监测以及副作用管理都必须纳入模型。只计入建设/许可成本的软件商业论证,重蹈了"药价即成本"这一幼稚错误的覆辙，并会系统性地低估它所支撑的每一个 [ICER](../增量成本效果比/) 和[预算影响](../预算影响分析/)模型中的成本一侧。对 NHS 采购而言，TCO 纪律正是让一项数字化产品的成本效益主张站得住脚的关键——也正是那些看起来便宜的方案会在这里露出马脚的地方。

## 计算方法

```
TCO = 初始成本（建设/许可 + 集成 + 数据迁移 + 培训）
    + Σ_t [运营 + 维护 + 支持 + 基础设施 + 升级
           + 合规/保障]_t / (1 + r)^t
    + 退役成本（退出、数据提取、并行运行）

周期：商业系统 3–5 年，临床基础设施按系统生命周期
r：公共部门 3.5%（绿皮书），商业 8–12%
基准：年度维护约为建设成本的 15–20%；约 78% 的全生命周期
TCO 发生在上线之后；忽略退役成本和供应商锁定本身就是一种定价失误。
```

## 算例

某电子观察记录系统的两种方案，5 年周期：

```
                        供应商 SaaS      自建
第 0 年（许可/建设）      £250,000        £900,000
集成 + 培训              £180,000        £150,000
年度运行（第 1–5 年）     £120,000/年     £190,000/年（托管 + 1.5 名全职维护人员）
退出/退役                £60,000         £30,000

未贴现 TCO               £1,090,000      £2,030,000
```

自建方案的工程估算（£900k）仅占其真实 TCO 的 44%——而自建估算本身通常还会超支 30–40%（参见[自建还是购买](../自建与外购/)）。除非自建方案能带来实质不同的*结果*，否则[成本最小化](../成本最小化分析/)的逻辑就适用，SaaS 方案将以约 £940k 之差胜出。

## 与软件工程的关联

在为自建方案辩护时，工程师往往低估了自己领域内已有的维护数据："维护成本约为建设成本 15–20%"这条经验法则意味着，每一个 £1M 的系统都在悄悄承诺未来每年 £150–200k 的产能——这项负债理应与[技术债](../技术债/)记在同一张心理资产负债表上。TCO 同时也是本仓库中每一个指标的成本那一半：每次部署的成本、[云单位经济学](../云单位经济学/)，以及 HTA 强加给药品申办方的那种分母纪律。当你产品的价格受到质疑时，一份包含现有方案真实运行成本在内的 TCO 比较，通常是能够拿出的最有力的重新框定论据。 像上面这样的多年期 TCO 数字，是随时间推移的大量成本条目之和——关于一旦模型必须对到分，这个总和为什么应当是精确十进制而不是浮点数，见[币种安全的成本汇总](../币种安全的成本汇总/)；关于把 TCO 总额分摊到各成本中心而不损失分币，见[精确到分的成本分摊](../精确到分的成本分摊/)。

## 陷阱

- **锚定于上线成本**：在第 0 年成本上比较方案，而排名到第 3 年就已反转。
- **内部人力"免费"的谬误**：因为"团队反正已经付过薪水了"，就把自建维护成本记为零——参见[机会成本](../机会成本/)。
- **忽略退出成本**：数据出口、合同终止和并行运行，正是"便宜"的 SaaS 变得昂贵的地方。
- **周期不一致**：把一个 3 年期的 SaaS TCO 与一个按 10 年摊销的自建方案相比较（参见[时间周期](../时间周期/)）。
