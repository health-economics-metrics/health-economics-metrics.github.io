# 爽约率（DNA率）

爽约率是指已预约的诊疗中，患者既未到场、也未取消预约的比例。临床医生、诊室与该时段的成本都已支付，却什么都没有发生。这是医疗领域中最纯粹的浪费指标——也是最容易通过软件解决的浪费之一。

## 为何重要

NHS England的数据（2019年）：每年错过的全科医生预约超过1,500万次，每次约£30——合计超过**每年£2.16亿**；医院门诊爽约每年约800万次（约占预约总数的6.4%），每次错过的平均成本约为**£160**。由于一条提醒信息的边际成本仅为几便士，而挽回的价值却是一个配备齐全的完整临床时段，因此降低爽约率在数字健康领域拥有数一数二出色的投资回报率算术——这也是为什么短信提醒、便捷改约与预测性超额预约，是最早被证实有效的数字健康成果之一。

## 计算方法

```
爽约率 = 爽约次数 / 已预约次数 × 100

降低带来的价值 = 预约总数 × Δ爽约率 × 每个挽回时段的价值

每个挽回时段的价值：该时段要么被重新填满（活动价值/等候名单缩减），
要么没有被填满（人员时间只能部分再利用）——具体机制至关重要，
与bed-days-saved.md中的道理相同。
```

## 实例演算

某门诊科室：每年200,000次预约，爽约率8%。一项"提醒+改约"服务（短信提醒配一键改约、交通信息、无障碍格式）将爽约率降至5.5%。

```
挽回的时段数 = 200,000 × 0.025 = 每年5,000个
按门诊平均价值约£160，从等候名单中重新填满：
  5,000 × £160 = 每年£800,000的挽回活动价值
服务成本：200,000 × £0.40 = 每年£80,000

回报比约为10:1，此外还有5,000名等候名单患者得以更早就诊
（参见waiting-list-impact.md与referral-to-treatment.md）。
```

这里的效应量（2.5个百分点）是切合实际的：提醒类随机对照试验一贯显示25–40%的相对爽约率下降。

## 与软件工程的联系

- **这本质上是一个排程系统问题**：提醒信息、自助改约、从取消预约中自动回填等候名单，以及能驱动精准超额预约的爽约预测模型。每一项都是普通的软件工程工作，却拥有异常清晰的经济学论证。
- **工程领域的对应类比**：预留产能的"未出席"——已预订但闲置的CI时段、已预留的云端产能、会议室、面试小组。这套经济学逻辑同样适用：一次廉价的自动化提醒（或对未使用预留的自动释放），就能挽回昂贵的已承诺产能。
- **预测伦理预告**：基于出席数据训练的爽约预测模型，会内嵌贫困程度与就医障碍等因素；若用它来*降低*可能爽约者的优先级，会放大不公平；若用它来*支持*患者按时就诊（交通协助、电话替代方案），则会缩小不公平。参见[触达与公平](../触达与公平/)。

## 陷阱

- **将"已取消并改约"重复计为挽回价值。**
- **为未被重新填满的挽回时段计价**——发送了提醒信息的空时段，仍然是空的。
- **将爽约率一味压向零**：最后那部分爽约的患者，往往正面临着真实存在的障碍；惩罚性做法（爽约N次后即除名）确实能降低这项指标，但代价是抛弃了这些患者。
