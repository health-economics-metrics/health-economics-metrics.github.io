# DORA মেট্রিক্স

DORA (DevOps Research and Assessment) মেট্রিক্স হলো সফটওয়্যার ডেলিভারি কর্মক্ষমতার চারটি পরিমাপ — ডেপ্লয়মেন্ট ফ্রিকোয়েন্সি, পরিবর্তনের লিড টাইম, পরিবর্তন ব্যর্থতার হার, এবং ব্যর্থ-ডেপ্লয়মেন্ট পুনরুদ্ধার সময় — প্লাস পঞ্চম হিসেবে নির্ভরযোগ্যতা।

## কেন এটি গুরুত্বপূর্ণ

DORA-র এক দশকের গবেষণা এই মেট্রিক্সগুলোকে সাংগঠনিক কর্মক্ষমতার সাথে যুক্ত করে। একটি স্বাস্থ্য ব্যবস্থার জন্য, এগুলো IT ভ্যানিটি সংখ্যা নয়: এগুলো নির্ধারণ করে ক্লিনিক্যাল মূল্য কত দ্রুত রোগীদের কাছে পৌঁছায়।

## গণিত

```
ডেপ্লয়মেন্ট ফ্রিকোয়েন্সি = প্রোডাকশন ডেপ্লয়মেন্ট / সময়
লিড টাইম     = t(ডেপ্লয়) − t(কমিট), মধ্যক
পরিবর্তন ব্যর্থতার হার = ব্যর্থ পরিবর্তন / মোট পরিবর্তন × 100
পুনরুদ্ধার সময় (MTTR) = t(পুনরুদ্ধার) − t(ব্যর্থতা), মধ্যক
```

স্বাস্থ্য-অর্থনীতির অনুবাদ:

```
লিড টাইম     → বিলম্বের ব্যয়: পাইপলাইনে সপ্তাহ × CoD
ব্যর্থতার হার → সফটওয়্যার পরিবর্তনের বিরূপ ঘটনা হার
পুনরুদ্ধার সময় → ডাউনটাইম ক্ষতি: MTTR × (হারানো ক্লিনিক্যাল কার্যক্রম+নিরাপত্তা ঝুঁকি)/ঘণ্টা
```

## সমাধানকৃত উদাহরণ

একটি ট্রাস্টের রোগী-প্রবাহ সফটওয়্যার টিম, একটি ডেলিভারি-প্রকৌশল বিনিয়োগের আগে/পরে:

```
                    আগে        পরে
ডেপ্লয়             মাসিক      সাপ্তাহিক
লিড টাইম            6 সপ্তাহ    4 দিন
CFR                 25%        8%
```

## সফটওয়্যার প্রকৌশলের সাথে সংযোগ

এটি *সরাসরি* সফটওয়্যার দিক — বলার মতো সংযোগ হলো বিপরীত ম্যাপিং: DORA মেট্রিক্স হাসপাতালের কার্যক্রমগত মেট্রিক্সের ভিন্ন পোশাক পরা রূপ। লিড টাইম ↔ [রেফারেল থেকে চিকিৎসা](../referral-to-treatment/); পরিবর্তন ব্যর্থতার হার ↔ [পুনঃভর্তির হার](../readmission-rate/)।

## ঝুঁকিপূর্ণ দিক

- **মেট্রিক্স কারচুপি**: নো-অপ রিলিজ দিয়ে ডেপ্লয় সংখ্যা স্ফীত করা।
- **দল জুড়ে লিগ টেবিল**: DORA গুচ্ছ অনুশীলনের তুলনা করে, ভিন্ন ঝুঁকি প্রোফাইলসহ দলের নয়।
- **একটি মেট্রিক্স অপ্টিমাইজ করা**: CFR/নির্ভরযোগ্যতা ছাড়া গতি থ্রুপুট-অস্থিরতা ট্রেড-অফ।
