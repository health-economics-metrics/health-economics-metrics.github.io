# Окупаемость инвестиций в ИИ

Окупаемость инвестиций (ROI) в ИИ — это измеримая отдача по прибылям и убыткам, относимая на инициативы ИИ. Отрезвляющий ориентир: исследование MIT «Разрыв ГенИИ» 2025 года обнаружило, что, несмотря на $30-40 млрд корпоративных инвестиций в генеративный ИИ, **~95% пилотов не показали измеримой отдачи по П&У** — а успешные 5% разделяли узнаваемые привычки.

## Почему это важно

У систем здравоохранения есть название для этой схемы пилотов ИИ: **«пилотит»** — кладбище NHS многообещающих приложений, пилотируемых вечно и никогда не масштабируемых. Выводы MIT точно ложатся на то, что уже знает оценка медицинских технологий: заявления о ценности нуждаются в заранее определённых конечных точках, атрибуция нуждается в компараторах, а «все чувствуют, что это помогает» — не строка выгоды. Успешное меньшинство в данных MIT сосредоточилось на автоматизации бэк-офиса с отслеживаемыми базовыми затратами, и **купленные инструменты успешны ~67% времени против внутренних разработок примерно в треть от этой частоты** — приоритеты, принадлежащие любому кейсу инвестиций в ИИ (см. [разработка против покупки](../разработка-против-покупки/)).

## Расчёт

```
ROI ИИ = (относимая выгода − общая стоимость ИИ) / общая стоимость ИИ

Общая стоимость ИИ = лицензии/вывод (см. inference-unit-economics.md)
              + интеграция + подготовка данных + оценка
              + переработка рабочего процесса + управление/гарантии
              (лицензия обычно составляет меньшую часть знаменателя)

Относимая выгода: измеряется относительно базовой линии или контроля, классифицируется как
наличные / мощность / качество согласно cash-releasing-vs-non-cash-releasing.md
```

## Разобранный пример

Больничная группа развёртывает ИИ для двух сценариев использования:

```
Сценарий A — составление клинических писем (бэк-офис, отслеживаемо):
  базовая линия: аутсорсинговая транскрипция £380 тыс/год
  после:    контракт на транскрипцию отменён; время клинической проверки +£60 тыс
  стоимость ИИ:  £120 тыс/год всё включено
  ROI = (380 тыс − 60 тыс − 120 тыс) / 120 тыс ≈ 167% — высвобождает наличные, поддаётся аудиту ✓

Сценарий B — «ИИ-помощник для клиницистов» (широкий, неотслеживаемый):
  заявление о выгоде: «экономит время 4000 сотрудникам» — базовая линия не зафиксирована
  измеренный эффект на П&У: не доказуем
  → корзина 95%, независимо от того, реально ли это помогает
```

Разница не в качестве ИИ — она в том, была ли у выгоды **базовая линия, владелец и бюджетная строка** ([реализация выгод](../реализация-выгод/)).

## Связь с программной инженерией

Плейбук в форме ОМТ для инвестиций в ИИ: **разбейте доказательства на этапы, как [уровни ESF NICE](../рамочная-программа-стандартов-доказательств-nice/)** — демонстрационный уровень доказательств для низкорисковых инструментов, контролируемые пилоты перед расходами на всю организацию, с предварительно зарегистрированными воротами развёртывания (схема [предварительного листинга с крайним сроком](../ускоренный-путь-diga-в-германии/) DiGA); **считайте избежание затрат так, как экономика здравоохранения считает избежание спроса** — реально только когда конкретная бюджетная строка сдвигается; и **оценивайте сам пилот с помощью [ОЦПИ](../ожидаемая-ценность-полной-информации/)** — пилот, который не может изменить решение о развёртывании, стоит £0. Для среза инструментов разработчика конкретно см. [продуктивность разработчиков с ИИ](../продуктивность-разработчиков-с-ии/).

## Подводные камни

- **Рассеивание выгоды**: ценность, тонко размазанная по тысячам пользователей, неизмерима по построению; выбирайте сценарии использования с сосредоточенными, отслеживаемыми базовыми линиями.
- **Учёт затрат только на лицензию**: интеграция, оценка и переработка рабочего процесса обычно доминируют в реальном знаменателе.
- **Кража атрибуции**: ИИ, развёрнутый вместе с переработкой процессов, присваивает себе всю дельту.
- **Эскалация затонувшего пилота**: продление неудачных пилотов, потому что остановка означает признание неудачи — дата закрытия должна быть согласована заранее.
