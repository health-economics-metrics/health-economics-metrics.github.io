# 預算影響分析（BIA）

預算影響分析（BIA）估算的是：採納某項介入措施，在未來1–5年內會對特定支付方的**預算**產生怎樣的影響。它回答的是*可負擔性*問題；而成本效果分析回答的是*價值*問題。一項技術可能價值極高卻難以負擔——也可能容易負擔卻價值不高。嚴謹的評審二者都需要。

## 為何重要

財務總監從不會問"ICER是多少？"——他們問的是"這會對明年的預算造成什麼影響？"ISPOR的良好實踐指南（該領域的標準）明確規定：應採用支付方自身的視角、1–5年的時間範圍、*未貼現*的年度現金流，以及切合實際的採納曲線，並以情景分析（而非機率分析）方式處理不確定性。NICE要求在成本效果分析之外，同時提供預算影響資訊；在英格蘭，一款全國預算影響超過約£2,000萬/年的產品，無論其ICER如何，都會觸發商業談判。

## 計算方法

```
預算影響_第t年 = 新方案情景成本(t) − 現行方案情景成本(t)

情景成本(t) = Σ 按病患群體求和：
   符合條件人群(t) × 採納率(t) × 每名病患淨成本(t)

每名病患淨成本 = 介入成本 − 被替代的醫療成本 + 被誘發的醫療成本
```

關鍵建模選擇包括：符合條件人群的增長、採納曲線（採用從來都不是瞬時完成的）、新方案會替代掉哪些原有服務、以及它可能*誘發*的任何新增需求（更便捷的可及性 → 更多使用者）。

## 實例演算

某支付方覆蓋200萬人，考慮引入一款數位療法，每名病患每年£300；符合條件成員佔比1.5%（30,000人）；採納率在三年內從20% → 40% → 60%；每名使用者會替代掉每年£120的其他醫療服務。

```
每名使用者淨成本 = 300 − 120 = £180

第1年：30,000 × 0.20 × 180 = £108萬
第2年：30,000 × 0.40 × 180 = £216萬
第3年：30,000 × 0.60 × 180 = £324萬
```

即便該產品的ICER表現優異，僅為£8,000/QALY，支付方到第3年仍必須找到£324萬的*新增資金*——那被替代的£120被稀薄地分攤在其他各條預算科目之中，並不會以現金形式被釋放出來（參見[現金釋放型與非現金釋放型](../現金釋放型與非現金釋放型節省/)）。這正是為什麼單位價值與可負擔性是兩道彼此獨立的門檻。

## 與軟體工程的聯絡

BIA正好是面向CFO的、與"按席位計算的投資回報率主張"相對應的另一半："它按每名開發者計算具有成本效果，但我們今年財政年度內負擔得起全組織鋪開嗎？"應對許可分級、採納S型曲線、只有在舊合同真正終止時才會現金釋放的被替代工具支出，以及被誘發的使用量（CI成本更低 → CI使用量更多）建模。在投資回報率之外附上一張為期3年的預算影響表，正是讓一份企業級工具採購提案在財務上站得住腳的關鍵。 把已公佈的預算影響數位按地點、人群或財年拆分——使各份與已公佈數位恰好吻合——就是[精確到分的成本分攤](../精確到分的成本分攤/)；把匯入該總額的大量條目相加，則是[幣種安全的成本彙總](../幣種安全的成本彙總/)。

## 陷阱

- **瞬時採納的幻想**：按穩態採納水平計算第1年的影響。
- **將被替代的成本當作現金計算**，而實際上它只是被稀釋分散的產能。
- **忽視被誘發的需求**——可及性的提升會增加符合條件人群本身的使用量。
- **混淆BIA與成本效果分析的時間範圍/貼現方式**：BIA在設計上就是短期、不貼現、且特定於某一支付方的。
