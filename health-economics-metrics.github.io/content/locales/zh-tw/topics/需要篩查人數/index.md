# 需要篩查人數 (Number Needed to Screen, NNS)

NNS 是為在規定的隨訪期內預防**一例**不良結局而需要篩查（而不僅僅是治療）的人數，取決於人群的基線風險，以及早期發現和治療所實現的相對風險降低。它是 NNT 在篩查專案層面的對應物：NNT 問的是要*治療*多少人才能預防一例結局；NNS 問的是要有多少人走完整個*篩查再治療*的路徑才能達到這一點。

## 為什麼重要

Rembold 在 1998 年提出 NNS，正是為了讓篩查專案可以與治療在同一基礎上比較，因為篩查檢驗的標題相對風險降低數位掩蓋了兩件治療不會掩蓋的事：實際被邀請參加篩查的人群的基線風險，以及所有接受篩查的人都要承擔檢驗成本和假陽性的負擔，而不只是之後受益的那一小部分人。英國國家篩查委員會的成本效果關卡（見[篩查經濟學](../篩查經濟學/)）就建立在這個區分之上——一個在低基線風險人群中相對風險降低很可觀的篩查專案，其 NNS 仍可能達到數千，此時每預防一例結局的專案成本才成為真正的問題。

## 計算方法

```
NNS = 1 / (基線風險 × 相對風險降低)

基線風險       = 隨訪期內被篩查人群中出現該結局的機率 (0–1)
相對風險降低   = 篩查所使能的早期治療所實現的風險按比例降低 (0–1)

每預防一例結局的專案成本 = NNS × 每次篩查成本
```

直接與 [NNT](../需治療人數/) 比較：NNS 把整個“篩查 → 診斷 → 治療”漏斗的有效性摺疊成一個數位，而 NNT 假定病患已經被診斷並開始了治療。

## 算例

某篩查專案的目標人群在研究期內事件的基線風險為 2%（`基線風險 = 0.02`），早期發現實現了 25% 的相對風險降低（`相對風險降低 = 0.25`）：

```
NNS = 1 / (0.02 × 0.25) = 1 / 0.005 = 200

需要篩查 200 人才能預防一例結局。

每次篩查 £50：
每預防一例結局的專案成本 = 200 × £50 = £10,000
```

這 £10,000 應與結局本身的成本以及它本會造成的 QALY 損失相權衡——這正是[預防經濟學](../預防經濟學/)對一般預防專案所做的比較。

## 與軟體工程的關聯

NNS 就是“要有多少使用者、事件或請求透過一條檢測或分診流程，才能抓到一個值得行動的真陽性”——與基於告警的監控和分診系統直接相關，其中低患病率的目標狀態會把 NNS 推高，就像它會讓陽性預測值崩塌一樣（見[篩查經濟學](../篩查經濟學/)和[臨床 AI 評估](../臨床AI評估/)）。一條每抓到一次真實命中就要處理 200 個事件的監控規則，只有當這次命中的價值至少是每個事件分診成本的 200 倍時才值得運作——與上面衛生示例是同樣的算術。

## 陷阱

- **忽視對基線風險的依賴**：同一個篩查檢驗或專案，在高風險和低風險人群中的 NNS——以及成本效果——差別極大。除非指明計算所針對的人群，否則永遠不要呈現 NNS。
- **誤讀分母**：NNS 計的是*接受篩查*的人，而不是檢測呈陽性或開始治療的人——它已經包含了整個漏斗的有效性，所以絕不應與只統計陽性者的指標比較。
- **跨隨訪期比較**：較短的隨訪期通常會推高 NNS，因為該視窗內觀察到的事件更少。只有按同樣的隨訪時長計算的 NNS 數位才具有可比性。
