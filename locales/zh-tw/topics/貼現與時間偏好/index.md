# 貼現與時間偏好

貼現是將未來的成本與效益折算為現值的過程，因為今天獲得的一份效益，其價值高於五年後獲得的同樣一份效益。

## 為何重要

每一份健康經濟學評審、每一份嚴肅的公共部門商業案例，都會對跨越多年的現金流進行貼現。英國HM Treasury《綠皮書》強制規定年社會時間偏好率為3.5%；NICE的參考案例對成本與健康效果均按每年3.5%貼現（對於獲益期超過30年以上的近乎治癒型療法，則採用1.5%的非參考案例貼現率）。如果你的軟體商業案例聲稱"10年內節省500萬英鎊"，財務評審人會立即要求你提供貼現後的數位。

## 計算方法

未來某筆金額的現值：

```
現值 = 未來值 / (1 + r)^t

現值 = 現在的價值
未來值 = 第t年的未來價值
r = 貼現率（NICE/《綠皮書》標準：0.035）
t = 距今年數
```

對於連續n年、每年恆定為B的效益（年金形式）：

```
現值 = B × [1 − (1 + r)^(−n)] / r
```

## 實例演算

你的軟體為某NHS信託機構每年節省£100,000，為期5年，從上線後第一年開始。

未貼現總額：£500,000。

按3.5%貼現後：

```
第1年：100,000 / 1.035^1 = £96,618
第2年：100,000 / 1.035^2 = £93,351
第3年：100,000 / 1.035^3 = £90,194
第4年：100,000 / 1.035^4 = £87,144
第5年：100,000 / 1.035^5 = £84,197

現值合計 ≈ £451,505
```

誠實的頭條數位約為£451,000，比樸素加總的數位低約10%。現在假設交付延遲一年：每一項的時點都推後一年，現值隨之降至約£436,000——這正是[延遲成本](../延遲成本/)在貼現視角下的體現。

## 與軟體工程的聯絡

- **技術債務償還與平臺遷移**承諾的往往是多年後才能兌現的效益流；在將其與本季度就能回本的工作相比較之前，應先對其進行貼現。
- **前期成本集中、效益後置**是遷移專案的典型形態。貼現會正確地懲罰這種形態：它為"現在投入產能、未來才能獲得價值"這件事的無風險時間價值正確定了價。
- **"第5年才能節省"這類主張理應受到雙重質疑**——它既會被大幅貼現，本身也高度不確定（參見[敏感性分析](../敏感性分析/)）。

## 陷阱

- **只對成本貼現而不對效益貼現**（或反之）——參考案例應對二者按相同的貼現率一併處理。
- **在公共部門案例中使用商業貼現率（8–12%）**，或在風險投資背景的案例中使用3.5%。貼現率應與決策者的實際情境相匹配。
- **將貼現與通貨膨脹混為一談。**貼現適用於*實際*（已經過通脹調整的）數值；不要在無意中同時進行兩次調整。
