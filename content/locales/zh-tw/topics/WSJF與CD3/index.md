# WSJF與CD3

CD3（延遲成本除以時長）與WSJF（加權最短任務優先）是按**價值密度**來排定工作優先順序的規則：即每消耗一單位稀缺產能，能消除多少延遲成本。在共享且固定的產能約束下，按CD3從高到低排序，在數學上正是使總延遲成本最小化的最優排序方式。

## 為何重要

每一份積壓任務清單，本質上都是一個配給問題：眾多有價值的條目，卻只有一條流水線。健康經濟學用成本效果排行榜解決了醫療預算領域的同一個問題：按每英鎊獲得的健康價值對介入措施排序，從榜首開始資助，直到預算耗盡為止。CD3正是交付產能領域中完全相同的邏輯：每單位*受約束資源*的效益，按排名順序獲得資助。把排序做對，等於白撿的錢——同樣的工作，同樣的產能，卻能帶來更低的總延遲成本。

## 計算方法

```
CD3  = 延遲成本（£/周） / 時長（周）      —— 使用真實貨幣單位（Black Swan Farming方法）

WSJF = (使用者-業務價值 + 時間緊迫性 + 風險降低/機會賦能)
       / 任務規模                        —— SAFe框架的相對尺度代理指標，
                                          採用修正版斐波那契打分
```

使用真實貨幣單位（[延遲成本](../延遲成本/)）的CD3，在嚴格意義上強於WSJF那種無量綱的分數——WSJF之於CD3，正如多準則打分之於完整的[成本效用分析](../成本效用分析/)：在無法進行貨幣化時可用，但在分數缺乏錨點時容易被操縱。

## 實例演算

三個功能，一個團隊：

```
功能   延遲成本（£/周）   時長    CD3
A         30,000       10周     3,000
B         12,000       2周      6,000
C         5,000        1周      5,000
```

按CD3排序：B、C、A。與"延遲成本最大者優先"（A、B、C）的排序相比較總延遲成本：

```
CD3排序  (B,C,A)：A等待3周，C等待2周 → 30,000×3 + 5,000×2  = £10萬延遲成本
延遲成本排序 (A,B,C)：B等待10周，C等待12周 → 12,000×10 + 5,000×12 = £18萬
```

同樣的功能，同樣的團隊——僅僅是排序方式的不同，就節省了£80,000。其直覺在於：小而緊急的條目應優先處理，因為它們能以低廉的代價釋放各自的延遲成本；而大條目短暫等待所損失的價值相對較小。

## 與軟體工程的聯絡

對於醫療軟體的投資組合而言，應以本書所教授的單位來量化延遲成本：QALY/周 × 閾值，再加上營運層面的£/周，這樣一來，積壓任務清單就能與醫療系統對其所購買的其他一切事物的排序方式直接相通、可以比較。兩點實踐要點：(1) 時長指的是*佔用約束瓶頸的日曆時間*，而非投入的工作量——一個耗時2周、但只需要瓶頸團隊投入2天的條目，實際代價比看起來要低（參見[下游資源最佳化](../下游資源最佳化/)）；(2) 醫院在按緊迫程度加權的吞吐量排定手術室名單時，其實隱含地運作著同一條規則——臨床優先順序分類，本質上就是按嚴重程度加權的CD3（參見[QALY缺口與嚴重程度調整因子](../QALY缺口與嚴重程度調整因子/)）。

## 陷阱

- **WSJF打分表演**：無量綱的斐波那契數位討論，最終往往取決於誰的嗓門最大；至少應將積壓清單最頂端的條目錨定在真實的延遲成本上。
- **時長操縱**：透過拆分條目來虛抬CD3排名——如果拆分後各部分確實能獨立交付價值，這是合理的；如果不能，這就是造假。
- **忽視緊迫性剖面**：截止日期形態的延遲成本（監管日期）會打破恆定速率的假設；應先按截止日期的可行性排定這類條目，再對其餘條目使用CD3。
- **重新排序造成的震盪**：CD3適用於承諾階段的排序決策，而非對已在進行中的工作進行日常重新洗牌（關於在製品數量，參見[流動指標](../流動指標/)）。
