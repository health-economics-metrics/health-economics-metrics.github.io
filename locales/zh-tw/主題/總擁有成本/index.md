# 總擁有成本（TCO）

TCO是一套系統在其整個生命週期內的全部成本：採購或自建、整合、營運、維護、支援、培訓與退役。一個令人不太舒服的基準事實是：**維護成本佔軟體TCO的50–80%**——大致四分之三的生命週期成本，是在*上線之後*才產生的。

## 為何重要

衛生技術評估早已認識到，一種藥物的價格並不等於它的成本——給藥、監測與副作用管理都應納入模型之中。只計算建設/許可成本的軟體商業案例，重蹈了"藥物價格天真論"的覆轍，系統性地低估了每一個以其為輸入的[ICER](../增量成本效果比/)與[預算影響](../預算影響分析/)分析的成本一側。對NHS採購而言，TCO紀律正是讓一款數位化產品的成本效果主張變得誠實可信的關鍵所在——也正是那些表面看起來便宜的方案最終敗下陣來的地方。

## 計算方法

```
TCO = 初始成本（建設/許可 + 整合 + 資料遷移 + 培訓）
    + Σ_t [營運 + 維護 + 支援 + 基礎設施 + 升級
           + 合規/保障]_t / (1 + r)^t
    + 退役成本（退出、資料提取、並行運作）

時間範圍：商業系統3–5年，臨床基礎設施按系統實際壽命計算
r：公共部門3.5%（《綠皮書》），商業部門8–12%
基準資料：年維護成本約為建設成本的15–20%；生命週期TCO中約78%
發生在上線之後；此處忽略退役成本，供應商鎖定本身自有其定價。
```

## 實例演算

某電子觀測系統的兩個方案，5年時間範圍：

```
                        供應商SaaS方案   自建方案
第0年（許可/建設）        £250,000        £900,000
整合+培訓                £180,000        £150,000
年度營運（第1–5年）      £120,000/年     £190,000/年（託管+1.5名全職維護人員）
退出/退役                £60,000         £30,000

未貼現TCO總計            £1,090,000      £2,030,000
```

自建方案的工程估算（£900,000）僅佔其真實TCO的44%——而自建估算本身通常還會超支30–40%（參見[自建與外購](../自建與外購/)）。除非自建方案能帶來實質性不同的*結果*，否則按[成本最小化](../成本最小化分析/)的邏輯，SaaS方案將以約£940,000的優勢勝出。

## 與軟體工程的聯絡

工程師在主張自建時，往往低估了自己所在領域自身的維護資料："年維護成本約為建設成本15–20%"這條經驗法則意味著，每一套£100萬的系統，都在悄然承諾每年£150,000–200,000的未來產能負擔——這項負債理應與[技術債務](../技術債務/)一同出現在同一張心理資產負債表上。TCO同樣是本書中每一項指標成本一側的共同基礎：每次部署的成本、[雲單位經濟學](../雲單位經濟學/)，以及衛生技術評估對藥物贊助方所強制推行的那套分母紀律。當你產品的價格受到質疑時，一份包含現有方案真實營運成本在內的TCO對比，通常是最有力的重新論證方式。 像上面這樣的多年期 TCO 數位，是隨時間推移的大量成本條目之和——關於一旦模型必須對到分，這個總和為什麼應當是精確十進位制而不是浮點數，見[幣種安全的成本彙總](../幣種安全的成本彙總/)；關於把 TCO 總額分攤到各成本中心而不損失分幣，見[精確到分的成本分攤](../精確到分的成本分攤/)。

## 陷阱

- **以上線成本為錨點**：只比較第0年的成本，而實際排序在第3年就已發生逆轉。
- **內部人力免費謬誤**：內部維護成本被按零計算，理由是"團隊反正已經拿著薪水了"——參見[機會成本](../機會成本/)。
- **忽視退出成本**：資料遷出、合同終止與並行運作，正是"便宜"的SaaS變得昂貴起來的地方。
- **違反同一時間範圍原則**：將一份3年期的SaaS TCO，與一個10年期攤銷的自建方案相比較（參見[時間範圍](../時間範圍/)）。
