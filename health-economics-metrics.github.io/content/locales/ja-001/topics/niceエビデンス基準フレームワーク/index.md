# NICEエビデンス基準フレームワーク(ESF)

ESFは、**デジタルヘルス技術がそのリスクに比例してどれだけの証拠を必要とするか**を規定するNICEのフレームワークです。これは「NHSが私たちのアプリを買う前に、何を証明しなければならないか?」に対する最も公式な答えに近いものです。

## なぜ重要か

ESF(2019年に初めて公開され、2022年にAIと適応的アルゴリズムをカバーするよう更新)は、デジタルヘルス技術を臨床機能によって階層に分類し、**累積的な**エビデンス基準を課します — 5つのグループ(設計要因、価値、性能/有効性、経済的影響、展開)にわたる21の基準:

```
階層A — 直接的な患者アウトカムのないシステムサービス(例:eローステリング)
        → 基本的な基準:信頼性、データ保護、技術的保証
階層B — 情報提供、シンプルなモニタリング、コミュニケーション(例:症状日記)
        → +利用者便益の証拠、適切な信頼性
階層C — 治療、診断、または臨床管理の積極的なガイド
        → +高品質な比較有効性の証拠(理想的にはRCT)と経済分析
```

経済的証拠については、ほとんどの階層で[費用結果分析](../費用結果分析/)が受け入れられます;最高リスクでは[費用効用分析](../費用効用分析/)が期待されます。ESFはあなたの**市場参入のエビデンスコスト**を定義します — 他のあらゆる構築費用と同じように予算を組んでください。

## 数式

公式はありません — 決定表です。実際の計算は商業的です:

```
必要なエビデンス投資 = f(階層)
  階層A:文書化+保証 ≈ £1万〜5万
  階層B:観察的/比較的な利用者便益研究 ≈ £5万〜25万
  階層C:RCTグレードの比較研究+経済モデル ≈ £25万〜£200万以上

自社製品の主張は意図的に位置づけてください:「患者に情報提供する」ではなく
「臨床的意思決定を支援する」と主張することは、あなたを1つ上の階層に移動させ、
請求額を10倍にすることがあります。
```

## 計算例

服薬リマインダーアプリの開発者が、用量調整の推奨機能の追加を検討しています。

- リマインダーアプリとして:**階層B** — アドヒアランスの改善を示すコホート研究で十分です。
- 用量推奨を伴う場合:**階層C** — 比較有効性の証拠(おそらく通常ケアに対するRCT)に加えて経済分析。

RCTの費用が£60万で、用量機能の増分収益が年間£20万なら、証拠の費用が損益分岐点に達するにはその機能が3年以上価値を持たなければなりません — ESFの階層を織り込むと、まったく違って見える製品の意思決定です。多くのチームは階層Bの製品を出荷し、階層Cの主張は資金調達の後に段階付けます。

## ソフトウェア工学との関連

ESFは、このリポジトリの中で最も転用しやすいガバナンスのパターンです:**ツール採用のためのリスクに応じたエビデンス要件**。内部版:コードフォーマッターにはデモが必要(階層A);節約時間を主張する生産性ツールには測定されたパイロット試験が必要(階層B);デプロイを自動的にブロックしたり臨床コードを自動生成したりするAIゲートには、組織全体への展開の前に対照試験グレードの証拠が必要(階層C)。比例した証拠は、両方の失敗モードを止めます — 官僚主義が些細なツールを窒息させることと、感覚だけで重大なものを出荷することです。「証拠期限付きの暫定的な採用」という補完については、[ドイツのDiGA早期承認](../ドイツのdiga早期承認/)も参照してください。

## 落とし穴

- **希望的観測による階層の誤分類** — 規制当局と購入者は、マーケティングが何を言うかではなく、製品が*何をするか*で分類します。
- **製品の後に構築される証拠**:計測や均衡状態のないまま出荷済みの製品にRCTを後付けすることは遅く、しばしば不可能です。
- **ESFを満たして残りを忘れること**:ESFはDTAC(臨床的安全性、データ保護、相互運用性)と並んで存在し、AIについては規制上の許可も伴います — [AI規制評価](../ai規制評価/)を参照してください。
