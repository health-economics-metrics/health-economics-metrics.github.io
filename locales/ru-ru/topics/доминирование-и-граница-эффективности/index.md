# Доминирование и граница эффективности (Dominance and the Efficiency Frontier)

Вариант **доминируется**, если другой вариант стоит дешевле *и* даёт больше. **Граница эффективности** — это то, что остаётся после исключения доминируемых вариантов: набор вариантов, где получить больше означает заплатить больше.

## Почему это важно

Прежде чем начинать дискуссию о порогах или бюджетах, оценка медицинских технологий сначала исключает варианты, которые никто никогда не должен выбирать. Нанесение каждого варианта на плоскость затраты-эффект и построение границы — это пятиминутное упражнение, которое регулярно убивает половину шорт-листа. Инкрементальные сравнения ([ICER](../инкрементальное-соотношение-затрат-и-эффективности/)) затем вычисляются только *вдоль границы*, каждый вариант против следующего по дешевизне недоминируемого варианта — никогда против «ничего не делать», если существуют лучшие промежуточные варианты.

## Математика

```
Строгое доминирование:     A доминирует над B, если Затраты_A ≤ Затраты_B и Эффект_A ≥ Эффект_B
                           (с хотя бы одним строгим неравенством)

Расширенное доминирование: B исключается, если смесь A и C достигает большего
                           эффекта на фунт — выявляется, когда ICER снижается
                           по мере продвижения вверх по границе. На допустимой
                           границе значения ICER должны возрастать.
```

Процедура: отсортируйте варианты по эффекту; удалите строго доминируемые; вычислите попарные ICER между соседями; удалите любой вариант, чей ICER превышает ICER следующего более эффективного варианта (расширенное доминирование); повторяйте, пока ICER не станут монотонно возрастающими.

## Практический пример

Четыре варианта снижения пропущенных приёмов (эффект = восстановленные приёмы в год):

```
Вариант             Затраты/год  Восстановлено
Ничего не делать    £0           0
SMS-напоминания     £20,000      2,000
Телефонные звонки   £120,000     2,200
SMS + сортировка ИИ £90,000      3,500
```

Телефонные звонки **строго доминируются** вариантом SMS + сортировка ИИ (стоят дороже, восстанавливают меньше). Граница: ничего → SMS → SMS + ИИ.

```
ICER(SMS против «ничего не делать») = 20,000 / 2,000  = £10 за восстановленный приём
ICER(SMS+ИИ против SMS)             = (90,000 − 20,000) / (3,500 − 2,000) = £46.67 за приём
```

Возрастающие ICER → действительная граница. При ~£160 экономии на восстановленный больничный приём (см. [долю неявок](../доля-неявок/)) оба шага по границе стоит предпринять; предложение о телефонном call-центре не должно даже доходить до комитета.

## Связь с разработкой программного обеспечения

Постройте тот же график для любого решения по инструментарию: стоимость в год на одной оси, измеренный исход (сэкономленные часы, предотвращённые инциденты, включённые деплои) на другой. Точки вверху и слева от границы исключаются прежде, чем кто-либо начнёт спорить о бюджете. Это переформулирует выбор вендора из споров о списке функций в «вы доминируетесь, совещание окончено». Это также выявляет распространённый корпоративный паттерн покупки самого дорогого варианта ради маргинального выигрыша — легитимно только если инкрементальная цена за инкрементальную единицу — это то, что организация сознательно готова заплатить.

## Подводные камни

- **Сравнение всего с базовой линией** вместо следующего варианта на границе — это льстит дорогим вариантам, скрывая более дешёвые близкие эквиваленты.
- **Одномерные оценки эффекта**, скрывающие то, что важно; если значимы два исхода, либо защитимо объедините их (см. [анализ «затраты-полезность»](../анализ-затраты-полезность/)), либо покажите две границы.
- **Забвение неопределённости**: варианты вблизи границы могут поменяться местами при [анализе чувствительности](../анализ-чувствительности/).
