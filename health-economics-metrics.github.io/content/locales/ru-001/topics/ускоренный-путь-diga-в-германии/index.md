# Ускоренный путь DiGA в Германии

DiGA (Digitale Gesundheitsanwendungen) — это законодательно закреплённый в Германии путь «приложений по рецепту» — первая в мире национальная система, где врачи назначают одобренные медицинские приложения, а обязательное страхование должно их возмещать. Это ведущий живой эксперимент оплаты цифровых терапевтических средств в национальном масштабе.

## Почему это важно

DiGA ответил на вопрос, который задаёт каждая компания цифрового здравоохранения — «кто реально будет платить?» — законодательством (DVG, 2019). Дизайн примечателен:

- **Быстрое решение**: BfArM (регулятор) должен принять решение в течение 3 месяцев.
- **Предварительный листинг**: приложения могут находиться в списке 12 месяцев, *пока ещё генерируя доказательства* — получая доход во время опорного исследования.
- **Крайний срок для доказательств**: доказать «положительный эффект для здравоохранения» (медицинскую пользу или структурное/процедурное улучшение, значимое для пациента) через сравнительное исследование — обычно РКИ — или быть исключённым из списка. Примерно половина предварительных записей не проходит конверсию.
- **Ценообразование**: производитель свободно устанавливает цену 1-го года; затем ведёт переговоры с федерацией страховщиков. Медианные начальные 3-месячные цены около €500; элементы ценообразования на основе результатов появятся с 2026 года.

Проверка рыночной реальности (исследование по конец 2024 года): ~68 приложений в списке, >1 млн накопленных назначений, ~81% назначений активировано, ~€234 млн накопленных расходов страховщиков — реальный рынок, но скромный на фоне ажиотажа, и приверженность после активации остаётся слабым местом.

## Расчёт

Коммерческая модель, которую запускает каждый основатель DiGA:

```
Выручка = назначения × коэффициент активации × цена за период назначения
Стоимость доказательств = опорное РКИ (обычно €1-3 млн) в течение 12-месячного окна
Ожидаемая ценность = В(доказательства успешны) × устойчивая выручка − стоимость доказательств

При ~50% провале конверсии В должна честно оцениваться — половина
области тратит деньги на РКИ и теряет листинг.
```

## Разобранный пример

Приложение управления депрессией предварительно листингуется по €450/квартал:

```
Год 1: 20 000 назначений × 81% активация × €450 ≈ €7,3 млн выручки
Стоимость РКИ: €2 млн, выполняется параллельно
Результат A (доказательства положительны): постоянный листинг, согласованная цена ~€380,
  устойчивое состояние 60 000 рецептов/год ≈ €18,5 млн/год
Результат B (доказательства не подтверждаются): исключение из списка на 12-м месяце; выручка прекращается.
```

Предварительный год финансирует генерацию доказательств — центральное новшество пути. Сравните с традиционной последовательностью (сначала доказательства, выручка годами позже), которая морит голодом именно те продукты, которые DiGA хочет видеть существующими.

## Связь с программной инженерией

Схема DiGA — **предварительное внедрение с заранее зарегистрированной метрикой успеха и автоматическим закатом** — напрямую копируема для управления инженерными инструментами: поставьте инструмент производственным пользователям на 12 месяцев, заранее зарегистрируйте метрику (измеренное сэкономленное время, снижение инцидентов), автоматически истекайте, если доказательства не поступят. Это решает парадокс пилота (инструментам, которым нужен масштаб для доказательства ценности, никогда не достаётся масштаб), не предоставляя постоянного статуса непроверенной технологии. Данные о 81%-ной активации/низкой приверженности также несут продуктовый урок: назначение (или указ руководства) обеспечивает установки; только качество продукта обеспечивает устойчивое использование — см. [приверженность и устойчивость](../приверженность-и-устойчивость/).

## Подводные камни

- **Рассмотрение листинга как финишной черты** — назначения требуют доверия назначающего; многие листингованные DiGA видят незначительный объём.
- **Недостаточная мощность опорного исследования** для экономии денег в год выручки — ложная экономия, объясняющая большую часть 50%-ного показателя провала.
- **Перенос модели без плательщика**: DiGA работает, потому что возмещение обязательно по закону; копия без обязательного платежа — просто пилотная программа.
