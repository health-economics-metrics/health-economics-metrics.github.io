# การวิเคราะห์การตัดสินใจหลายเกณฑ์ (MCDA)

การวิเคราะห์การตัดสินใจหลายเกณฑ์ (MCDA) เป็นแบบจำลองการให้คะแนนแบบผลรวมถ่วงน้ำหนักที่ใช้ในการประเมินเทคโนโลยีด้านสุขภาพ เมื่อเกณฑ์ ICER/ความเต็มใจจ่ายเพียงตัวเดียวไม่ครอบคลุมทุกสิ่งที่ผู้ตัดสินใจใส่ใจ: ความเสมอภาค ความต้องการที่ยังไม่ได้รับการตอบสนอง นวัตกรรม ผลกระทบต่องบประมาณ ความรุนแรงของโรค แต่ละเกณฑ์ได้น้ำหนักที่สะท้อนความสำคัญ (ได้มาจากผู้มีส่วนได้ส่วนเสีย รวมกันเป็น 1) แต่ละทางเลือกได้คะแนนที่ปรับให้เป็นมาตรฐานต่อเกณฑ์ (โดยทั่วไป 0–1) และคะแนนรวมคือผลรวมถ่วงน้ำหนัก — รูปแบบทางคณิตศาสตร์เดียวกับบัตรคะแนนการประเมินผู้ขายซอฟต์แวร์

## ทำไมจึงสำคัญ

MCDA ถูกใช้ในกรอบงานเช่น EVIDEM และในหน่วยงาน HTA บางแห่งสำหรับยากำพร้า/โรคหายาก ที่แนวทางเกณฑ์ต้นทุนต่อ QALY แบบเคร่งครัดถูกมองว่าแคบเกินกว่าจะครอบคลุมทุกสิ่งที่สำคัญต่อการตัดสินใจ คณะทำงาน ISPOR MCDA Emerging Good Practices Task Force ทำให้แนวปฏิบัติที่ดีสำหรับการหาน้ำหนักและคะแนนที่ปกป้องได้เป็นทางการ ก็เพราะการตัดสินที่ถ่วงน้ำหนักแบบไม่เป็นทางการสร้างง่ายและเล่นกลได้ง่าย เมื่อเทคโนโลยีสุขภาพมีมิติของคุณค่าที่[เกณฑ์ความเต็มใจจ่าย](../เกณฑ์ความเต็มใจจ่าย/)ตัวเดียวแสดงไม่ได้ — ความรุนแรง นวัตกรรม ความเสมอภาค — MCDA ให้ผู้ตัดสินใจมีโครงสร้างที่ชัดเจนและตรวจสอบได้ในการรวมมิติเหล่านั้น แทนที่จะเป็นดุลยพินิจที่ไม่ได้กล่าวไว้

## คณิตศาสตร์

```
คะแนน MCDA = Σ_i (น้ำหนัก_i × คะแนน_i)

น้ำหนักควรรวมเป็น 1 (ได้มาจากวิธีการของผู้มีส่วนได้ส่วนเสีย
เช่น swing weighting หรือ Analytic Hierarchy Process)
```

## ตัวอย่างที่คำนวณแล้ว

คณะกรรมการ HTA ประเมินการบำบัดดิจิทัลด้วยสี่เกณฑ์:

```
เกณฑ์                              น้ำหนัก   คะแนน   น้ำหนัก × คะแนน
ประโยชน์ทางคลินิก                   0.4       0.8     0.32
ผลกระทบด้านต้นทุน                   0.3       0.5     0.15
ความรุนแรงของโรค / ความต้องการที่ยังไม่ได้รับการตอบสนอง  0.2   0.9   0.18
นวัตกรรม                            0.1       0.6     0.06
                                    ─────             ─────
                                    1.0               0.71
```

น้ำหนักรวมเป็น 1.0 (0.4 + 0.3 + 0.2 + 0.1) และคะแนน MCDA คือ 0.71 (0.32 + 0.15 + 0.18 + 0.06) คณะกรรมการเทียบ 0.71 กับเกณฑ์ที่ตกลงไว้ล่วงหน้า หรือจัดอันดับเทียบกับเทคโนโลยีคู่แข่งที่ให้คะแนนด้วยวิธีเดียวกัน

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

นี่คือคณิตศาสตร์เดียวกับบัตรคะแนนการเลือกผู้ขายแบบถ่วงน้ำหนัก เมทริกซ์การประเมิน RFP หรือแบบจำลองการให้คะแนนเพื่อจัดลำดับความสำคัญฟีเจอร์ — ดู[สร้างเทียบกับซื้อ](../สร้างเทียบกับซื้อ/) สำหรับกรณีใช้คลาสสิกของบัตรคะแนนถ่วงน้ำหนักในการจัดซื้อซอฟต์แวร์ ควรเปรียบเทียบกับ[WSJF และ CD3](../wsjf-และ-cd3/) ด้วย: WSJF/CD3 เป็นวิธีจัดลำดับความสำคัญแบบ *อัตราส่วน* (ต้นทุนของความล่าช้าหารด้วยขนาดงานหรือระยะเวลา) ขณะที่ MCDA เป็น *ผลรวม* ถ่วงน้ำหนัก MCDA และ WSJF/CD3 เป็นคำตอบที่ต่างกันเชิงโครงสร้างต่อคำถามว่า "เราจัดอันดับตัวเลือกคู่แข่งอย่างไร" และการรู้ว่าการตัดสินใจหนึ่งๆ ต้องการแบบใดจริงๆ — คุณค่ารวมข้ามเกณฑ์อิสระ หรือความหนาแน่นของคุณค่าต่อหน่วยกำลังการผลิตที่หายาก — สำคัญกว่าว่าสูตรใดดูเข้มงวดกว่า

## ข้อผิดพลาดที่พบบ่อย

- **อคติในการหาน้ำหนัก**: ผู้ตั้งน้ำหนักแทบกำหนดอันดับล่วงหน้า ดังนั้น "สูตร" อาจฟอกการตัดสินใจทางการเมืองหรือการค้าให้กลายเป็นการคำนวณที่ดูเป็นกลาง ระบุว่าใครตั้งน้ำหนักและอย่างไร
- **นับซ้ำเกณฑ์ที่ครอบคลุมที่อื่นแล้ว**: ให้คะแนน "ความคุ้มทุน" เป็นเกณฑ์หนึ่ง *และ* ให้คะแนน "ผลกระทบด้านต้นทุน" แยกอีกเกณฑ์ ถ่วงน้ำหนักเงินเกินเกณฑ์อื่นโดยไม่มีใครตั้งใจ
- **ความแม่นยำลวง**: คะแนนถ่วงน้ำหนักทศนิยมสองตำแหน่ง (0.71) สื่อถึงความเข้มงวดมากกว่าที่การให้คะแนนของผู้มีส่วนได้ส่วนเสียบนมาตราส่วน 0–10 รองรับจริง และความแปรปรวนระหว่างผู้ประเมินในการให้คะแนนเหล่านั้นมักไม่ถูกรายงานเลย
