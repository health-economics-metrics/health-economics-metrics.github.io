# 分析視角

視角決定了在一項經濟分析中*誰的*成本與效益才算數：是支付方的、提供方的，還是整個社會的。同一項介入措施，從一個視角看可能極為出色，從另一個視角看卻可能糟糕透頂。

## 為何重要

每一項經濟評估都必須事先宣告其視角，因為視角決定了哪些成本/效益專案會被納入：

- **支付方視角**（例如NHS採購方、保險公司）：只計入支付方需要報銷的成本。
- **提供方視角**（例如一家醫院信託機構）：內部服務提供成本、人員配備、場地設施。
- **社會視角**：一切成本——包括病患時間、交通、家人提供的非正式照護，以及對僱主造成的生產力損失。

NICE的參考案例在成本方面採用**NHS與個人社會服務（PSS）**視角。美國"成本效果分析第二委員會"則建議同時報告醫療保健部門視角與社會視角兩套分析，並附一份列明納入範圍的"影響清單"。

## 計算方法

沒有公式——這是一條在做任何計算之前就應先應用的界定規則：

```
納入的成本/效益類別 = f(視角)
```

一個實用的檢驗方法：製作一份影響清單表，每一行對應一項成本/效益，每一列對應一種視角，並標記出哪些單元格應被計入。

## 實例演算

某症狀自查應用每年將10,000次全科醫師（GP）就診轉化為自我照護。

- **支付方（NHS）**：每次全科醫師問診節省£42，共節省 10,000 × £42 = **每年£420,000**——明顯為正。
- **提供方（全科診所）**：若診所按人頭付費，其收入不變但工作量下降——輕度為正。
- **社會視角**：加上病患節省的交通與等待時間，假設為10,000 × 2小時 × £15/小時 = £300,000的時間價值；但需扣除因2%的使用者被錯誤安慰、之後病情加重才就診所造成的傷害，即200 × £3,000 = £600,000的額外治療成本。社會淨值為：420,000 + 300,000 − 600,000 = **每年£120,000**——為正，但結果高度依賴於安全性假設。

同一款應用，三種不同的答案。正是對視角的明確宣告，才使得這些數位具有可比性與誠實性。

## 與軟體工程的聯絡

工具與平臺的投資回報率同樣存在多種視角：

- **團隊預算（"支付方"）**：許可費用是否在我的成本中心承受範圍內？
- **平臺組織（"提供方"）**：包含整合、支援與維護在內的總成本。
- **公司（"社會"）**：應納入對客戶的影響、安全性外部性，以及所有受影響團隊所耗費的時間。

一款對採購團隊而言很便宜、卻把遷移工作轉嫁給另外40個團隊的CI工具，正是軟體領域的成本轉嫁——只有從更寬的視角才能看清。在每一份商業案例中都應明確宣告所採用的視角；評審者無法質疑他們看不見的假設。

## 陷阱

- **悄悄切換視角**：計入社會層面的效益，卻只計入支付方層面的成本，會讓任何方案看起來都具有成本效果。
- **視角混用導致重複計算**（例如，在支付方資料本身已包含員工時間成本的情況下，同時將一次節省的全科醫師問診計為支付方節省和病患時間節省兩筆）。
- **忽視成本轉嫁**："節省"其實只是把成本轉移給了病患、照護者或另一個部門。
