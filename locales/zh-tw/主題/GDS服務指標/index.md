# GDS服務指標

英國政府數位服務局（GDS）《服務手冊》要求每一項政府數位服務都必須報告四項KPI：**每筆交易成本、使用者滿意度、完成率，以及數位化使用率**。這四項指標共同構成了一項公共數位服務最基本的經濟學框架——也是NHS數位服務所繼承的模板。

## 為何重要

GDS的這些指標，正是支撐了過去十年政府數位化建設的"渠道轉移"商業案例的具體化：《數位效率報告》發現，數位化交易的成本約為電話渠道的1/20，約為面對面渠道的1/50（地方政府資料：網頁£0.15，電話£2.83，面對面£8.62）。但這些節省只有在人們*真正完成*數位化流程（完成率）、*且*選擇該渠道而非昂貴渠道（使用率）時才能真正實現——這四項KPI構成的是一個單一的經濟學模型，而非四塊互不相關的儀表盤。

## 計算方法

```
每筆交易成本 = 服務總成本 / 已完成交易數
完成率       = 已完成交易數 / 已開始交易數 × 100
數位化使用率 = 數位化交易數 / 全渠道交易總數 × 100
使用者滿意度   = 滿意+非常滿意的佔比（5分制，服務內調查）

渠道轉移節省 = 交易量 × 使用率轉移幅度 × (舊渠道成本 − 數位渠道成本)
… 再減去失敗需求成本：(1 − 完成率) × 回退渠道成本
```

## 實例演算

某NHS預約管理服務：每年200萬筆交易，目前70%透過電話（£3.20/通）、30%透過數位渠道（£0.25）。一次重新設計將數位化使用率提升至55%，完成率從84%提升至93%：

```
使用率轉移帶來的節省 = 200萬 × 0.25 × (3.20 − 0.25) = 每年£1,475,000

失敗需求節省：失敗的數位化流程會回退到電話渠道
  改造前：200萬 × 0.30 × 0.16 × £3.20 = £307,200
  改造後：200萬 × 0.55 × 0.07 × £3.20 = £246,400
  淨節省£60,800/年——完成率的改善保護住了使用率提升所帶來的收益

滿意度是一項先行指標：不滿意的使用者會退回電話渠道，
因此滿意度的下降，會在使用率下滑出現之前就提前預示這一趨勢。
```

## 與軟體工程的聯絡

這四項KPI是一個生產級別的[成本後果表](../成本後果分析/)範例：一項成本指標，三項結果指標，從不被壓縮為單一分數。對產品工程師而言，其中的營運啟示是：**完成率本質上是一個漏斗埋點問題**（每一個流失點都是可以被找到並修復的）；**每筆交易成本**本質上就是[雲單位經濟學](../雲單位經濟學/)再加上人工輔助渠道的成本；**使用率其實是一項偽裝過的公平性指標**——那些無法或不願轉換渠道的使用者，往往不成比例地集中在老年人、殘障人士與困難群體之中，因此激進的渠道關閉會把"節省"直接轉化為可及性傷害（參見[觸達與公平](../觸達與公平/)）。將這些KPI公開發布（GOV.UK就是按服務逐項公開的）本身就是一種約束機制：透明度對預測起到的規範作用，正如[效益兌現](../效益兌現/)審計一樣。

## 陷阱

- **靠強制手段提升使用率**：關閉電話線路確實能拉昇數位化使用率，卻把失敗需求轉嫁給了一線員工；應測量整個系統的總成本。
- **從第2頁才開始測量完成率**：在流失點之後才開始計算漏斗，會人為美化完成率數位。
- **計算每筆交易成本時忽略輔助數位化支援**以及失敗需求的處理成本。
- **只在成功完成時才發放滿意度調查**——不滿意的使用者大多根本走不到調查這一步。
