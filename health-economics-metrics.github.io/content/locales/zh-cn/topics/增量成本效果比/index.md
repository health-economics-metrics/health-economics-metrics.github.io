# 增量成本效果比 (Incremental Cost-Effectiveness Ratio，ICER)

ICER是指选择某一方案而非次优替代方案时，每多获得一单位健康效果所需的额外成本。它是卫生技术评估中最核心的数字。（当效果单位为QALY时，它也被称为增量成本效用比，ICUR。）

## 为什么重要

卫生系统从不孤立地评估一项技术——总是*增量地*，与本应采取的替代方案相比较。NICE把一项技术的ICER与其**每QALY £20,000–£30,000**的阈值相比较；美国的ICER研究所报告的区间为每QALY $50,000–$200,000；加拿大的工作标准大致为每QALY CAD$50,000。你的产品对国家卫生服务体系而言是否"值得"，在形式上就等同于其ICER是否低于当地阈值。参见[支付意愿阈值](../支付意愿阈值/)。

## 计算方法

```
ICER = (成本_新方案 − 成本_对照方案) / (效果_新方案 − 效果_对照方案)
     = ΔC / ΔE
```

解读规则：

- ΔC < 0，ΔE > 0：新方案**占优**——更便宜且更好；无需计算比率。
- ΔC > 0，ΔE > 0：计算ICER，并与阈值λ比较；若ICER < λ则采纳。
- ΔC > 0，ΔE < 0：新方案被支配——应拒绝。
- 当ΔE趋近于0时，比率的表现会变得不正常——排序时应优先使用[净货币效益](../净货币效益/)。

对照组必须是*次优的非被支配方案*，而不是"什么都不做"——参见[占优与效率前沿](../优势与效率前沿/)。

## 算例

一项面向心力衰竭患者的远程监测服务，按每1,000名患者/年计，与常规诊疗相比：

```
成本：   服务£900,000；避免的入院节省£600,000
         ΔC = 900,000 − 600,000 = £300,000
效果：   更早干预获得25个QALY
         ΔE = 25

ICER = 300,000 / 25 = 每QALY £12,000
```

每QALY £12,000远低于NICE的£20,000阈值——是一个有力的案例。请注意*净*成本的重要性：若不计入那£600,000的抵消，ICER将变为每QALY £36,000，该方案很可能无法通过。成本抵消及其证据质量，正是这类分析成败的关键所在（参见[避免的下游成本](../避免的下游成本/)）。

## 与软件工程的关联

ICER这一纪律可以完整地迁移到工程决策中：

```
（方案B成本 − 方案A成本） / （方案B产出 − 方案A产出）
```

——每多一次部署的增量成本、每节省一个工程师小时的增量成本、每避免一次故障的增量成本——都必须相对于次优替代方案计算，而不是相对于"什么都不做"。有两个值得借鉴的习惯：（1）*明确点名对照组*——大多数工具的ROI主张，暗地里比较的都是一个稻草人；（2）*先把成本相抵*——一款花费£100k、但取代了£80k既有支出的工具，其ΔC实际上只有£20k。

## 常见陷阱

- **对照组作弊**：与一个已过时或人为拉低的基准相比，会虚增ΔE，从而美化ICER。
- **用平均值代替增量值**：整个项目的每QALY成本，并不等于扩大或采纳该项目的ICER。
- **迷信点估计**：ICER是两个不确定差值之比；应通过[PSA与CEAC](../概率敏感性分析/)报告不确定性。
- **负的ICER含义模糊**（既便宜又差，与既贵又好，会得到相同的符号）——报告负的ICER时，务必说明它究竟落在哪个象限。
- **在没有明确换算步骤的情况下跨币种比较 ICER**：以一国货币计算的 ICER，在与另一国阈值比较之前，必须用声明的方法换算——关于为什么换算系数的选择（购买力平价与市场汇率）本身就可能颠覆采纳决定，见[跨币种 ICER 比较](../跨币种-icer-比较/)。
