# 轉診至治療（RTT）

轉診至治療，是指從全科醫師轉診到由顧問醫師主導的治療正式開始之間所經過的時間。《NHS憲章》設定的標準是：**92%的病患應在18周內開始治療**。RTT是英格蘭NHS體系中政治能見度最高的單一營運指標。

## 為何重要

未能達成RTT目標的信託機構會面臨監管審查、介入介入與聲譽損害；全國等候名單本身就是一個上頭版頭條的數位。病患每多等一週，都意味著健康的損失（在更差的健康狀態下等待——參見下文QALY算術），且往往也意味著成本的增加（病情會惡化；參見[更早介入](../更早介入/)）。任何能在轉診至治療路徑中的任一環節節省時間的軟體——分診、診斷週轉、門診產能、排程——都能直接緩解未達標所帶來的營運與財務後果，這也是為什麼RTT影響是NHS數位化商業案例中的一條一等效益線。

## 計算方法

```
RTT達標率 = 18周內接受治療的病患數 / 接受治療總人數 × 100
每名病患的等待時間健康成本 = 等待時長 × (治療後效用值 − 等待期效用值)

路徑視角：RTT = Σ各階段時長（轉診分診 → 首次門診 →
診斷檢查 → 決策 → 治療）——應改進排隊最長的那個環節，
而非最繁忙的那個環節（參見flow-metrics.md）。
```

## 實例演算

某專科每年治療5,000名路徑病患；平均等待24周；等待期效用值0.68，治療後效用值0.80。

數位化分診加"直接檢查"協議，消除了5周純粹的排隊等待時間：

```
QALY獲益 = 5,000 × (5/52) × (0.80 − 0.68) = 每年57.7 QALY
按每QALY £20,000–£30,000貨幣化（參見willingness-to-pay-thresholds.md）：
  ≈ 每年£115萬–£173萬的健康價值
```

——此外，該信託機構也由未達標轉為達標18周標準，這一點帶來的治理層面價值，是任何電子表格都無法完全捕捉的。

## 與軟體工程的聯絡

RTT是一項**跨越多階段佇列的前置時間指標**——是醫院版本的"從提交到生產環境的前置時間"（參見[DORA指標](../DORA指標/)）。改進方法完全一致：為每一個階段埋點，找出日曆時間究竟積壓在哪裡（幾乎總是在交接與排隊環節，而非臨床工作本身），並消除等待狀態。典型的軟體勝利場景包括：能在數小時內、而非按周批次處理轉診的電子分診系統、以推送方式而非複診預約來傳遞診斷結果，以及自動化的"直接檢查"判定標準。應以[延遲成本](../延遲成本/)（以QALY/周為單位）來為這項改進估值。

## 陷阱

- **改進的並非真正的約束瓶頸所在環節**——在診斷佇列不斷增長的同時縮短首次門診等待，只是把積壓轉移到了別處。
- **操縱指標**：路徑重置與計時暫停可以在不讓任何人更早得到治療的情況下改善報告出來的RTT數位；應審計其背後的真實分佈。
- **將整條路徑的改進都歸功於單一工具**，而實際上是多項變更同時落地——歸因需要一個對照組。
