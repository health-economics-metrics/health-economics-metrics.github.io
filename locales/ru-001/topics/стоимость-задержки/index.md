# Стоимость задержки (СЗ)

Стоимость задержки — это экономическая ценность, теряемая за единицу времени, пока функция, продукт или услуга *не* поставляются. Это самый прочный мост между метриками поставки программного обеспечения и экономикой здравоохранения: он превращает «мы поставили с опозданием» в валюту — или в QALY.

## Почему это важно

Правило Рейнертсена: «Если вы количественно измеряете только одну вещь, измеряйте Стоимость задержки». Большинство организаций знают, сколько стоит проект, но не знают, сколько стоит месяц задержки, поэтому они оптимизируют бюджеты, истекая временной ценностью. Для медицинского ПО ставки буквальны: каждую неделю, на которую задерживается улучшение пути лечения, пациенты дольше ждут в худших состояниях здоровья. СЗ — самая сильная математическая рамка для представления заинтересованным сторонам NHS, потому что она оценивает *отсутствие* вашего ПО.

## Расчёт

```
СЗ = выгода на единицу времени, потерянная, пока не поставлено   (£/неделю или QALY/неделю)

Общие потери от задержки = СЗ × длительность задержки

Для приоритизации см. wsjf-and-cd3.md: CD3 = СЗ / длительность.
```

Для клинического ПО выражайте как в здоровье, так и в деньгах:

```
СЗ_здоровье = затронутые пациенты в неделю × выгода QALY на пациента
СЗ_деньги  = СЗ_здоровье × λ (порог готовности платить, £20тыс–30тыс/QALY)
             + потерянная эксплуатационная экономия в неделю
```

## Разобранный пример

**Операционный**: ПО экономит £200 на пациента на пути лечения; траст обрабатывает 50 таких пациентов/неделю.

```
СЗ = 200 × 50 = £10 000/неделю
10-недельная задержка закупки стоит 200 × 50 × 10 = £100 000 предотвратимых потерь.
```

**Клинический**: улучшение триажа устраняет 5 недель ожидания (полезность 0,68 → 0,80 раньше) для 100 пациентов/неделю:

```
Выгода QALY на пациента = (5/52) × 0,12 ≈ 0,0115
СЗ_здоровье = 100 × 0,0115 = 1,15 QALY/неделю
СЗ_деньги  = 1,15 × £20 000 ≈ £23 000/неделю ценности здоровья
```

6-месячная задержка развёртывания «стоит» ~30 QALY — аргумент, который переосмысляет сбой ввода в эксплуатацию ИТ-системы как клиническое событие. (Ориентир масштаба: знаменитый анализ Maersk от Black Swan Farming нашёл отдельные функции с СЗ ≈ $200 тыс/неделю, которые ждали 38 недель.)

## Связь с программной инженерией

СЗ — это метрика, которая делает [время ожидания DORA](../метрики-dora/) и [эффективность потока](../метрики-потока/) финансово читаемыми: время ожидания × СЗ = деньги (или здоровье), сгоревшие в очередях. Применения:

- **Приоритизация**: ранжируйте работу по СЗ/длительности ([WSJF/CD3](../wsjf-и-cd3/)) вместо самой громкой заинтересованной стороны.
- **Экономика процесса**: двухнедельный цикл релизов имеет ожидаемую стоимость задержки ~1 неделя × СЗ на функцию против непрерывной поставки — оценивайте партию.
- **Закупки**: 6-18-месячные циклы закупок NHS имеют СЗ; демонстрация этого меняет разговоры о срочности (см. [анализ бюджетного воздействия](../анализ-бюджетного-воздействия/) для противоположности доступности).

## Подводные камни

- **Предположение линейной СЗ**: некоторая работа имеет ценность в форме крайнего срока (регуляторные даты — бесконечная СЗ после даты, ноль до неё) или убывающую ценность (окна первопроходца). Классифицируйте профиль срочности перед умножением.
- **СЗ на результатах, которые никому не нужны**: задержка стоит только если у вещи есть ценность; отложенный мусор бесплатен.
- **Двойной учёт задержки и дисконтирования**: [дисконтирование](../дисконтирование-и-временное-предпочтение/) уже оценивает время на многолетних горизонтах; СЗ — это операционная версия в пределах горизонта. Используйте СЗ для недель/месяцев, сдвиг ЧПС — для лет.
