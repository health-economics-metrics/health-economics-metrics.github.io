# 需治療人數（NNT）

NNT是指在一個規定的時間範圍內，需要接受某項介入的病患數量，才能使其中**一名**額外病患獲益。它將容易誤導人的百分比風險降幅，轉化為任何人都能直觀理解的"每份獲益所需付出的努力"單位。

## 為何重要

"心臟病發作風險降低25%！"聽起來極具說服力。但如果基線風險是5年內4%，那麼絕對降幅其實只有1個百分點，也就是說**需要100人連續服藥5年，才能讓其中1人獲益**——而這100人都要承擔相應的成本與副作用。NNT正是應對相對風險行銷話術的解藥，這也是實證醫學之所以以其為首要指標的原因。以他汀類藥物用於一級預防為例：每避免一次心臟病發作，5年內的NNT約為50–100。它的映象指標**NNH**（需傷害人數）則衡量平均每傷害一人，需要治療多少人。

## 計算方法

```
ARR（絕對風險降幅） = 對照組事件發生率 − 治療組事件發生率
NNT                = 1 / ARR

NNH（需傷害人數）   = 1 / (治療組傷害率 − 對照組傷害率)

經濟學橋樑：
每避免一次事件的成本 = NNT × 每個療程的成本
```

務必同時說明時間範圍與基線人群——脫離這兩者，NNT毫無意義。

## 實例演算

某醫院的跌倒預測系統，標記出高風險病患以進行介入（床墊感測器、複核、加強看護）。試驗資料：伴有損傷的跌倒率從入院病患的3.2%降至2.4%。

```
ARR = 0.8個百分點 → NNT = 1/0.008 = 125
   （需要125名病患接受該介入組合，才能預防1次伴有損傷的跌倒）

介入成本約為每名病患£40 → 每避免一次跌倒的成本 = 125 × 40 = £5,000
一次伴有損傷的院內跌倒的成本（額外住院、影像檢查、訴訟風險）約為£12,000
淨結果：預防措施的投入產出比約為2.4:1——外加額外的QALY獲益。
```

請注意NNT是如何確保這一主張保持誠實的："跌倒率降低25%"與"每治療125名病患可預防1次跌倒"，其實是同一個結果，只是說服力的呈現方式不同。

## 與軟體工程的聯絡

NNT正是任何"對大量專案採取行動、卻只捕獲少數問題"的關卡或檢查機制的恰當計量單位："**需要多少個PR透過AI評審關卡，才能真正捕獲一個流向生產環境的缺陷？**"如果該關卡每評審400個PR才能真正捕獲一個實際問題（NNT = 400），而每次評審耗費開發者4分鐘的注意力，那麼每捕獲一個問題就要花費約27個開發者-小時——現在可以將這個數位與該問題若真的流入生產環境所造成的事件成本相比較。NNH對應的則是假陽性：每出現一次*誤報*要檢查多少個PR，每一次誤報又耗費了多少注意力與信任成本？篩查類工具（程式碼檢查器、安全掃描器、異常檢測）在釋出時就應附帶NNT/NNH算術——參見[篩查經濟學](../篩查經濟學/)，瞭解為何低患病率會使這些數位變得異常殘酷。 [需要篩查人數](../需要篩查人數/)是高一層級的對應數位，針對的是整個篩查再治療的專案，而不只是治療。

## 陷阱

- **沒有時間範圍**："NNT = 50"這句話本身毫無意義；"5年內NNT = 50"才是一個完整的主張。
- **基線風險的直接移植**：在高風險試驗人群中計算出的NNT，一旦應用到低風險的實際部署人群中就會失真崩潰。
- **忽視NNH**——一個NNT為400、NNH為3的關卡機制，只是一臺製造麻煩的機器，而非一套真正的安全系統。
