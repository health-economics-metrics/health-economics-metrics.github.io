# 邊際成本與平均成本

平均成本是總成本除以產出單位數。邊際成本則是多生產一個*額外*單位所需的成本。決策應當依據邊際成本來做——但已釋出的單位成本數位幾乎總是平均成本。

## 為何重要

數位健康商業案例中最常見的一個錯誤，就是按**平均**成本為節省下來的資源估值，而實際的節省其實是**邊際**成本。一個醫院床位天的平均（全額分攤）成本超過£400，但釋放一個床位天並不能節省£400——建築、供暖以及大部分人力成本仍會照常發生。除非釋放的床位足夠多、能夠關閉一整個病區，否則實際釋放出的現金可能只有£50–£150。

## 計算方法

```
平均成本：  AC = TC / Q
邊際成本：  MC = dTC/dQ   （多生產/少生產一個單位所需的成本）

TC = 總成本，Q = 數量
```

固定成本的存在，使得在產能削減場景下MC < AC，而當存在閒置產能時，MC甚至可能趨近於零。關於節省的主張應採用：

```
真實節省 = ΔQ × MC          （小幅變動時）
真實節省 = TC的階躍變化      （跨越產能閾值的大幅變動，例如關閉一個病區）
```

## 實例演算

你的軟體縮短了平均住院時長，為某信託機構每年釋放出1,000個床位天。

- **樸素主張**：1,000 × £400平均成本 = **節省£400,000**。這是錯的。
- **邊際主張**：每個床位天的可變成本（餐食、洗滌、耗材，以及部分彈性護理人力）約為£120。節省額 = 1,000 × £120 = **£120,000**，*外加*若這些釋放出的床位被用於擇期等候病患，還有相應的產能價值（按活動付費機制下的收入，或等候名單的縮減）。
- **階躍變化主張**：如果該信託機構每年能釋放7,300個床位天（相當於一個20張床位的病區），就可以真正關閉這個病區：人員配置+營運成本合計約每年£150萬的真實現金。此時，按平均成本計算得出的數位，反而更接近真實情況。

同一項介入措施，會得出三個各自都站得住腳的數位，具體取決於這一變化是否跨越了某個產能階梯。

## 與軟體工程的聯絡

雲端計算經濟學本身就是邊際成本的天然領域：

- 在已預留產能上多運作一次CI，其邊際成本約為£0，而每次運作的平均成本（平臺總支出 ÷ 運作次數）卻可能高達數英鎊。按平均成本收費的內部計費系統，會驅使團隊不敢充分使用那些在邊際上其實是免費的共享產能。
- 反過來，"我們節省了30%的算力"，只有在實例真正被終止、或預留資源真正被削減時，才能真正釋放現金——這正是軟體版本的"床位天陷阱"。參見[現金釋放型與非現金釋放型節省](../現金釋放型與非現金釋放型節省/)。

## 陷阱

- **按平均成本為產能估值，並將其呈現為現金**（這是最經典的錯誤）。
- **假設邊際成本是恆定不變的。**它會在產能邊界處出現階躍（病區關閉、許可分級、預留實例承諾）。
- **在同一份論證中，擴容決策用邊際成本、縮容決策卻用平均成本**——應根據實際所面對的決策型別來選擇。
