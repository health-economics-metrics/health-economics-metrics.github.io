# 总拥有成本（TCO）

TCO是一套系统在其整个生命周期内的全部成本：采购或自建、集成、运营、维护、支持、培训与退役。一个令人不太舒服的基准事实是：**维护成本占软件TCO的50–80%**——大致四分之三的生命周期成本，是在*上线之后*才产生的。

## 为何重要

卫生技术评估早已认识到，一种药物的价格并不等于它的成本——给药、监测与副作用管理都应纳入模型之中。只计算建设/许可成本的软件商业论证，重蹈了"药物价格天真论"的覆辙，系统性地低估了每一个以其为输入的[ICER](../增量成本效果比/)与[预算影响](../预算影响分析/)分析的成本一侧。对NHS采购而言，TCO纪律正是让一款数字化产品的成本效果主张变得诚实可信的关键所在——也正是那些表面看起来便宜的方案最终败下阵来的地方。

## 计算方法

```
TCO = 初始成本（建设/许可 + 集成 + 数据迁移 + 培训）
    + Σ_t [运营 + 维护 + 支持 + 基础设施 + 升级
           + 合规/保障]_t / (1 + r)^t
    + 退役成本（退出、数据提取、并行运行）

时间范围：商业系统3–5年，临床基础设施按系统实际寿命计算
r：公共部门3.5%（《绿皮书》），商业部门8–12%
基准数据：年维护成本约为建设成本的15–20%；生命周期TCO中约78%
发生在上线之后；此处忽略退役成本，供应商锁定本身自有其定价。
```

## 实例演算

某电子观测系统的两个方案，5年时间范围：

```
                        供应商SaaS方案   自建方案
第0年（许可/建设）        £250,000        £900,000
集成+培训                £180,000        £150,000
年度运营（第1–5年）      £120,000/年     £190,000/年（托管+1.5名全职维护人员）
退出/退役                £60,000         £30,000

未贴现TCO总计            £1,090,000      £2,030,000
```

自建方案的工程估算（£900,000）仅占其真实TCO的44%——而自建估算本身通常还会超支30–40%（参见[自建与外购](../自建与外购/)）。除非自建方案能带来实质性不同的*结果*，否则按[成本最小化](../成本最小化分析/)的逻辑，SaaS方案将以约£940,000的优势胜出。

## 与软件工程的联系

工程师在主张自建时，往往低估了自己所在领域自身的维护数据："年维护成本约为建设成本15–20%"这条经验法则意味着，每一套£100万的系统，都在悄然承诺每年£150,000–200,000的未来产能负担——这项负债理应与[技术债务](../技术债务/)一同出现在同一张心理资产负债表上。TCO同样是本书中每一项指标成本一侧的共同基础：每次部署的成本、[云单位经济学](../云单位经济学/)，以及卫生技术评估对药物赞助方所强制推行的那套分母纪律。当你产品的价格受到质疑时，一份包含现有方案真实运营成本在内的TCO对比，通常是最有力的重新论证方式。 像上面这样的多年期 TCO 数字，是随时间推移的大量成本条目之和——关于一旦模型必须对到分，这个总和为什么应当是精确十进制而不是浮点数，见[币种安全的成本汇总](../币种安全的成本汇总/)；关于把 TCO 总额分摊到各成本中心而不损失分币，见[精确到分的成本分摊](../精确到分的成本分摊/)。

## 陷阱

- **以上线成本为锚点**：只比较第0年的成本，而实际排序在第3年就已发生逆转。
- **内部人力免费谬误**：内部维护成本被按零计算，理由是"团队反正已经拿着薪水了"——参见[机会成本](../机会成本/)。
- **忽视退出成本**：数据迁出、合同终止与并行运行，正是"便宜"的SaaS变得昂贵起来的地方。
- **违反同一时间范围原则**：将一份3年期的SaaS TCO，与一个10年期摊销的自建方案相比较（参见[时间范围](../时间范围/)）。
