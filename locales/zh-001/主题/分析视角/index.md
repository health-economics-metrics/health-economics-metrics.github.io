# 分析视角

视角决定了在一项经济分析中*谁的*成本与效益才算数：是支付方的、提供方的，还是整个社会的。同一项干预措施，从一个视角看可能极为出色，从另一个视角看却可能糟糕透顶。

## 为何重要

每一项经济评估都必须事先声明其视角，因为视角决定了哪些成本/效益项目会被纳入：

- **支付方视角**（例如NHS采购方、保险公司）：只计入支付方需要报销的成本。
- **提供方视角**（例如一家医院信托机构）：内部服务提供成本、人员配备、场地设施。
- **社会视角**：一切成本——包括患者时间、交通、家人提供的非正式照护，以及对雇主造成的生产力损失。

NICE的参考案例在成本方面采用**NHS与个人社会服务（PSS）**视角。美国"成本效果分析第二委员会"则建议同时报告医疗保健部门视角与社会视角两套分析，并附一份列明纳入范围的"影响清单"。

## 计算方法

没有公式——这是一条在做任何计算之前就应先应用的界定规则：

```
纳入的成本/效益类别 = f(视角)
```

一个实用的检验方法：制作一份影响清单表，每一行对应一项成本/效益，每一列对应一种视角，并标记出哪些单元格应被计入。

## 实例演算

某症状自查应用每年将10,000次全科医生（GP）就诊转化为自我照护。

- **支付方（NHS）**：每次全科医生问诊节省£42，共节省 10,000 × £42 = **每年£420,000**——明显为正。
- **提供方（全科诊所）**：若诊所按人头付费，其收入不变但工作量下降——轻度为正。
- **社会视角**：加上患者节省的交通与等待时间，假设为10,000 × 2小时 × £15/小时 = £300,000的时间价值；但需扣除因2%的用户被错误安慰、之后病情加重才就诊所造成的伤害，即200 × £3,000 = £600,000的额外治疗成本。社会净值为：420,000 + 300,000 − 600,000 = **每年£120,000**——为正，但结果高度依赖于安全性假设。

同一款应用，三种不同的答案。正是对视角的明确声明，才使得这些数字具有可比性与诚实性。

## 与软件工程的联系

工具与平台的投资回报率同样存在多种视角：

- **团队预算（"支付方"）**：许可费用是否在我的成本中心承受范围内？
- **平台组织（"提供方"）**：包含集成、支持与维护在内的总成本。
- **公司（"社会"）**：应纳入对客户的影响、安全性外部性，以及所有受影响团队所耗费的时间。

一款对采购团队而言很便宜、却把迁移工作转嫁给另外40个团队的CI工具，正是软件领域的成本转嫁——只有从更宽的视角才能看清。在每一份商业论证中都应明确声明所采用的视角；评审者无法质疑他们看不见的假设。

## 陷阱

- **悄悄切换视角**：计入社会层面的效益，却只计入支付方层面的成本，会让任何方案看起来都具有成本效果。
- **视角混用导致重复计算**（例如，在支付方数据本身已包含员工时间成本的情况下，同时将一次节省的全科医生问诊计为支付方节省和患者时间节省两笔）。
- **忽视成本转嫁**："节省"其实只是把成本转移给了患者、照护者或另一个部门。
