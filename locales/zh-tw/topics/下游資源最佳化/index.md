# 下游資源最佳化

為一名資深從業者——全科醫師、高年資住院醫師、顧問醫師——節省一小時，往往能防止整個多學科團隊（護士、行政文員、治療師）因等待臨床審批而陷入瓶頸式延誤。解除瓶頸的價值，等於其下游所有人的吞吐量之和。

## 為何重要

醫療運轉依賴一整條審批鏈：出院要等待顧問醫師簽字，治療方案要等待多學科團隊評審，轉診要等待分診。當那個起關卡作用的角色被延誤時，代價並不只是那一個人的一小時——而是所有下游依賴角色的閒置或阻塞時間，再加上病患滯留在懸而未決狀態中的時間（額外的[床位天數](../節省的床位天數/)、更長的[轉診至治療等待時間](../轉診至治療/)）。這正是約束理論在臨床路徑上的應用：在*約束瓶頸處*節省的一小時，其價值等於整個系統的邊際吞吐量；而在其他環節節省的一小時，價值則要小得多。

## 計算方法

```
解除瓶頸的價值 = Σ 各下游角色（被釋放的阻塞小時數 × 單位成本）
              + 路徑吞吐量提升 × 每完成一條路徑的價值

對比：在非關卡角色處節省同樣一小時的價值 ≈ 僅相當於該角色
自身的產能價值（參見practitioner-time.md）。
```

需透過實證方式識別約束所在：工作在哪裡排隊最久？延誤最終可以追溯到誰的收件箱？

## 實例演算

某病區每天早晨的出院需要顧問醫師稽核。該顧問醫師每天要花90分鐘從散落在各個系統中的資訊中彙總資料；稽核工作要到14:00才能完成，而每天有6例出院因此錯過當天辦理——每例都造成一個本可避免的床位天。

一款出院摘要儀表盤（將化驗結果、用藥記錄、警示標記整合到一個檢視中）將資訊彙總時間縮短至20分鐘；稽核工作在11:30前即可完成：

```
避免的床位天數 = 原本6例延誤出院中的4例 × 365 ≈ 每年1,460個床位天
下游解除阻塞情況：2名出院協調員 + 藥房 + 轉運人員，此前每天下午
               都是先閒置、後突擊——約每天釋放3個員工-小時的
               阻塞時間 ≈ 每年1,100小時
```

顧問醫師自己節省的那70分鐘，其實是這項價值中*最小*的一部分——這正是這項指標的意義所在。床位天數應按其具體機制估值（參見[節省的床位天數](../節省的床位天數/)），員工工時則應作為產能來估值。

## 與軟體工程的聯絡

這對應的正是程式碼評審、架構籤核，以及資深工程師的收件箱。當五名工程師等待某位唯一能批准設計方案的人整整一天時，代價是五個工程師-天，外加這項工作本身產生的一天[延遲成本](../延遲成本/)——而絕不只是一個評審者-小時。能壓縮這一關卡角色任務耗時的工具（更好的評審上下文、自動化預檢查、能自動彙總批准者所需資訊的儀表盤），買到的是系統整體吞吐量，而非個人便利。應測量該約束瓶頸處的排隊/等待時間（參見[流動指標](../流動指標/)）——這正是軟體世界中那個"14:00出院懸崖"的對應物。

## 陷阱

- **最佳化一個非約束環節**：為一個後面沒有任何工作排隊等待的角色打造精美的工具，幾乎不會產生任何系統層面的價值。
- **約束遷移**：解除了顧問醫師這個瓶頸，約束會轉移到別處（藥房、轉運）——在宣稱獲得完整吞吐量提升之前，應先對*下一個*約束瓶頸建模。
- **將下游節省的工時直接算作現金**：被釋放的阻塞時間屬於產能，仍需經受通常的[重新部署檢驗](../現金釋放型與非現金釋放型節省/)。
