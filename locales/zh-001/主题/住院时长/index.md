# 住院时长（LOS）

住院时长是指从入院到出院之间的天数——这是住院医疗中最核心的流动效率指标。英国急症医疗的平均住院时长约为4–5天；每多住一天，都会占用宝贵的床位资源，并使患者暴露于院内获得性风险之中。

## 为何重要

住院时长几乎驱动着急症医院经济学中的一切：床位产能、择期手术吞吐量、急诊流动、人员配置。在规模效应下，即便只是将平均住院时长缩短几分之一天，也能释放出巨大的产能（参见[节省的床位天数](../节省的床位天数/)）。住院时长同样是双向的质量信号——过长可能暗示流程失灵（诊断延迟、出院文书、等待社会照护安排）；过短则可能意味着过早出院，其后果会以[再入院](../再入院率/)的形式在后期显现。

## 计算方法

```
住院时长（单次住院）  = 出院日期 − 入院日期
平均住院时长          = 占用床位天数 / 出院人次（应同时报告均值与中位数；
                       由于长期住院的极端值影响，住院时长呈明显右偏分布）

进行比较时需进行病例组合调整（年龄、诊断、病情严重程度），
否则你测量的只是医院收治的是哪些病人，而非医院的实际表现。
```

利特尔法则将各项流动变量联系在一起：`占用床位数 = 入院速率 × 平均住院时长`——这与支配软件队列的法则完全相同（参见[流动指标](../流动指标/)）。

## 实例演算

某信托机构每天收治40名急诊内科患者，平均住院时长6.0天：这意味着永久占用240张床位（40 × 6）。出院协调软件（任务追踪、药房带药自动化、转运预订）将住院时长中非临床性质的尾部平均缩短了0.4天。

```
所需床位数 = 40 × 5.6 = 224 → 持续释放出16张床位
           = 16 × 365 = 每年5,840个床位天
```

应依据具体机制（重新填满/关闭/冗余吸收）为这5,840个床位天估值，参见[节省的床位天数](../节省的床位天数/)。请注意，真正发生变化的并非医疗本身，而是*等待*——患者在医学上早已适合出院；系统却仍在处理文书工作。这本质上是一个排队问题，而软件恰恰擅长解决排队问题。

## 与软件工程的联系

住院时长就是医院的周期时间，其改进方法与交付流程改进完全一致：为各阶段埋点（入院 → 治疗 → 医学上适合出院 → 实际已出院），找出时间究竟积压在哪里（通常是在交接环节），移除等待状态，而非一味增加产能。"医学上已适合出院，却仍占用床位"的这批患者，正是医院版本的"已获批准却尚未合并的PR"。可直接切入的软件机会包括：出院任务编排、诊断周转、出院用药的电子处方开具、社会照护转介集成。

## 陷阱

- **只报告均值**——极端值会主导结果；一个正在下降的均值，可能掩盖了正在增长的长期住院尾部。
- **前后对比主张中缺乏病例组合调整**：入院门槛本身会随季节及长期趋势而变化。
- **住院时长的缩短以再入院的形式重新出现**——任何关于住院时长的主张，都应同时附上30天再入院数据。
