# 리얼옵션 가치평가

리얼옵션 가치평가는 금융 옵션 가격 책정의 논리를 (금융시장이 아닌) 실물 투자 결정에 적용하는 것으로, 구체적으로는 프로젝트가 성공하면 의무 없이 나중에 확장할 수 있는 *확장 옵션*을 다룹니다. 단순화한 1기간 이항 모델(Cox, Ross, Rubinstein, 1979)은 이 유연성을 직접 평가하여, "작게 출시하고 지켜보자"를 직감에서 가격이 매겨진 숫자로 바꿔 줍니다.

## 왜 중요한가

정적 NPV 계산은 프로젝트를 전부 아니면 전무의 내기로 가격을 매깁니다. 오늘의 규모로 영원히, 자금을 대든지 말든지입니다. 실제 프로젝트, 특히 단계적 디지털 헬스 도입은 그렇게 내기가 이루어지는 경우가 드뭅니다. 보건 시스템은 작은 파일럿에 자금을 대고, 어떤 일이 벌어지는지 지켜본 뒤, 효과가 있을 때에만 추가 자금을 투입할 수 있습니다. 그 유연성에는 실제 가치가 있으며, 이를 무시하면 단계적 투자가 일시불 투자에 비해 체계적으로 저평가됩니다. 더 안전해 보이는 단계적 제안에 보상하는 조달 절차에서는 정반대의 결과입니다. 리얼옵션 가치평가는 유연성 자체에 가격을 매기므로, 단계적 제안이 단순한 NPV 행에서 작아 보인다는 이유로 불이익을 받지 않고 전면 투입 대안과 공정하게 비교될 수 있습니다.

## 수식

```
"상승" 상태의 위험중립 확률:
  p = ((1 + 무위험이자율) − 하락계수) / (상승계수 − 하락계수)

각 상태에서의 확장 페이오프(0으로 하한 — 확장은 선택 사항):
  페이오프_상승 = max(프로젝트_가치 × 상승계수 − 확장_비용, 0)
  페이오프_하락 = max(프로젝트_가치 × 하락계수 − 확장_비용, 0)

옵션 가치(할인된 기대 페이오프):
  옵션_가치 = (p × 페이오프_상승 + (1 − p) × 페이오프_하락) / (1 + 무위험이자율)

확장 NPV = 정적_NPV + 옵션_가치
```

프로젝트의 가치는 다음 의사결정 시점까지 상승(`상승계수`)하거나 하락(`하락계수`)합니다. 확장은 그 상태에서 수익성이 있을 때에만 행사됩니다. 페이오프의 하한을 0으로 두는 것이 이것을 의무가 아닌 진정한 *옵션*으로 만듭니다. 나중에 확장하는 옵션이 아니라 먼저 정보를 수집하는 옵션의 가격 책정은 [완전정보의 기대가치](../완전정보의-기대가치/)를 참고하세요. 그 결정을 기다리는 비용은 [지연 비용](../지연-비용/)을 참고하세요.

## 계산 예시

`프로젝트_가치 = £1,000,000`인 디지털 서비스 파일럿이 있으며, 다음 의사결정 시점까지 1.5배로 상승하거나 0.5배로 하락할 수 있고, 무위험이자율은 8%, 확장 비용은 £600,000입니다.

```
p = (1.08 − 0.5) / (1.5 − 0.5) = 0.58

페이오프_상승 = max(1,000,000 × 1.5 − 600,000, 0) =  900,000
페이오프_하락 = max(1,000,000 × 0.5 − 600,000, 0) = max(−100,000, 0) = 0

하한이 중요하다: 시장이 실망스러우면 옵션은 행사되지 *않는다* —
£600,000의 확장 비용이 하락 상태에서 프로젝트가 가질
£500,000의 가치를 넘기 때문이다.

옵션_가치 = (0.58 × 900,000 + 0.42 × 0) / 1.08
          = 522,000 / 1.08
          ≈ £483,333.33
```

옵션 가치를 정적 NPV 기준선 £200,000에 더하면 확장 NPV = 200,000 + 483,333.33 ≈ **£683,333.33**입니다. 이 옵션 가치 없이 정적 NPV £200,000만 보고하면 단계적 프로젝트의 실제 가치를 두 배 넘게 과소평가하게 됩니다.

## 소프트웨어 공학과의 연관성

이는 "지금 최소 버전을 출시하고, 잘되면 추가로 투자할 옵션을 남겨 둔다"의 공식 버전이며, 디지털 헬스 제품의 단계적 도입과 직접 관련됩니다. [지연 비용](../지연-비용/)과 [WSJF/CD3](../wsjf와-cd3/)의 불확실성 하의 순서 결정 틀과 구조적으로 나란하고, [완전정보의 기대가치](../완전정보의-기대가치/) 및 [표본정보의 기대가치](../표본정보의-기대가치/)를 보완합니다. 셋 모두 서로 다른 각도에서 불확실성 하의 유연성이나 정보에 가격을 매깁니다.

## 함정

- **의존하는 거래 자산 가정 없이 위험중립 가격 책정을 빌려 오기**: 리얼옵션 모델은 기초 가치가 *거래되는* 자산이라고 가정하는 금융 옵션 가격 책정에서 위험중립 확률을 빌려 옵니다. 정말로 거래되지 않는 실물 프로젝트에게 이는 모델링의 편의일 뿐 문자 그대로의 시장 사실이 아닙니다.
- **`상승계수`/`하락계수`를 자유 모수로 취급하기**: 이항 모형의 상승/하락 입력은 그 자체로 정당화가 필요한 가정이며, 원하는 답을 내도록 고르는 자유 모수가 아닙니다.
- **옵션 가치만 보고하기**: 리얼옵션 가치는 독립 프로젝트의 정적 NPV에 *가산되는* 것입니다. 흔한 오류는 기본 케이스를 빼고 옵션 가치만 보고하는 것으로, 정적 NPV가 음수이면 케이스를 과대평가하고, (위 계산 예시처럼) 정적 NPV를 아예 빼놓으면 과소평가하게 됩니다.
