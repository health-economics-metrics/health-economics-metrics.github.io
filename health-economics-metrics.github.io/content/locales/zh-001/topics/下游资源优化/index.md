# 下游资源优化

为一名资深从业者——全科医生、高年资住院医师、顾问医生——节省一小时，往往能防止整个多学科团队（护士、行政文员、治疗师）因等待临床审批而陷入瓶颈式延误。解除瓶颈的价值，等于其下游所有人的吞吐量之和。

## 为何重要

医疗运转依赖一整条审批链：出院要等待顾问医生签字，治疗方案要等待多学科团队评审，转诊要等待分诊。当那个起关卡作用的角色被延误时，代价并不只是那一个人的一小时——而是所有下游依赖角色的闲置或阻塞时间，再加上患者滞留在悬而未决状态中的时间（额外的[床位天数](../节省的床位天数/)、更长的[转诊至治疗等待时间](../转诊至治疗/)）。这正是约束理论在临床路径上的应用：在*约束瓶颈处*节省的一小时，其价值等于整个系统的边际吞吐量；而在其他环节节省的一小时，价值则要小得多。

## 计算方法

```
解除瓶颈的价值 = Σ 各下游角色（被释放的阻塞小时数 × 单位成本）
              + 路径吞吐量提升 × 每完成一条路径的价值

对比：在非关卡角色处节省同样一小时的价值 ≈ 仅相当于该角色
自身的产能价值（参见practitioner-time.md）。
```

需通过实证方式识别约束所在：工作在哪里排队最久？延误最终可以追溯到谁的收件箱？

## 实例演算

某病区每天早晨的出院需要顾问医生审核。该顾问医生每天要花90分钟从散落在各个系统中的信息中汇总资料；审核工作要到14:00才能完成，而每天有6例出院因此错过当天办理——每例都造成一个本可避免的床位天。

一款出院摘要仪表盘（将化验结果、用药记录、警示标记整合到一个视图中）将信息汇总时间缩短至20分钟；审核工作在11:30前即可完成：

```
避免的床位天数 = 原本6例延误出院中的4例 × 365 ≈ 每年1,460个床位天
下游解除阻塞情况：2名出院协调员 + 药房 + 转运人员，此前每天下午
               都是先闲置、后突击——约每天释放3个员工-小时的
               阻塞时间 ≈ 每年1,100小时
```

顾问医生自己节省的那70分钟，其实是这项价值中*最小*的一部分——这正是这项指标的意义所在。床位天数应按其具体机制估值（参见[节省的床位天数](../节省的床位天数/)），员工工时则应作为产能来估值。

## 与软件工程的联系

这对应的正是代码评审、架构签核，以及资深工程师的收件箱。当五名工程师等待某位唯一能批准设计方案的人整整一天时，代价是五个工程师-天，外加这项工作本身产生的一天[延迟成本](../延迟成本/)——而绝不只是一个评审者-小时。能压缩这一关卡角色任务耗时的工具（更好的评审上下文、自动化预检查、能自动汇总批准者所需信息的仪表盘），买到的是系统整体吞吐量，而非个人便利。应测量该约束瓶颈处的排队/等待时间（参见[流动指标](../流动指标/)）——这正是软件世界中那个"14:00出院悬崖"的对应物。

## 陷阱

- **优化一个非约束环节**：为一个后面没有任何工作排队等待的角色打造精美的工具，几乎不会产生任何系统层面的价值。
- **约束迁移**：解除了顾问医生这个瓶颈，约束会转移到别处（药房、转运）——在宣称获得完整吞吐量提升之前，应先对*下一个*约束瓶颈建模。
- **将下游节省的工时直接算作现金**：被释放的阻塞时间属于产能，仍需经受通常的[重新部署检验](../现金释放型与非现金释放型节省/)。
