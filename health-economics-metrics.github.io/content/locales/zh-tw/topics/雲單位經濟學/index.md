# 雲單位經濟學（FinOps）

雲單位經濟學將原始的雲端支出，轉化為**每單位產出的成本**——每客戶、每筆交易、每例已處理案例、每個令牌。這正是FinOps的核心能力，它能把"我們的AWS賬單是每月£400,000"這種說法，轉化為"服務一名病患的成本是£0.83"。

## 為何重要

總支出數位無法回答那些真正重要的問題：產品的效率是在提升還是在下降？增長究竟是改善還是侵蝕了利潤率？我們應該如何定價？單位成本可以同時回答這三個問題。就數位健康而言，"每例已處理案例的成本"本身*就是*一項醫療服務單位成本——可以直接與採購方用於所有其他服務的[全國成本採集](../全國統一收費標準與單位成本/)資料相比較，這使其成為將數位化路徑與傳統路徑進行定價比較的天然語言。

## 計算方法

```
單位成本 = 已分攤的總成本（含共享/平臺成本）/ 已交付單位數

兩大類別：
  資源效率類單位：每GB儲存成本、每vCPU小時成本、每令牌成本、
                 每建置分鐘成本
  業務類單位：    每客戶成本、每筆交易成本、每次問診成本、
                 每例已處理案例成本

邊際與平均的區分原則同樣適用（參見marginal-vs-average-cost.md）：
已承諾/已預留的支出會使邊際單位成本趨近於0，直到下一次
承諾階梯為止——擴容決策應按邊際成本定價，效率趨勢判斷
則應看平均成本。
```

## 實例演算

某數位化分診服務：雲端支出每月£62,000（計算£30,000，資料£18,000，共享平臺分攤£14,000），每月處理380,000例分診事件：

```
每例事件平均成本 = 62,000 / 380,000 ≈ £0.163

與採購方參照對比：電話分診約£8–12/通，全科醫師問診約£42
→ 數位化事件的成本約為最便宜的人工替代方案的2%——這正是
  gds-service-metrics.md中渠道轉移經濟學在成本一側的體現。

趨勢檢驗：去年為每例£0.21，處理量為24萬例 → 規模經濟正在改善
（固定平臺成本正被逐步攤薄），這一點值得在季度業務回顧中重點體現。
```

## 與軟體工程的聯絡

單位經濟學是工程決策轉化為財務可讀語言的地方：一種能將每例成本減半的架構，是一項定價優勢；而一種呈超線性擴張成本的架構，則是一顆只有透過這項指標才能被察覺的定時炸彈。可從醫療成本核算中遷移過來的做法包括：**公開分攤規則**（共享成本曾一度扭曲單位成本數位，直到PLICS（病人層面資訊與成本系統）實現了病人層面成本核算的標準化——你的平臺成本分攤也需要同等的嚴謹性）；**選擇採購方所熟悉的計量單位思考**（採購方購買的是"診療事件"，而非"vCPU"）；以及將單位成本作為權威的成本分母，輸入到每一個[ICER](../增量成本效果比/)和[預算影響](../預算影響分析/)模型之中。對於AI功能而言，計量單位是令牌——參見[推理單位經濟學](../推理單位經濟學/)。

## 陷阱

- **忽視共享成本**：不含平臺/安全/待命值班分攤的單位成本，通常會低估30–50%，一經審計便會站不住腳。
- **虛榮分母**："每次API呼叫成本"看起來很好看；"每例已完成病患診療事件成本"才真正有資訊量。
- **對邊際決策採用平均成本定價**：對邊際上近乎免費的使用量向團隊按平均單位成本收費，會催生形式主義的"節支表演"（NHS版本的這一激勵機制缺陷，參見[全國統一收費標準](../全國統一收費標準與單位成本/)）。
