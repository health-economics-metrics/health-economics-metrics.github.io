# DORAメトリクス

DORA(DevOps Research and Assessment)メトリクスは、ソフトウェアデリバリーのパフォーマンスの4つの測定値です — デプロイ頻度、変更のリードタイム、変更失敗率、失敗したデプロイからの復旧時間、そして5つ目として信頼性。これらはこの分野で最も検証されたデリバリーのベンチマークであり、それぞれが医療経済学的な読み方を直接持っています。

## なぜ重要か

DORAの10年にわたる研究は、これらのメトリクスを組織のパフォーマンスに結びつけています。2024年のレポートのクラスター:**エリート**チームはオンデマンドでデプロイし(1日に複数回)、コミットから本番環境まで1日未満、変更の約5%が失敗し、1時間未満で復旧します;**低**パフォーマーは月1回以下のデプロイ、数か月かかり、約40%が失敗し、復旧に数週間かかります。医療システムにとって、これらは単なるITの見栄えの数字ではありません:それらは、臨床的価値が患者にどれだけ速く届くか、そして各変更がどれだけのリスクを伴うかを決定します。

## 数式

```
デプロイ頻度       = 本番デプロイ数 / 時間
変更のリードタイム = t(デプロイ) − t(コミット)、中央値
変更失敗率         = 失敗した変更数 / 総変更数 × 100
復旧時間(MTTR)    = t(復旧) − t(障害)、中央値
信頼性             = SLO達成度(可用性、レイテンシ、正確性)
```

医療経済学への翻訳:

```
リードタイム → 遅延コスト:パイプライン内の週数 × CoD(£またはQALY/週)
失敗率       → ソフトウェア変更の有害事象率:CFR × インシデント1件あたりの費用
復旧時間     → ダウンタイムの害:MTTR × (失われた臨床活動+安全性リスク)/時間
信頼性       → 便益の割引:可用性99%のサービスは、モデル化された便益の
              約0.99を提供する — これはアドヒアランスのソフトウェア版
```

## 計算例

あるトラストの患者フローソフトウェアチーム、デリバリーエンジニアリングへの投資の前後:

```
                    前          後
デプロイ            月次        週次
リードタイム        6週間       4日
CFR                 25%         8%
MTTR                2日         2時間
```

このチームは年間約30件の改善を出荷し、改善1件あたりの平均価値は週£4,000([CoD](../遅延コスト/))です。約5.4週間のリードタイム削減は、各改善の便益の流れを前倒しします:30 × 5.4 × 4,000 ≈ **年間£648,000**の価値がより早く届けられます。CFRの改善:30 × (0.25 − 0.08) = 年間約5件の失敗した変更の減少 × 平均インシデント費用£15,000(臨床システムのダウンタイム、修復)= **年間£76,500**。デリバリーへの投資は、あらゆる臨床介入と同じ通貨で評価されます。

## ソフトウェア工学との関連

これは*まさに*ソフトウェア側ですが、述べる価値のある関連は逆方向のマッピングです:DORAメトリクスは、別の衣をまとった病院の運用メトリクスです。リードタイム ↔ [紹介から治療まで](../紹介から治療まで/);変更失敗率 ↔ [再入院率](../再入院率/)(跳ね返ってきた作業);MTTR ↔ 緊急対応;デプロイ頻度 ↔ 診療所のスループット。改善の方法は双方向に転用できます。なぜなら、どちらも安全制約のもとでのキューイングシステムだからです。また、DORA 2025年のAIに関する発見にも注目してください:AIの採用は現在、より高いスループットと相関しますが、安定性は*悪化*します — これは有効性と副作用を持つ介入であり、まさにこのリポジトリが教える正味便益分析を要求します([AI開発者生産性](../ai開発者生産性/)を参照)。

## 落とし穴

- **メトリクスのごまかし**:デプロイ数は無意味なリリースで水増しされ、CFRはホットフィックスを失敗として数えないことで低く見せられます。HTAがエンドポイントを定義するのと同じように、イベントを正確に定義してください。
- **チーム横断のリーグテーブル**:DORAのクラスターは、異なるリスクプロファイルを持つチームではなく、実践を比較します;「高」にある臨床システムチームは、「エリート」が無謀であろう場所で最適かもしれません。
- **1つのメトリクスを最適化すること**:CFR/信頼性を伴わない速度は、スループットと安定性のトレードオフです — 常に4つを一緒に報告してください(それらはスコアではなく[費用結果表](../費用結果分析/)です)。
