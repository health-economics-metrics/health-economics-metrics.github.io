# 工作效率與活動受損量表 (Work Productivity and Activity Impairment, WPAI)

WPAI 是一份經過驗證的自評問卷（Reilly、Zbrozek、Dasbach，1993），用於衡量健康問題對有薪工作和日常活動的影響程度，通常針對過去 7 天。它把損失分成*缺勤*（absenteeism）——字面意義上損失的工作時間——和*出勤但效率下降*（presenteeism）——人在工作崗位上但生產率降低，後者通常是更大、更隱蔽的成本組成部分。

## 為什麼重要

簡單的病假天數統計只能看到缺勤。一位從不請假、卻因慢性疾病只有 60% 工作能力的醫師或知識工作者，不會給缺勤記錄增加任何內容，卻造成了巨大而真實的生產率損失——WPAI 正是為了讓這一隱形成本變得可見而設計的。由於它是經過驗證的工具，而不是臨時編制的調查，其得分可用於[病患報告結局](../病患報告結果/)證據包和疾病成本研究，評估者無需重新驗證該測量。作為一種自評工具，它本身就是 PROM 的一種形式，主要區別在於它關注工作和活動，而不是症狀或生活品質。

## 計算方法

```
缺勤 % = 因健康損失的小時數 / (因健康損失的小時數 + 實際工作小時數) × 100

出勤但效率下降 % = 工作時自評的受損程度 0–10 × 10
                  （直接取自問卷，此處不做推導）

工作總受損 % =
    缺勤% + (1 − 缺勤%/100) × 出勤效率下降%
    （把兩部分合並，使總和永遠不超過 100%）

生產率成本 = 工作總受損% / 100 × 該時期收入
```

總受損公式有意不是簡單的相加：直接把兩個百分比相加可能超過 100%，所以出勤效率下降只應用於工作時間中*剩餘*（未缺勤）的部分。

## 算例

一名偏頭痛病患排定每週工作 40 小時，但缺了其中 4 小時：

```
損失小時 = 4，工作小時 = 36
缺勤% = 4 / (4 + 36) × 100 = 10%
```

他在 WPAI 問卷中另外把工作時對生產率的影響評為 10 分中的 3 分，即 `出勤效率下降% = 30%`（這一步是問卷的原始回答，不是由其他數位推導的）：

```
工作總受損% = 10 + (1 − 10/100) × 30
            = 10 + 0.9 × 30
            = 10 + 27
            = 37%
```

對於收入為 £800（每天 £160）的 5 天工作周：

```
生產率成本 = 37/100 × 800 = £296
```

請注意，樸素的病假天數統計只會記錄損失的 4 小時（10%）——把出勤效率下降這一組成部分計入後，真實受損程度幾乎是其三倍。

## 與軟體工程的關聯

這直接對應工程團隊的健康指標：

- **缺勤**就是病假和帶薪休假——可見、已被追蹤、也容易的那一部分。
- **出勤但效率下降**是倦怠或被上下文切換拖垮的工程師，每次站會都在，但以降低的產能工作——通常是更大、更隱蔽的成本，在人頭數或出勤資料中看不見。它轉而表現為 [DORA](../DORA指標/) 和[流程指標](../流動指標/)中吞吐量的下降，或對同一筆[技術債](../技術債務/)的解決變慢，而該債務的“利息”會讓受損程度更嚴重。
- 工程上的教訓與臨床上的相同：只測量缺勤並稱之為“生產率損失”，會系統性地低估真實成本，因為它漏掉了所有在場卻受損的人。

## 陷阱

- **自評中的回憶偏差。** 7 天的回憶視窗與任何回顧性自評一樣，受到相同的報告失真影響。
- **把 0–10 量表當作真實的物理測量。** 它是由自評得出的有序量表，不是經過驗證的物理量——把其上的差值嚴格地當作線性或等距量表，是建模的便利，而不是經過驗證的物理事實。
- **在 WPAI 各變體之間彙總得分。** WPAI 有多個針對特定情形的版本——WPAI:GH（總體健康）、WPAI:SHP（特定健康問題）以及針對具體疾病的變體——在沒有先核實它們是同一工具版本之前，不同變體的得分不應彙總或比較。
