# Юнит-экономика облака (FinOps)

Юнит-экономика облака переводит валовые расходы на облако в **стоимость на единицу результата** — на клиента, на транзакцию, на решённый случай, на токен. Это возможность FinOps, которая превращает «наш счёт AWS — £400 тыс/месяц» в «обслуживание одного пациента стоит £0,83».

## Почему это важно

Цифры общих расходов не могут ответить на вопросы, которые имеют значение: становится ли продукт более или менее эффективным? Улучшает ли рост маржу или разрушает её? Что нам следует взимать? Удельные затраты отвечают на все три. Для цифрового здравоохранения в частности, «стоимость на решённый случай» *является* удельной стоимостью услуги здравоохранения — напрямую сопоставимой с цифрами [Национального сбора затрат](../национальный-тариф-и-удельные-затраты/), которые заказчик использует для любой другой услуги, что делает это естественным языком для оценки цифровых путей относительно традиционных.

## Расчёт

```
Удельная стоимость = общая распределённая стоимость (вкл. общие расходы/расходы платформы) / доставленные единицы

Два семейства:
  единицы эффективности ресурсов: стоимость/ГБ хранения, стоимость/час-vCPU, стоимость/токен,
                             стоимость/минуту сборки
  бизнес-единицы:            стоимость/клиент, стоимость/транзакцию, стоимость/консультацию,
                             стоимость/решённый случай

Применяется дисциплина предельных против средних затрат (marginal-vs-average-cost.md):
зафиксированные/зарезервированные расходы делают предельную удельную стоимость ≈ 0 до
следующего шага обязательства — оценивайте решения о расширении по предельным затратам,
тренды эффективности — по средним.
```

## Разобранный пример

Служба цифровой триажировки: расходы на облако £62 000/месяц (вычисления £30 тыс, данные £18 тыс, распределение общей платформы £14 тыс), обрабатывающая 380 000 эпизодов триажа/месяц:

```
Средняя стоимость на эпизод = 62 000 / 380 000 ≈ £0,163

Сравнение заказчика: телефонный триаж ≈ £8–12/звонок, консультация семейного врача ≈ £42
→ цифровой эпизод работает на ~2% от самой дешёвой человеческой альтернативы — экономика
смены канала из gds-service-metrics.md, со стороны затрат.

Проверка тренда: в прошлом году £0,21/эпизод при 240 тыс эпизодов → улучшающаяся
экономика масштаба (амортизация фиксированных затрат платформы), заслуживает заголовка в квартальном обзоре.
```

## Связь с программной инженерией

Юнит-экономика — это то место, где инженерные решения становятся финансово читаемыми: архитектура, вдвое сокращающая стоимость-на-эпизод, — это ценовое преимущество; та, что масштабируется сверхлинейно, — это бомба замедленного действия, видимая только в этой метрике. Практики, переносимые из здравоохранительного расчёта затрат: **публикуйте правила распределения** (общие расходы искажали удельные цифры, пока PLICS не стандартизировал расчёт затрат на уровне пациента — распределение затрат вашей платформы нуждается в той же строгости); **выбирайте единицы, в которых думает покупатель** (заказчики покупают эпизоды, а не vCPU); и вводите удельные затраты в каждую модель [ИКЭЭ](../инкрементальный-коэффициент-экономической-эффективности/) и [бюджетного воздействия](../анализ-бюджетного-воздействия/) как авторитетный знаменатель стоимости. Для функций ИИ единица — токен — см. [юнит-экономику вывода](../юнит-экономика-вывода/).

## Подводные камни

- **Игнорирование общих затрат**: удельные затраты, исключающие распределение платформы/безопасности/дежурства, занижают на 30-50% и рушатся при аудите.
- **Тщеславные знаменатели**: «стоимость на вызов API» льстит; «стоимость на завершённый эпизод пациента» информирует.
- **Ценообразование по средней стоимости для предельных решений**: выставление командам средней удельной стоимости за использование, которое предельно бесплатно, порождает театр избегания расточительства (см. [национальный тариф](../национальный-тариф-и-удельные-затраты/) для версии этой ошибки стимулирования в NHS).
