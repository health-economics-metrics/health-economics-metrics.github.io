# 便益実現

便益実現管理(BRM)とは、ビジネスケースで約束された便益が提供後に実際に実現したことを特定し、基準値を設定し、追跡し、*証拠づける*という規律です。英国の公共投資では、これはHM財務省のグリーンブックの**5ケースモデル**の中に存在します;医療では、その親戚は市販後調査です。

## なぜ重要か

ビジネスケースは約束であり、便益実現は監査です。主要なNHSデジタルプログラムの評価は、繰り返し、決して実現しなかった予測された便益を発見しました — そして便益が現金化可能でなかった場合、それはトラストの収支に何ももたらしませんでした。グリーンブックの対応:あらゆる支出ケースは**5つのケース**(戦略的、経済的、商業的、財務的、管理的)をクリアしなければならず、便益実現は*承認前*に管理ケースの中で計画されます — 責任者が名指しされ、基準値が記録され、測定日が設定されます。これなしでは、「このソフトウェアは看護師1人あたり30分を節約した」は永遠にベンダーのフィクションのままです。

## 数式

```
実現率 = 実現した便益 / 予測された便益   (便益ごと、期間ごと)

計算可能にする仕組み:
  基準値は稼働開始「前」に記録される(そうでなければ差は測定不能)
  各便益:責任者、メトリクス、データソース、測定スケジュール
  評価時に楽観バイアスで調整された予測(グリーンブックの義務)
  現金/非現金/定性的に分類され別々に追跡される便益
  (現金化可能な節約と非現金化節約を参照)
```

## 計算例

あるeローステリングのビジネスケースは、年間で以下を約束していました:£450,000の派遣支出削減(現金)、8,000病棟管理者時間(容量)、改善された充足率コンプライアンス(定性的)。稼働開始から12か月後:

```
便益              予測         実現         率     証拠
派遣支出          £450,000     £287,000     64%    基準年に対する台帳
管理者時間        8,000        5,100        64%    タイムモーションサンプル
充足コンプライアンス +10pp       +12pp        120%   ローステリングシステムのデータ

レビューからのアクション(これがBRMの要点):
派遣の不足分は、オンボーディングされていない2つの病棟に遡った → それらをオンボーディングする;
予測モデルの30%の楽観バイアスの誤りが記録された → 次のケースに適用される。
```

64%の実現は失敗ではなく — *知識*です。測定されないケースは永遠に100%を主張します。

## ソフトウェア工学との関連

エンジニアリング組織は、予測された便益に基づいてプラットフォームへの投資を承認しますが、それを監査することはほとんどありません — これはまさにBRMが修正する病理です。軽量な移植版:一定の閾値を超えるすべての提案は、便益の責任者、基準メトリクス、T+6か月のレビュー日を名指しします;実現率は、組織がそのチーム(あるいはベンダー)の次の予測をどれだけ割り引くかにフィードバックされます。これはまた、AIツールへの懐疑論への答えでもあります:[GenAIパイロットの約95%が損益計算書上で測定可能なリターンを示さなかったというMITの発見](../ai-return-on-investment/)は便益実現の結果です — 実際にリターンをもたらしたパイロットは、追跡可能で所有者のいる便益項目を持っていました。予測→測定→再較正は、ポートフォリオ規模で実行される[EVPI](../expected-value-of-perfect-information/)で価格設定されたパイロット試験と同じループです。

## 落とし穴

- **稼働開始前の基準値がないこと** — 致命的で修復不可能な見落としです。
- **便益の孤児化**:名指しされた責任者がいなければ、誰もデータを集めず、すべてのレビューが「おおむね順調」と言います。
- 同じ解放された容量を主張する**プログラム間での便益の二重計上** — ポートフォリオ全体にわたる便益登録簿を保持してください。
- **実現の茶番**:簡単な定性的な成功を測定する一方で、現金の項目は静かに検証されないままです。
