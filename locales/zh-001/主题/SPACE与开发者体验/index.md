# SPACE与开发者体验（DevEx）

SPACE（满意度与幸福感、绩效、活动量、沟通与协作、效率与流动）与DevEx（反馈循环、认知负荷、心流状态）是用于**多维度**衡量开发者生产力的框架——这是该领域对"没有任何单一指标能经受住现实检验"这一发现的回应。

## 为何重要

这两套框架都体现了健康结果研究早在数十年前就艰难习得的同一条教训：单一数字（代码行数、血压）无法真实反映多维度的现实，而对其进行优化只会催生操纵行为，而非真正的改进。SPACE要求至少组合三个维度的指标，同时混合遥测数据与自我报告——这在结构上与[EQ-5D](../EQ-5D/)在计算任何指数之前先对五个维度分别刻画完全相同，也正是[PROM](../患者报告结果/)之所以与临床测量并存的原因。满意度/幸福感同样绝非软性点缀——它直接影响[人才留任](../人才留任/)经济学，而人才流失的代价正是以负荷薪资的月数来定价的。

## 计算方法

这两套框架都不是公式，而是测量设计：

```
SPACE原则：至少涵盖3个维度，至少1项感知类（调查）指标 + 至少1项系统类（遥测）指标

DevEx各维度及示例配对：
  反馈循环   → CI耗时（遥测）+ "等待感觉很慢"（调查）
  认知负荷   → 文档可查找性、入职耗时 + 主观感受的费力程度
  心流状态   → 会议/打断密度 + 自我报告的专注度

衍生指数（例如DX公司的DXI）将调查复合指标映射为时间：
供应商主张约为每个指数点相当于每名开发者每周13分钟——
应将其视为一个需要在本地验证的供应商基准，而非一条自然常数。
```

## 实例演算

某平台团队为300名开发者论证一项DevEx投资（CI提速+文档改造）的合理性：

```
基线：CI耗时p75 = 28分钟；调查"我在等待构建时会失去专注"：62%表示同意
改进后：CI耗时p75 = 9分钟；同意比例降至24%

回收的时间（遥测数据）：每天6次构建 × 19分钟 × 0.4可用系数 = 每名开发者每天约45分钟
产能价值：300 × 0.75小时 × 220天 × £60/小时 ≈ 每年£297万（非现金释放型——
参见cash-releasing-vs-non-cash-releasing.md；这里的0.4可用性系数，正是
practitioner-time.md中所述的碎片化折扣）
感知层面的印证，正是让遥测数据主张变得可信的关键——单独使用其中任何
一种都容易被操纵；二者结合，才能形成相互印证的三角验证。
```

## 与软件工程的联系

这份文档本身*就属于*软件的一侧；而真正值得指出的迁移方向，反倒是流向健康经济学。一个"质量调整工程师年"——按标准化体验指数加权的时间——正是[QALY](../质量调整生命年/)的构造方式应用到工程产能上的体现，它也继承了QALY的规则：权重必须来自经过验证的量表工具（一致的调查、已公布的计分方法），并且必须在比较*之前*就先行确定，绝不能事后调整以美化某个偏好的工具。[SF-6D与EQ-5D](../EQ-5D/)之间的教训同样适用：不同的量表工具会系统性地给出不同的数字，因此绝不应跨越不同供应商的量表工具去比较DevEx指数。

## 陷阱

- **压缩为单一指标**：把SPACE压缩成一个单一分数的仪表盘，恰恰重新制造了这套框架本想防止的问题。
- **将活动量指标当作结果**：提交次数、PR数量与故事点，都属于"活动量"维度——而SPACE明确警示，这正是最容易被操纵的维度（健康领域的对应类比：统计做了多少次手术，而非统计康复了多少人）。
- **调查疲劳与霍桑效应**：轻量级的季度调查工具，效果优于每周一次的高强度问询。
- **团队之间的比较**：就像未经病例组合调整的医院排行榜一样——领域差异、历史遗留负担、待命值班等情境差异，往往起着主导作用。
