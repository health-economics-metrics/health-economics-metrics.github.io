# 成本後果分析（CCA）

成本後果分析將成本與一份**未經聚合的全結果分解表**並列呈現——臨床、營運、體驗各方面的結果都獨立列出，而不將其壓縮為單一比值或分數。決策者需明確地對各項權衡取捨進行判斷。

## 為何重要

在NICE的證據標準框架下，成本後果分析是**大多數數位健康技術的首選經濟學呈現格式**。數位化產品往往產生多種異質性效果（節省時間、滿意度、爽約率下降、微小的臨床獲益），這些效果很難誠實地聚合為單一的QALY數位。成本後果分析不強行構造一個脆弱的複合指標，而是展示完整的賬目清單。對於大多數軟體商業案例而言，這既是最誠實的呈現格式，也是最具說服力的格式，因為每一位利益相關方都能在其中找到與自己決策相關的那一行。

## 計算方法

這裡刻意不設聚合公式。輸出結果是一張表：

```
                          介入方案      對照方案     差值
成本（年度）               £X            £Y          ΔC
結果1（自然單位）           …             …           Δ1
結果2                      …             …           Δ2
定性結果                    以文字描述，不打分
```

每一行都保留其自身的計量單位。規則如下：所有結果指標須事先設定（不得在結果出來後再挑揀有利資料）；應全程保持相同的[視角](../分析視角/)與[時間範圍](../時間範圍/)；每一行都需報告其不確定性。

## 實例演算

某信託機構的數位化術前評估平臺，對比電話評估流程，按年度計算：

```
                              數位化平臺    電話流程     差值
營運成本                       £180,000      £95,000      +£85,000
護士評估工時                   6,200         11,800       −5,600小時
當日手術取消例數                92            174          −82
病患滿意度（CSAT）              4.5/5         3.9/5        +0.6
評估遺漏/未完成率                1.2%          4.8%         −3.6個百分點
```

沒有單一分數——但這份資料足以讓決策變得清晰易懂：£85,000換來了5,600護士工時（約合£15/小時，遠低於任何用人成本）、82例被避免的手術取消（每例都會浪費一個價值約£1,200的手術室時段），以及更好的病患體驗。委員會同樣能清楚看到這份方案*沒有*提供的東西：沒有主張任何QALY或死亡率方面的效果。

## 與軟體工程的聯絡

成本後果分析正是一份優秀平臺提案早已在使用的"平衡計分卡"的正式版本：成本與DORA指標、DevEx開發者體驗分數、事件數量並列呈現——不作聚合。值得補充的健康經濟學紀律是：**事先設定好所有行專案**（在試點開始前就決定哪些指標算數，這樣你就無法在某項指標變差後悄悄將其剔除），以及**展示不利的行專案**——一份只有好訊息的成本後果分析報告，不過是行銷材料。當不存在站得住腳的複合指標時（對開發者工具而言，這幾乎總是如此），就應使用成本後果分析。

## 陷阱

- **挑揀有利結果**——這一格式的公信力完全依賴於事先設定。
- **偷偷夾帶聚合**：顏色編碼或"總體評分"會重新引入成本後果分析原本旨在避免的那種武斷權重。
- **決策癱瘓**：成本後果分析需要一位願意權衡取捨的決策者；應搭配一條明確的建議及其推理過程。
