# WSJFとCD3

CD3(期間で割った遅延コスト)とWSJF(加重最短ジョブ優先)は、**価値密度**によって作業をスケジューリングする優先順位付けのルールです:希少な容量の単位消費あたり、どれだけの遅延コストが取り除かれるか。共有された固定容量のもとでは、CD3が最も高いものを先に行うことが、総遅延コストを最小化するための数学的に最適な順序です。

## なぜ重要か

あらゆるバックログは配給の問題です:価値のある項目は多く、パイプラインは1つ。医療経済学は、費用効果のリーグテーブルによって医療予算について同じ問題を解決しました — £1あたりの健康の獲得で介入を順位付けし、予算が尽きるまでリストを下って資金提供します。CD3はデリバリー容量にとって同一のロジックです:*制約となる資源*の単位あたりの便益を、順位順に資金提供します。順序を正しくすることは無料のお金です — 同じ作業、同じ容量、より少ない総遅延コストです。

## 数式

```
CD3  = 遅延コスト(£/週) / 期間(週)      — 実際の単位(Black Swan Farming)

WSJF = (利用者/ビジネス価値 + 時間的緊急性 + リスク削減/機会の
        実現) / ジョブサイズ            — SAFeの相対スケールの代理指標、
                                        修正フィボナッチスコア
```

本物の通貨([遅延コスト](../cost-of-delay/))を用いたCD3は、WSJFの単位のないポイントよりも厳密に強力です — WSJFはCD3に対して、多基準スコアリングが完全な[費用効用分析](../cost-utility-analysis/)に対するようなものです:金銭化が実用的でないときに使えますが、スコアに基準点がなければごまかせます。

## 計算例

3つの機能、1つのチーム:

```
機能   CoD(£/週)    期間      CD3
A      30,000       10週      3,000
B      12,000       2週       6,000
C      5,000        1週       5,000
```

CD3の順序:B、C、A。「最大CoDを先に」(A、B、C)と総遅延コストを比較してください:

```
CD3順序  (B,C,A):Aは3週待ち、Cは2週待つ → 30k×3 + 5k×2  = £10万の遅延コスト
CoD順序  (A,B,C):Bは10週、Cは12週待つ    → 12k×10 + 5k×12 = £18万
```

同じ機能、同じチーム — 順序付けだけで£80,000を節約します。直感:小さく緊急な項目を先に行うのは、それらが安価に遅延コストを解放するからです;大きな項目は少し待たされても失うものはわずかです。

## ソフトウェア工学との関連

ヘルスケアソフトウェアのポートフォリオでは、CoDをこのリポジトリが教える単位で表してください:QALY/週×閾値+運用上の£/週、そうすればバックログは、医療システムが購入する他のすべてを順位付けする方法と直接比較可能になります。2つの実践上の注意点:(1)期間とは*制約を占有する暦時間*を意味し、労力ではありません — ボトルネックチームの2日を必要とする経過2週間の項目は、見た目よりも安いです([下流のリソース最適化](../downstream-resource-optimization/)を参照);(2)病院は、緊急度で重み付けされたスループットで手術室リストを順序付けするとき、暗黙のうちに同じルールを運用しています — 臨床的な優先順位付けのカテゴリーは重症度で重み付けされたCD3です([QALY不足分と重症度修正因子](../qaly-shortfall-and-severity-modifiers/)を参照)。

## 落とし穴

- **WSJFスコアの茶番**:単位のないフィボナッチの議論は、最も声の大きい者に収束します;少なくともバックログの上位項目は実際のCoDに基準点を置いてください。
- **期間のごまかし**:CD3の順位を膨らませるために項目を分割すること — 分割が独立して価値を届ける場合は問題ありませんが、そうでない場合は不正です。
- **緊急性のプロファイルを無視すること**:締め切り型のCoD(規制上の日付)は定常率の仮定を崩します;それらは日付の実現可能性でスケジュールし、残りをCD3してください。
- **再順位付けの churn**:CD3はコミット時点での順序付けの意思決定のためのものであり、進行中の作業の日々の入れ替えのためではありません(WIPについては[フローメトリクス](../flow-metrics/)を参照)。
