# NICE证据标准框架（ESF）

ESF是NICE的一套框架，规定了**一项数字健康技术需要与其风险相称的多少证据**。它是对"在NHS采购我们的应用之前，我们必须证明什么？"这一问题最接近官方答案的存在。

## 为何重要

ESF（首次发布于2019年，2022年更新以涵盖AI与自适应算法）按临床功能将数字健康技术划分为不同层级，并要求提供**累进式**的证据标准——共5大类21项标准（设计要素、价值、性能/效果、经济影响、部署）：

```
A层 —— 系统服务类，无直接患者结果（例如电子排班）
       → 基本标准：可信度、数据保护、技术保障
B层 —— 提供信息、简单监测、沟通类（例如症状日记）
       → 在A层基础上加：用户获益证据、适当的可靠性
C层 —— 治疗、诊断，或主动引导临床管理
       → 在B层基础上加：高质量的对照效果证据（理想情况下为随机对照试验）
         以及经济学分析
```

对于经济学证据，[成本后果分析](../成本后果分析/)对大多数层级而言已属可接受；而在风险最高的层级，则需要[成本效用分析](../成本效用分析/)。ESF界定的正是你**进入市场所需的证据成本**——应像对待任何其他建设成本一样，为其编列预算。

## 计算方法

没有公式——这是一张决策表。真正起作用的计算属于商业范畴：

```
所需证据投入 = f(层级)
  A层：文档记录 + 保障措施 ≈ £10,000–50,000
  B层：观察性/对照性用户获益研究 ≈ £50,000–250,000
  C层：随机对照试验级别的对照研究 + 经济学模型 ≈ £250,000–£200万以上

应审慎地定位你产品的宣传主张：声称"支持临床决策"而非
"为患者提供信息"，会使你被划入更高一级，账单可能因此升高10倍。
```

## 实例演算

某用药提醒应用的开发方，考虑加入一项剂量调整建议功能。

- 作为纯提醒类应用：**B层**——一项显示依从性改善的队列研究即已足够。
- 若加入剂量建议：**C层**——需要对照效果证据（很可能是与常规照护对比的随机对照试验），外加经济学分析。

如果该随机对照试验成本为£600,000，而剂量功能带来的增量收入为每年£200,000，那么该功能必须持续创造价值3年以上，证据成本才能收支平衡——一旦将ESF层级成本计入考量，这项产品决策看起来就会完全不同。许多团队会先交付B层产品，把C层的宣传主张暂时搁置，等待资金到位后再补上。

## 与软件工程的联系

ESF是本书中最具可迁移性的单一治理模式：**按风险分级的工具采纳证据要求**。其内部版本是：一个代码格式化工具只需要一次演示（A层）；一个声称节省工时的生产力工具需要一次经过测量的试点（B层）；一个能自动阻止部署、或自动编写临床代码的AI关卡，在全组织推广之前，需要达到对照试验级别的证据（C层）。相称的证据要求能同时阻止两种失败模式——官僚主义扼杀无关紧要的小工具，以及仅凭感觉就推出影响重大的工具。另见[DiGA快速通道](../德国DiGA快速通道/)，作为"附带证据截止期的临时采纳"这一互补机制。

## 陷阱

- **出于一厢情愿而误判层级**——监管者与采购方是根据产品*实际做什么*来分类的，而非根据营销宣传怎么说。
- **在产品之后才补建证据**：在一个已上线、且未预先埋点或未保持均势状态的产品上事后补做随机对照试验，既缓慢又往往根本不可能。
- **满足了ESF却忽视了其余要求**：ESF与DTAC（临床安全、数据保护、互操作性）并行存在，对于AI而言还需另加监管审批——参见[AI监管评估](../AI监管评估/)。
