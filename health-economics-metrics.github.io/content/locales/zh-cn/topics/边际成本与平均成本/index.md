# 边际成本与平均成本 (Marginal vs Average Cost)

平均成本是总成本除以产出单位数。边际成本是多生产一个*额外*单位的成本。决策应当依据边际成本作出——但公开发布的单位成本几乎总是平均值。

## 为什么重要

数字健康商业论证中最常见的错误，就是按**平均**成本为一项被节省的资源估值，而真实的节省其实是**边际**成本。一个住院床位天的平均（全额分摊）成本超过£400，但释放一个床位天并不能节省£400——建筑、供暖以及大部分人员成本仍会继续发生。除非释放的床位足够多到可以关闭一个病房，否则实际释放出来的现金可能只有£50–£150。

## 计算方法

```
平均成本：  AC = TC / Q
边际成本：  MC = dTC/dQ   （多一个/少一个单位的成本）

TC = 总成本，Q = 数量
```

固定成本会使产能缩减时的MC低于AC，在存在闲置产能的情况下MC甚至可以趋近于零。节省主张应当使用：

```
真实节省 = ΔQ × MC          （小幅变化）
真实节省 = TC的阶跃变化      （跨越产能门槛的大幅变化，例如关闭一个病房）
```

## 算例

你的软件缩短了平均住院时长，为某信托机构每年释放1,000个床位天。

- **朴素的主张**：1,000 × £400平均成本 = **节省£400,000**。错误。
- **边际主张**：每个床位天的变动成本（餐食、洗涤、耗材、部分弹性护理人力）约为£120。节省 = 1,000 × £120 = **£120,000**，*外加*若这些床位被等候中的择期患者回填所带来的价值（按活动量付费机制下的收入，或候诊名单的缩减）。
- **阶跃变化主张**：如果该信托机构每年释放7,300个床位天（相当于一个20张床位的病房），就能真正关闭该病房：人员及运营成本合计约为£150万/年的真实现金。此时平均成本的算法就更接近真实情况了。

同一项干预措施，却有三个都站得住脚的数字，区别就在于这一变化是否跨越了一个产能阶梯。

## 与软件工程的关联

云经济学是边际成本思维的天然领地：

- 在已预留产能上多跑一次CI，其边际成本约为£0，而每次运行的平均成本（平台总支出 ÷ 运行次数）可能高达数英镑。按平均成本计费的转嫁系统，会促使团队回避使用那些在边际上实际免费的共享产能。
- 反过来，"我们节省了30%的算力"只有在实例被真正终止、或预留额度被真正削减时才能释放现金——这是软件版的床位天陷阱。参见[现金释放型与非现金释放型节省](../现金释放型-vs-非现金释放型节约/)。

## 常见陷阱

- **按平均成本为产能估值，并将其呈现为现金**（这是最经典的错误）。
- **假设边际成本恒定不变。** 它会在产能边界处发生阶跃（病房关闭、许可证层级、预留实例承诺）。
- **在同一份商业论证中，扩张决策用边际成本、收缩决策用平均成本**——应根据实际决策的性质来选用。
