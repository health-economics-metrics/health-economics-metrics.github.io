# 流程指标 (Flow Metrics)

流程指标衡量工作在交付系统中的流动方式:周期时间、前置时间、吞吐量、在制品 (WIP) 以及流动效率。它们受利特尔法则 (Little's Law) 支配——正是支配医院床位与等候名单的那套排队论数学。

## 为什么重要

大多数交付时间并非用于工作本身,而是用于等待。针对知识工作的流动效率研究反复发现,工作项在其经过时间中仅有 **5–15%** 处于被实际处理状态;其余都是排队。这意味着最廉价的加速手段是消除队列,而不是增加人手——这与医院患者流程改进项目在病床问题上得出的洞见完全一致。对于任何存在[延迟成本](../延迟成本/)的场景,流程指标能定位延迟成本累积的确切位置。

## 计算方法

```
周期时间   = t(完成) − t(开始)
前置时间   = t(交付) − t(请求)     (包含开始前的排队)
吞吐量     = 已完成项数 / 周期
WIP        = 已开始但尚未完成的项数
流动效率   = 活跃时间 / (活跃时间 + 等待时间) × 100

利特尔法则:平均 WIP = 吞吐量 × 平均周期时间
           (等价地:周期时间 = WIP / 吞吐量)
```

利特尔法则是关键杠杆:在吞吐量固定的情况下,削减 WIP 会按比例缩短周期时间。它同样支配着医院:`占用床位数 = 每日入院数 × 住院时长`。

## 实例演算

某团队有 40 个在制项,每周完成 10 个:周期时间 = 40/10 = 4 周。他们实施 WIP 限制,将 WIP 削减至 15:周期时间 = 15/10 = **1.5 周**——同样的人员,同样的吞吐量,交付速度提升 62%,完全来自队列纪律的改进。

用 CoD 定价:若工作项平均每周延迟成本为 3,000 英镑,每个工作项现在在队列中少停留 2.5 周:10 项/周 × 2.5 × 3,000 = **每周消除 75,000 英镑的延迟成本**——而这来自一次不花一分钱的政策调整。

医院镜像:每天 40 例入院 × 6.0 天住院时长 (LOS) = 240 张床位;将 LOS 中的非临床等待时间削减至 5.6 天,即可释放 16 张床位([住院时长](../住院时长/))——同一法则,同一杠杆。

## 与软件工程的关联

流程指标是交付工程与医疗运营之间的共通语言:

- **PR 各子阶段基准**(LinearB,约 800 万个 PR 样本):卓越水平的接单时间 < 7 小时,评审 < 6 小时,总周期 < 约 26 小时——接单时间纯属排队,是首先要攻克的环节。
- **[等候名单](../候诊名单影响/)**即积压;**[RTT](../转诊至治疗/)**即前置时间;**[床位占用率](../节省的床位天数/)**即 WIP。改进方法可双向迁移:WIP 限制 ↔ 入院平滑化;排队时间埋点 ↔ 路径阶段跟踪。
- 流动效率低于 15% 在两个领域都很常见,而两者都容易掩盖这一点,因为*人*很忙,而*工作*在等待——应测量工作本身的时钟,而不是工作者的时钟。

## 常见误区

- **崇拜利用率**:将工作者利用率推向 100% 会使排队时间呈非线性爆炸式增长(M/M/1 模型:等待时间 ∝ ρ/(1−ρ))——这正是占用率 95% 的医院陷入僵局、分配率 95% 的团队停滞不前的原因。
- **对偏态分布使用平均值**:周期时间呈重尾分布;应使用百分位数(p85)预测,而非均值。
- **通过在上游拒绝工作来削减 WIP**,并称之为流动改进——需求并未消失,只是排到了测量边界之外(医院版本:救护车在急诊科外排队等候)。
