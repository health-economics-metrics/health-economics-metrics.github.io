# 时间周期 (Time Horizon)

时间周期是指一项分析计入成本与效果的时间跨度。它必须足够长，才能捕捉到被比较方案之间所有有意义的差异。

## 为什么重要

周期选得太短，就会错过晚发生的效益（预防）和晚发生的成本（维护）。周期选得过长，一切又都会被不确定性淹没。对于具有死亡率影响的治疗方案，卫生技术评估常常采用**终身**周期；[预算影响分析](../预算影响分析/)则刻意采用较短的 **1–5 年**周期，因为它要回答的问题是可负担性，而不是价值本身。时间周期是一项须明确声明的建模选择，而周期不匹配是操纵比较结果的一种经典手法。

## 计算方法

时间周期是任何评估中求和运算的上限：

```
净现值 = Σ (t = 0 … T) [ (效益_t − 成本_t) / (1 + r)^t ]

T = 时间周期（年）
r = 贴现率（参见 discounting-and-time-preference.md）
```

结果应连同所采用的时间周期一并报告，理想情况下应在多个不同周期下分别展示。

## 算例

某电子处方系统的实施成本为 £2 百万，年运行成本 £200,000。它每年避免的用药错误价值 £600,000（即避免伤害所对应的治疗成本）。

按周期计算的净效益（为清晰起见，未贴现）：

```
周期 1 年：  −2,000,000 − 200,000 + 600,000  = −£1,600,000
周期 3 年：  −2,000,000 + 3 × 400,000        = −£800,000
周期 5 年：  −2,000,000 + 5 × 400,000        =  £0
周期 10 年： −2,000,000 + 10 × 400,000       = +£2,000,000
```

在任何短于 5 年的周期下，该系统都"失败"；在 10 年周期下则"成功"。两者都不是真正的答案；诚实的报告应说明盈亏平衡点，并以系统的使用寿命（多久之后会被替换？）来论证所选周期的合理性。

## 与软件工程的关联

- **以一个冲刺周期来衡量的工具评估**，系统性地错过了学习曲线带来的初期下滑（成本前置）以及长期维护（成本后置）。在第 2 周就测量的 AI 编码助手试点，捕捉到的是新鲜感的高峰，而非稳态表现。
- **合同期限 ≠ 效益周期。** 一份 1 年期的 SaaS 合同，如果你合理预期会续约，仍然可以按 5 年周期来评估——但要明确说明这一点。
- **遗留系统替换的论证**应运行至旧系统可信的报废时点，而不是一个随意选取的整数年份。

## 陷阱

- **周期货比三家**：挑选能让自己偏好的方案胜出的那个周期。应在计算结果之前就预先登记所采用的周期。
- **同一比较中对不同方案采用不同周期。**
- **终身周期却不做贴现或不确定性分析**——第 30 年的效益按面值计算就是虚构。长周期应搭配[敏感性分析](../敏感性分析/)一起使用。
