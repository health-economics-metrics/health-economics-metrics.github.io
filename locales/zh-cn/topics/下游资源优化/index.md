# 下游资源优化 (Downstream Resource Optimization)

为一位资深从业者——全科医生 (GP)、高年资住院医师、或顾问医生 (consultant)——节省一小时,往往能避免整个多学科团队 (MDT) 中一批正在等待临床签核的护士、行政文员和治疗师陷入瓶颈延误。解除瓶颈的价值,等于其下游所有人的吞吐量之和。

## 为什么重要

医疗保健依赖层层授权链运转:出院要等顾问医生签核,治疗方案要等 MDT 评审,转诊要等分诊。当把关角色被延误时,代价并不只是那一个人的一小时——而是每一个依赖角色的闲置或受阻时间,再加上患者滞留的时间(额外的[住院床日](../节省的床位天数/)、更长的 [RTT 等待](../转诊至治疗/))。这正是约束理论 (theory of constraints) 在临床路径中的应用:在*约束点*节省的一小时,价值等于整个系统的边际吞吐量;在其他地方节省的一小时,价值则要小得多。

## 计算方法

```
解除瓶颈的价值 = Σ 下游各角色(释放的受阻工时 × 单位成本)
              + 路径吞吐量提升 × 每次路径完成的价值

对比:在非把关角色节省同样一小时的价值 ≈ 仅相当于该角色自身的
产能价值(参见 practitioner-time.md)
```

凭经验识别约束点:工作在哪里排队最久?延误最终都能追溯到谁的收件箱?

## 实例演算

某病区每天早上的出院都需要顾问医生审核。该顾问医生每天花 90 分钟整理散落在各系统中的信息;审核在 14:00 前完成,而每天有 6 例出院因太晚完成而无法当天处理——每一例都造成一个本可避免的住院床日。

一个出院摘要仪表盘(化验、用药、标记一览无余)将信息整理时间压缩到 20 分钟;审核在 11:30 前即可完成:

```
避免的住院床日   = 6 例延误出院中的 4 例 × 365 ≈ 每年 1,460 个床日
下游解除瓶颈:2 名出院协调员 + 药房 + 转运人员
             此前每天下午先闲置后突击——
             约每天 3 名员工-小时的受阻时间被释放 ≈ 每年 1,100 小时
```

顾问医生自己节省的 70 分钟,恰恰是价值中*最小*的一部分——这正是该指标的意义所在。按机制为床日计价(参见[节省的住院床日](../节省的床位天数/)),并将员工工时作为产能计价。

## 与软件工程的关联

这就是代码评审、架构签核,以及资深工程师的收件箱。当五名工程师为等待唯一能审批设计方案的那个人而耽误一天时,代价是五个工程师-天,再加上工作本身一天的[延迟成本](../延迟成本/)——而不是一个评审者-小时。能压缩把关角色任务耗时的工具(更好的评审上下文、自动化预检、为审批者整理所需信息的仪表盘)买到的是系统吞吐量,而不是个人便利。测量约束点处的接单/等待时间(参见[流程指标](../流程指标/))——这就是软件领域中 14:00 出院悬崖的等价物。

## 常见误区

- **优化非约束环节**:为一个后面无人排队等待的角色打造精美工具,几乎产生不了系统价值。
- **约束点迁移**:解除顾问医生的瓶颈后,约束点会转移(转到药房、转到转运)——在宣称获得完全吞吐量提升之前,要先为*下一个*约束点建模。
- **将下游工时当作现金计算**:受阻时间的释放属于产能,须经过通常的[再调配检验](../现金释放型-vs-非现金释放型节约/)。
