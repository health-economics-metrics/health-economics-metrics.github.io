# الهيمنة وحدود الكفاءة

يكون خيار **مُهيمَنًا عليه** إذا كان خيار آخر يكلّف أقل *ويقدّم* أكثر. **حدود الكفاءة** هي ما يبقى بعد استبعاد الخيارات المُهيمَن عليها: مجموعة الاختيارات التي يتطلّب فيها الحصول على المزيد دفع المزيد.

## لماذا يهم هذا

قبل أي نقاش حول العتبات أو الميزانيات، يستبعد تقييم التقنية الصحية أولًا الخيارات التي لا ينبغي لأحد اختيارها أبدًا. رسم كل خيار على مستوى التكلفة مقابل الأثر ورسم الحدود تمرين مدته خمس دقائق يقتل عادةً نصف القائمة المختصرة. المقارنات التزايدية ([نسب ICER](../نسبة-فعالية-التكلفة-التزايدية/)) تُحسَب بعد ذلك فقط *على طول الحدود*، كل خيار مقابل الخيار الأرخص التالي غير المُهيمَن عليه - أبدًا مقابل "لا تفعل شيئًا" عندما توجد خيارات وسيطة أفضل.

## طريقة الحساب

```
الهيمنة الصارمة:   A يهيمن على B إذا كانت التكلفة_A ≤ التكلفة_B والأثر_A ≥ الأثر_B
                    (مع تباين صارم واحد على الأقل)

الهيمنة الموسَّعة: B يُستبعَد إذا كان مزيج من A وC يحقّق أثرًا أكبر
                    لكل جنيه - يُكتشَف عندما تنخفض نسب ICER عند
                    الصعود على الحدود. نسب ICER الصحيحة للحدود يجب أن تتزايد.
```

الإجراء: رتِّب الخيارات بالأثر؛ استبعد المُهيمَن عليها صراحةً؛ احسب نسب ICER الزوجية بين المتجاورين؛ استبعد أي خيار تتجاوز نسبة ICER الخاصة به نسبة الخيار الأكثر فعالية التالي (الهيمنة الموسَّعة)؛ كرِّر حتى تتزايد نسب ICER بشكل رتيب.

## مثال محلول

أربعة خيارات لتخفيض المواعيد الفائتة (الأثر = مواعيد مُستعادة/سنة):

```
الخيار              التكلفة/سنة   المُستعاد
لا تفعل شيئًا        0£            0
تذكيرات SMS         20,000£       2,000
مكالمات هاتفية       120,000£      2,200
SMS + فرز بالذكاء الاصطناعي  90,000£  3,500
```

المكالمات الهاتفية **مُهيمَن عليها صراحةً** بواسطة SMS + الفرز بالذكاء الاصطناعي (تكلّف أكثر، تستعيد أقل). الحدود: لا شيء ← SMS ← SMS + الذكاء الاصطناعي.

```
ICER(SMS مقابل لا شيء)   = 20,000 / 2,000  = 10£ لكل موعد مُستعاد
ICER(SMS+الذكاء الاصطناعي مقابل SMS) = (90,000 − 20,000) / (3,500 − 2,000) = 46.67£ لكل موعد
```

نسب ICER متزايدة ← حدود صحيحة. عند ~160£ مُوفَّرة لكل موعد مستشفى مُستعاد (انظر [معدل عدم الحضور](../معدل-عدم-الحضور/))، كل خطوتَي الحدود تستحقان الاتخاذ؛ مقترح مركز المكالمات الهاتفية يجب ألا يبلغ اللجنة أبدًا.

## الصلة بهندسة البرمجيات

بناء نفس الرسم لأي قرار أدوات: التكلفة سنويًا على محور، النتيجة المقيسة (ساعات مُوفَّرة، حوادث مُتجنَّبة، نشرات مُمكَّنة) على المحور الآخر. النقاط أعلى ويسار الحدود تُستبعَد قبل أن يجادل أحد حول الميزانية. هذا يُعيد صياغة اختيار المورّدين من نقاشات قوائم المزايا إلى "أنت مُهيمَن عليك؛ انتهى الاجتماع." يفضح هذا أيضًا النمط المؤسسي الشائع لشراء الخيار الأغلى مقابل مكسب هامشي - مشروع فقط إذا كان السعر التزايدي لكل وحدة تزايدية سعرًا ستدفعه المنظمة عن علم.

## المزالق

- **مقارنة كل شيء بخط الأساس** بدلًا من الخيار التالي على الحدود - هذا يُجمِّل الخيارات المكلِفة بإخفاء أشباه معادلات أرخص.
- **نقاط أثر أحادية البُعد** تخفي ما يهم؛ إذا كانت نتيجتان تُحسَبان، اجمعهما بشكل مُبرَّر (انظر [تحليل التكلفة والمنفعة العامة](../تحليل-التكلفة-والمنفعة-العامة/)) أو أظهر حدَّين.
- **نسيان عدم اليقين**: خيارات قريبة من الحدود قد تتبادل الأماكن تحت [تحليل الحساسية](../تحليل-الحساسية/).
