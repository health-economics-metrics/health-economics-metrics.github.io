# النقاط النهائية والمؤشرات الحيوية الرقمية

المؤشر الحيوي الرقمي هو قياس فيزيولوجي أو سلوكي موضوعي يُجمَع عبر أجهزة استشعار (سرعة المشي من هاتف، أو النوم من جهاز قابل للارتداء، أو الرعاش من مقياس التسارع). والنقطة النهائية الرقمية هي مثل هذا القياس مرفوعًا إلى مرتبة **نتيجة تجربة** - يُستخدَم لإثبات أثر العلاج. الترقية من "بيانات يبثها الجهاز" إلى "دليل تقبله جهة تنظيمية" تمر عبر سُلَّم تحقق محدد.

## لماذا يهم هذا

النقاط النهائية التقليدية للتجارب متقطعة (زيارات عيادة كل 3 أشهر) ومكلفة؛ أما النقاط النهائية الرقمية فمستمرة، وبيئية (الحياة الواقعية، لا أداء العيادة)، ورخيصة لكل ملاحظة - يمكنها تقليص التجارب، واكتشاف الآثار أبكر، وتمكين الدراسات اللامركزية. المشكلة هي التحقق: الإطار المعتمَد (المتوافق مع FDA، ذو الركائز الثلاث) يتطلب **التحقق/التحقق التحليلي** (المستشعر يقيس الكمية الفيزيائية بدقة)، و**التحقق السريري** (القياس يعكس الحالة السريرية التي يدّعيها)، و**جانبًا صحيًا ذا معنى** مُثبَتًا (المرضى يهتمون بما يلتقطه). النقطة النهائية دون هذه الركائز الثلاث هي بيانات بث، لا دليل.

## الحساب

```
التحقق التحليلي: التوافق مع المرجع (انظر wearable-validation.md -
                       MAPE، وCCC، وBland-Altman)
التحقق السريري:   الارتباط/التمييز مقابل مراسٍ سريرية
                       (صلاحية المجموعات المعروفة، الاستجابة للتغير)
اقتصاديات النقطة النهائية:
  الأحداث المكتشَفة لكل مريض-سنة (مستمر) مقابل أخذ عينات لكل زيارة
  قوة التجربة: القياسات المستمرة تقلل حجم العينة عندما
  يهيمن التباين بين الزيارات - N ∝ σ²/Δ²، وσ² تنخفض مع أخذ العينات الكثيف
```

## مثال محلول

تجربة لمرض باركنسون تدرس سرعة المشي من مستشعر المعصم مقابل درجات تقييم ربع سنوية بالعيادة:

```
النقطة النهائية بالعيادة: 4 قياسات/مريض/سنة، ضوضاء عالية يوميًا
النقطة النهائية الرقمية: ~200 قياس سلبي/مريض/سنة

تباين تقدير التغير السنوي ينخفض ~5 أضعاف مع أخذ العينات الكثيف ←
حجم الأثر القابل للاكتشاف عند قوة ثابتة يتحسن ~√5 ≈ 2.2 ضعفًا، أو
بشكل مكافئ ينكمش حجم العينة ~40-60% لنفس الفرضية.
عند 25,000£ لكل مريض مُسجَّل، تقليص 200 مريض ≈ 5 ملايين£ موفَّرة
لكل تجربة - الحالة التجارية لاستثمار التحقق
(الذي قد يبلغ هو نفسه 1-2 مليون£) عبر خط أنابيب الراعي.
```

## الصلة بهندسة البرمجيات

النقاط النهائية الرقمية هي انضباط هندسة بيانات مرتدٍ ثوبًا سريريًا: **التتبع والإصدار** (تحديثات الخوارزمية في منتصف الدراسة تهدد قابلية المقارنة - مشكلة [PCCP](../التقييم-التنظيمي-للذكاء-الاصطناعي/) بصيغة تجريبية؛ ثبّت الإصدار وتحقق بالجسر)؛ **تصميم البيانات المفقودة** (فجوات وقت الارتداء ذات دلالة لا عشوائية - انظر [التحقق من الأجهزة القابلة للارتداء](../التحقق-من-الأجهزة-القابلة-للارتداء/)؛ خيارات الإسناد هي ادعاءات علمية)؛ و**قرارات تقسيم الحافة/السحابة** التي تغيّر ما يمكن استرجاعه من الإشارة الخام لاحقًا أصلًا. الفرق التي تعامل خط أنابيب القياس كبرمجيات خاضعة للتنظيم منذ اليوم الأول - مُختبَرة، ومُوثَّقة الإصدار، ومُوثَّقة - تشتري مصداقية نقاطها النهائية بثمن زهيد؛ وإعادة إدخال التحقق لاحقًا إلى خط أنابيب بُني بسرعة هو حيث تموت برامج النقاط النهائية الرقمية.

## المزالق

- **الارتباط بالعيادة كتحقق كامل**: مطابقة قياس عيادي معيب تثبت الوراثة لا الحقيقة؛ تحقق مقابل الجانب الصحي ذي المعنى.
- **مخاطر تنظيمية للنقطة النهائية الجديدة**: نقطة نهائية غير مسبوقة قد تكون متفوقة علميًا وتغرق التقديم مع ذلك - أشرك الجهات التنظيمية مبكرًا (برامج التأهيل موجودة).
- **عدم تطابق المستشعر مع السكان**: التحقق على معاصم شابة سليمة، والنشر على مرضى مسنين برعاش وفروق تصبّغ لم يرها مستشعر PPG قط.
- **انحراف الميزات**: إعادة تدريب خوارزمية المشي على بيانات جديدة يعيد تعريف النقطة النهائية بصمت في منتصف الدراسة.
