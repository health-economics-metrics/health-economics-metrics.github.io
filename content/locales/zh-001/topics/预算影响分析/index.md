# 预算影响分析（BIA）

预算影响分析（BIA）估算的是：采纳某项干预措施，在未来1–5年内会对特定支付方的**预算**产生怎样的影响。它回答的是*可负担性*问题；而成本效果分析回答的是*价值*问题。一项技术可能价值极高却难以负担——也可能容易负担却价值不高。严谨的评审二者都需要。

## 为何重要

财务总监从不会问"ICER是多少？"——他们问的是"这会对明年的预算造成什么影响？"ISPOR的良好实践指南（该领域的标准）明确规定：应采用支付方自身的视角、1–5年的时间范围、*未贴现*的年度现金流，以及切合实际的采纳曲线，并以情景分析（而非概率分析）方式处理不确定性。NICE要求在成本效果分析之外，同时提供预算影响信息；在英格兰，一款全国预算影响超过约£2,000万/年的产品，无论其ICER如何，都会触发商业谈判。

## 计算方法

```
预算影响_第t年 = 新方案情景成本(t) − 现行方案情景成本(t)

情景成本(t) = Σ 按患者群体求和：
   符合条件人群(t) × 采纳率(t) × 每名患者净成本(t)

每名患者净成本 = 干预成本 − 被替代的医疗成本 + 被诱发的医疗成本
```

关键建模选择包括：符合条件人群的增长、采纳曲线（采用从来都不是瞬时完成的）、新方案会替代掉哪些原有服务、以及它可能*诱发*的任何新增需求（更便捷的可及性 → 更多使用者）。

## 实例演算

某支付方覆盖200万人，考虑引入一款数字疗法，每名患者每年£300；符合条件成员占比1.5%（30,000人）；采纳率在三年内从20% → 40% → 60%；每名使用者会替代掉每年£120的其他医疗服务。

```
每名使用者净成本 = 300 − 120 = £180

第1年：30,000 × 0.20 × 180 = £108万
第2年：30,000 × 0.40 × 180 = £216万
第3年：30,000 × 0.60 × 180 = £324万
```

即便该产品的ICER表现优异，仅为£8,000/QALY，支付方到第3年仍必须找到£324万的*新增资金*——那被替代的£120被稀薄地分摊在其他各条预算科目之中，并不会以现金形式被释放出来（参见[现金释放型与非现金释放型](../现金释放型与非现金释放型节省/)）。这正是为什么单位价值与可负担性是两道彼此独立的门槛。

## 与软件工程的联系

BIA正好是面向CFO的、与"按席位计算的投资回报率主张"相对应的另一半："它按每名开发者计算具有成本效果，但我们今年财政年度内负担得起全组织铺开吗？"应对许可分级、采纳S型曲线、只有在旧合同真正终止时才会现金释放的被替代工具支出，以及被诱发的使用量（CI成本更低 → CI使用量更多）建模。在投资回报率之外附上一张为期3年的预算影响表，正是让一份企业级工具采购提案在财务上站得住脚的关键。 把已公布的预算影响数字按地点、人群或财年拆分——使各份与已公布数字恰好吻合——就是[精确到分的成本分摊](../精确到分的成本分摊/)；把汇入该总额的大量条目相加，则是[币种安全的成本汇总](../币种安全的成本汇总/)。

## 陷阱

- **瞬时采纳的幻想**：按稳态采纳水平计算第1年的影响。
- **将被替代的成本当作现金计算**，而实际上它只是被稀释分散的产能。
- **忽视被诱发的需求**——可及性的提升会增加符合条件人群本身的使用量。
- **混淆BIA与成本效果分析的时间范围/贴现方式**：BIA在设计上就是短期、不贴现、且特定于某一支付方的。
