# 自建与外购 (Build vs Buy)

自建与外购之争，是在贴现[总拥有成本（TCO）](../总拥有成本/)、交付时间与风险这几个维度上，对定制开发与商业采购进行的结构化比较。经验先验数据一边倒：**实际自建成本通常会超出预测30–40%**，外购方案的部署速度快40–60%，而MIT于2025年的GenAI研究发现，采购的AI工具成功率约为67%，而内部自建方案的成功率大约只有其三分之一。

## 为何重要

卫生系统时时刻刻都要面对这一抉择（在NHS的语境下称为"自制还是委托"（make vs commission）），而工程组织在这一抉择上系统性地偏向自建方向出错——因为搭建者估算的是"搭建"本身的成本，而非[总拥有成本（TCO）](../总拥有成本/)，也因为搭建这件事本身更有趣。经济学框架强制推行一种诚实的比较：两个选项都按同一时间跨度定价，都经过风险调整，并且*把时间差异按[延迟成本](../延迟成本/)定价*——这一项往往最终决定了答案，却也最常被遗漏。

## 计算方法

```
在同一个3–5年的时间跨度内、按贴现方式比较：

方案净现值 = PV(收益，按价值实现时点平移) − PV(总拥有成本)

风险调整（Green Book"乐观偏差"模式）：
  自建成本 × 1.3–1.4     （超支先验系数）
  自建的价值实现时间 + 40–60%  （部署延迟先验系数）
  外购：改为加入系统集成现实检验成本与退出成本

决策驱动因素，按通常起决定作用的顺序排列：
  1. 差异化程度——这项能力是你的产品本身，还是基础设施？
  2. 价值实现时间 × 延迟成本
  3. 经风险调整后的总拥有成本
```

## 实例演算

某信托机构需要一套电子知情同意系统。外购方案：SaaS每年£15万，3个月内上线。自建方案：预估£60万，另加每年£12万的维护费用，12个月内上线。

```
经风险调整的自建成本：60万 × 1.35 = £81万；价值实现时间约18个月
5年期总拥有成本：外购 = 15万 × 5 = £75万
                自建 = 81万 + 12万 × 5 = £141万
延迟项：知情同意数字化每月可节省£2.5万；自建方案晚15个月交付
        → 延迟成本 = 15 × 2.5万 = £37.5万

综合比较：£75万 对比 £178.5万——外购胜出约£100万，
而除自建成本本身之外，最大的单项成本，正是那笔此前无人计价的延迟成本。
```

当该能力具有差异化意义（属于你产品的核心算法）、没有任何供应商能满足某项硬性约束（临床安全、数据主权）、或供应商锁定风险严重且已被计价时，选择自建依然是正确的。

## 与软件工程的关联

可迁移的健康经济学纪律有三方面：**基于先验的风险调整**（那30–40%的超支上调系数，正是软件领域版的Green Book乐观偏差——应机械地应用它，为例外情形据理力争，而不是以例外情形为出发点）；**对照组的诚实性**（自建的替代方案不是"什么都不做"，而是当前最佳的可购买方案——参见[机会成本](../机会成本/)）；以及**在比较成本之前先做等效性检验**（如果外购与自建真正能满足同一规格要求，那么这就是[成本最小化分析](../成本最小化分析/)，更便宜的一方胜出；如果不能，那么结果上的差异必须被赋予价值，而不是凭空断言）。

## 常见陷阱

- **拿供应商标价与未经风险调整的自建估算相比较**——这是对自建方案的双重偏袒。
- **零成本计价的内部人力**（"反正团队本来就在"）。
- **双向都未计价的锁定风险**：供应商退出成本固然存在，但自建方案的"巴士系数"（bus-factor）与维护年限风险同样未被计价。
- **身份驱动型的自建决策**："这对我们至关重要"这一说法被用在了本质上只是基础设施的部分——应通过"客户是否会注意到差异"来检验其差异化程度是否成立。
