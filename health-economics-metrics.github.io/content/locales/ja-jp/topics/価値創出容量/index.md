# 価値創出容量(運用面の好転)

価値創出容量とは、解放された時間の「機会便益」のことです:あなたのソフトウェアが解放する時間で、病院が今や何を*達成できるか*ということです。これは最高執行責任者や医療部長にとって最も重要な指標です。なぜなら、それは彼らが管理されている通貨 — 活動、目標、ターンアラウンド — で語られるからです。

## なぜ重要か

NHSは巨大な紹介から治療までのバックログに直面しており、国の待機時間基準を逃すトラストは規制上の精査と介入に直面します([紹介から治療まで](../紹介から治療まで/)を参照)。採用は遅く制約されています;資産は固定されています。唯一の速いレバーは、既存のスタッフと空間からより多くの価値創出活動を引き出すことです。専門家の時間を取り戻すソフトウェアは単に「お金を節約する」だけではありません — それは*容量を鋳造*します:雇用や建設なしには存在できなかった診療所、スケジュールできなかった評価です。

## 数式

```
創出された隠れた容量 = 解放された時間 → 可能になった活動単位 × 制度上の価値

活動単位:外来受診、術前評価、モニタリングレビュー
制度上の価値:全国診療報酬/NHS Payment Schemeの価格
             (全国診療報酬と単位費用を参照)
```

これは、[医療従事者の時間](../医療従事者の時間/)のアウトプットベースの評価を、サービスラインに拡大し、運用チームがすでに計画に使っている活動単位で表現したものです。

## 計算例

バンド6の専門看護師が術前評価診療所を運営しています。文書作成の自動化により、25人の看護師それぞれについて1日1時間が取り戻されます;その1時間で2件の評価ができます。

```
追加の評価 = 25人の看護師 × 1日2件 × 250日 = 年間12,500件
術前評価1件あたり約£120の制度上の価値で:
  12,500 × £120 = 年間£150万のケア容量が創出される
```

— 看護師を1人も雇用せず、部屋を1つも建設せずにです。(このスタブが元々引用していた広く引用されるモデルは、より小さなコホートについて年間£766,920という数字を出していました;計算のパターンは同じです — この数字は看護師数×セッション数×診療報酬でスケールします。)COOにとっての運用上の枠組み:術前評価は手術室リストの制約であることをやめ — 当日キャンセルされる手術が減り、手術室の稼働率が上がります。これは*次の*便益項目が始まる場所です([下流のリソース最適化](../下流のリソース最適化/)を参照)。

## ソフトウェア工学との関連

同じ再構成が、開発者生産性の主張を賃金計算から救い出します:解放されたエンジニアリング時間を、*組織が他の方法では手が届かなかった出荷された機能* — 機能、移行、信頼性の作業 — として表現し、組織がそのような機能に限界的に支払う額(外部委託業者の料金、あるいは先延ばしにされた採用の等価物)で評価します。COOの枠組みはまた、プラットフォーム作業を売り込むことについても何かを教えてくれます:聴衆が管理されている単位で便益を表現してください。運用リーダーは抽象的な時間ではなく活動と目標で考えます;エンジニアリングリーダーは節約された分ではなく、ロードマップの項目と人員数で考えます。

## 落とし穴

- **需要のない容量の主張**:手術のパイプラインがそれらを埋めない限り、12,500件の追加評価枠は意味がありません — 下流の制約を確認してください。
- **支払いの仕組みのない診療報酬の価値**:混合支払いのもとでは、追加の活動が追加の収入をもたらさないことがあります;価値は代わりに待機リストの削減かもしれません([待機リストへの影響](../待機リストへの影響/)を参照)。
- **容量を現金として提示すること** — これは代表的な非現金化便益です;そのようにラベル付けしてください([現金化可能な節約と非現金化節約](../現金化可能な節約と非現金化節約/)を参照)。
