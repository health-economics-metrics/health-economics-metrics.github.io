# 贴现与时间偏好

贴现是将未来的成本与效益折算为现值的过程，因为今天获得的一份效益，其价值高于五年后获得的同样一份效益。

## 为何重要

每一份健康经济学评审、每一份严肃的公共部门商业论证，都会对跨越多年的现金流进行贴现。英国HM Treasury《绿皮书》强制规定年社会时间偏好率为3.5%；NICE的参考案例对成本与健康效果均按每年3.5%贴现（对于获益期超过30年以上的近乎治愈型疗法，则采用1.5%的非参考案例贴现率）。如果你的软件商业论证声称"10年内节省500万英镑"，财务评审人会立即要求你提供贴现后的数字。

## 计算方法

未来某笔金额的现值：

```
现值 = 未来值 / (1 + r)^t

现值 = 现在的价值
未来值 = 第t年的未来价值
r = 贴现率（NICE/《绿皮书》标准：0.035）
t = 距今年数
```

对于连续n年、每年恒定为B的效益（年金形式）：

```
现值 = B × [1 − (1 + r)^(−n)] / r
```

## 实例演算

你的软件为某NHS信托机构每年节省£100,000，为期5年，从上线后第一年开始。

未贴现总额：£500,000。

按3.5%贴现后：

```
第1年：100,000 / 1.035^1 = £96,618
第2年：100,000 / 1.035^2 = £93,351
第3年：100,000 / 1.035^3 = £90,194
第4年：100,000 / 1.035^4 = £87,144
第5年：100,000 / 1.035^5 = £84,197

现值合计 ≈ £451,505
```

诚实的头条数字约为£451,000，比朴素加总的数字低约10%。现在假设交付延迟一年：每一项的时点都推后一年，现值随之降至约£436,000——这正是[延迟成本](../延迟成本/)在贴现视角下的体现。

## 与软件工程的联系

- **技术债务偿还与平台迁移**承诺的往往是多年后才能兑现的效益流；在将其与本季度就能回本的工作相比较之前，应先对其进行贴现。
- **前期成本集中、效益后置**是迁移项目的典型形态。贴现会正确地惩罚这种形态：它为"现在投入产能、未来才能获得价值"这件事的无风险时间价值正确定了价。
- **"第5年才能节省"这类主张理应受到双重质疑**——它既会被大幅贴现，本身也高度不确定（参见[敏感性分析](../敏感性分析/)）。

## 陷阱

- **只对成本贴现而不对效益贴现**（或反之）——参考案例应对二者按相同的贴现率一并处理。
- **在公共部门案例中使用商业贴现率（8–12%）**，或在风险投资背景的案例中使用3.5%。贴现率应与决策者的实际情境相匹配。
- **将贴现与通货膨胀混为一谈。**贴现适用于*实际*（已经过通胀调整的）数值；不要在无意中同时进行两次调整。
