# クラウド単位経済学(FinOps)

クラウド単位経済学は、生のクラウド支出を**アウトプット単位あたりの費用**に変換します — 顧客あたり、取引あたり、解決された症例あたり、トークンあたり。これは、「AWSの請求額は月£40万」を「患者1人にサービスを提供する費用は£0.83」に変えるFinOpsの能力です。

## なぜ重要か

総支出の数字は、重要な問いに答えられません:製品はより効率的になっているのか、それとも非効率になっているのか?成長は利益率を改善するのか、破壊するのか?いくら請求すべきか?単位費用はこれら3つすべてに答えます。デジタルヘルスに特化して言えば、「解決された症例あたりの費用」は*まさに*医療サービスの単位費用です — コミッショナーが他のあらゆるサービスに使う[National Cost Collection](../national-tariff-and-unit-costs/)の数値と直接比較可能であり、これはデジタル経路を従来のものと比較して価格設定するための自然な言語にします。

## 数式

```
単位費用 = 配分された総費用(共有/プラットフォーム費用を含む) / 提供された単位数

2つの系統:
  リソース効率単位:GBあたり保存費用、vCPU時間あたり費用、トークンあたり費用、
                    ビルド分あたり費用
  ビジネス単位:      顧客あたり費用、取引あたり費用、診察あたり費用、
                    解決症例あたり費用

限界と平均の規律が適用される(限界費用と平均費用を参照):
コミット済み/予約済みの支出は、次のコミットメント段階まで限界単位費用を
ほぼゼロにします — 拡大の意思決定は限界費用で、効率のトレンドは平均費用で
価格設定してください。
```

## 計算例

あるデジタルトリアージサービス:クラウド支出は月£62,000(コンピューティング£30k、データ£18k、共有プラットフォーム配分£14k)、月380,000件のトリアージエピソードを処理:

```
エピソードあたりの平均費用 = 62,000 / 380,000 ≈ £0.163

コミッショナーとの比較:電話トリアージ≈£8〜12/通話、GP診察≈£42
→ デジタルエピソードは最も安い人間の代替手段の約2%で運用されます — これは
gds-service-metrics.mdのチャネルシフトの経済学を、費用側から見たものです。

トレンドの確認:昨年は240,000エピソードで£0.21/エピソード → 規模の経済が
改善している(固定プラットフォーム費用が償却されている)、QBRで見出しにする価値あり。
```

## ソフトウェア工学との関連

単位経済学は、エンジニアリングの選択が財務的に可読になる場所です:エピソードあたりの費用を半分にするアーキテクチャは価格優位性であり、超線形にスケールするものは、この指標でしか見えない時限爆弾です。医療の費用計算から転用できる実践:**配分ルールを公表すること**(PLICSが患者レベルの費用計算を標準化するまで、共有費用は単位あたりの数値を歪めていました — あなたのプラットフォーム費用の配分にも同じ厳密さが必要です);**購入者が考える単位を選ぶこと**(コミッショナーはvCPUではなくエピソードを買います);そして、単位費用をあらゆる[ICER](../incremental-cost-effectiveness-ratio/)と[予算影響](../budget-impact-analysis/)モデルに権威ある費用の分母として供給することです。AI機能については、単位はトークンです — [推論単位経済学](../inference-unit-economics/)を参照してください。

## 落とし穴

- **共有費用を無視すること**:プラットフォーム/セキュリティ/オンコールの配分を除いた単位費用は30〜50%過小評価され、監査で崩壊します。
- **見栄えのための分母**:「APIコールあたりの費用」は実際以上に良く見せますが、「完了した患者エピソードあたりの費用」は情報を与えます。
- **限界的な意思決定への平均費用の価格設定**:限界的に無料である利用にチームへ平均単位費用を請求することは、無駄回避の茶番を促します(このインセンティブのバグのNHS版については[全国診療報酬](../national-tariff-and-unit-costs/)を参照)。
