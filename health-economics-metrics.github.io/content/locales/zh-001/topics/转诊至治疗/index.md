# 转诊至治疗（RTT）

转诊至治疗，是指从全科医生转诊到由顾问医生主导的治疗正式开始之间所经过的时间。《NHS宪章》设定的标准是：**92%的患者应在18周内开始治疗**。RTT是英格兰NHS体系中政治能见度最高的单一运营指标。

## 为何重要

未能达成RTT目标的信托机构会面临监管审查、介入干预与声誉损害；全国等候名单本身就是一个上头版头条的数字。患者每多等一周，都意味着健康的损失（在更差的健康状态下等待——参见下文QALY算术），且往往也意味着成本的增加（病情会恶化；参见[更早干预](../更早干预/)）。任何能在转诊至治疗路径中的任一环节节省时间的软件——分诊、诊断周转、门诊产能、排程——都能直接缓解未达标所带来的运营与财务后果，这也是为什么RTT影响是NHS数字化商业论证中的一条一等效益线。

## 计算方法

```
RTT达标率 = 18周内接受治疗的患者数 / 接受治疗总人数 × 100
每名患者的等待时间健康成本 = 等待时长 × (治疗后效用值 − 等待期效用值)

路径视角：RTT = Σ各阶段时长（转诊分诊 → 首次门诊 →
诊断检查 → 决策 → 治疗）——应改进排队最长的那个环节，
而非最繁忙的那个环节（参见flow-metrics.md）。
```

## 实例演算

某专科每年治疗5,000名路径患者；平均等待24周；等待期效用值0.68，治疗后效用值0.80。

数字化分诊加"直接检查"协议，消除了5周纯粹的排队等待时间：

```
QALY获益 = 5,000 × (5/52) × (0.80 − 0.68) = 每年57.7 QALY
按每QALY £20,000–£30,000货币化（参见willingness-to-pay-thresholds.md）：
  ≈ 每年£115万–£173万的健康价值
```

——此外，该信托机构也由未达标转为达标18周标准，这一点带来的治理层面价值，是任何电子表格都无法完全捕捉的。

## 与软件工程的联系

RTT是一项**跨越多阶段队列的前置时间指标**——是医院版本的"从提交到生产环境的前置时间"（参见[DORA指标](../DORA指标/)）。改进方法完全一致：为每一个阶段埋点，找出日历时间究竟积压在哪里（几乎总是在交接与排队环节，而非临床工作本身），并消除等待状态。典型的软件胜利场景包括：能在数小时内、而非按周批量处理转诊的电子分诊系统、以推送方式而非复诊预约来传递诊断结果，以及自动化的"直接检查"判定标准。应以[延迟成本](../延迟成本/)（以QALY/周为单位）来为这项改进估值。

## 陷阱

- **改进的并非真正的约束瓶颈所在环节**——在诊断队列不断增长的同时缩短首次门诊等待，只是把积压转移到了别处。
- **操纵指标**：路径重置与计时暂停可以在不让任何人更早得到治疗的情况下改善报告出来的RTT数字；应审计其背后的真实分布。
- **将整条路径的改进都归功于单一工具**，而实际上是多项变更同时落地——归因需要一个对照组。
