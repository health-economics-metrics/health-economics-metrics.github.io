# 多準則決策分析 (Multi-Criteria Decision Analysis, MCDA)

多準則決策分析（MCDA）是衛生技術評估中使用的加權和評分模型，用於單一的 ICER/支付意願閾值無法涵蓋決策者所關心的一切時：公平性、未滿足的需求、創新性、預算影響、疾病嚴重程度。每個準則被賦予一個反映其重要性的權重（來自利益相關者，總和為 1），每個備選方案在每個準則上獲得一個歸一化得分（通常為 0–1），總分就是加權和——與軟體供應商評估計分卡同樣的數學形式。

## 為什麼重要

MCDA 被用於 EVIDEM 等框架，以及一些 HTA 機構對孤兒藥/罕見病的評估，在那裡嚴格的每 QALY 成本閾值方法被認為過於狹窄，無法涵蓋決策中重要的一切。ISPOR MCDA Emerging Good Practices Task Force 把獲取站得住腳的權重和得分的良好實踐正式化，正因為非正式的加權決策既容易構造，也容易被操縱。當一項衛生技術具有單一的[支付意願閾值](../支付意願閾值/)無法表示的價值維度——嚴重程度、創新性、公平性——MCDA 為決策者提供了一個明確、可審計的結構來整合它們，而不是一個未說出口的判斷。

## 計算方法

```
MCDA 得分 = Σ_i (權重_i × 得分_i)

權重之和應為 1（透過 swing weighting 或 Analytic Hierarchy Process
等利益相關者方法獲得）
```

## 算例

一個 HTA 委員會按四個準則評估一種數位療法：

```
準則                              權重    得分    權重 × 得分
臨床獲益                          0.4     0.8     0.32
成本影響                          0.3     0.5     0.15
疾病嚴重程度 / 未滿足需求          0.2     0.9     0.18
創新性                            0.1     0.6     0.06
                                  ─────           ─────
                                  1.0             0.71
```

權重之和為 1.0（0.4 + 0.3 + 0.2 + 0.1），MCDA 得分為 0.71（0.32 + 0.15 + 0.18 + 0.06）。委員會把 0.71 與事先約定的閾值比較，或與以同樣方式評分的競爭技術排序。

## 與軟體工程的關聯

這與加權的供應商選擇計分卡、RFP 評估矩陣或功能優先順序評分模型是同樣的數學——關於加權計分卡在軟體採購中的經典用例，見[自建與外購](../自建與外購/)。也值得與 [WSJF 與 CD3](../WSJF與CD3/)對照：WSJF/CD3 是基於*比值*的優先順序方法（延遲成本除以工作量大小或時長），而 MCDA 是加權*和*。MCDA 與 WSJF/CD3 是對“如何給相互競爭的選項排序”這一問題在結構上不同的兩種回答，而弄清某個決策實際需要哪一種——跨獨立準則的總價值，還是每單位稀缺產能的價值密度——比哪個公式看起來更嚴謹更重要。

## 陷阱

- **權重獲取偏差**：誰設定權重，實際上就預先決定了排名，因此“公式”可能把政治或商業決定洗成看似客觀的計算。要記錄誰設定了權重以及如何設定。
- **重複計算已在別處涵蓋的準則**：把“成本效果”作為一個準則打分，*同時*又單獨給“成本影響”打分，會使金錢相對其他準則被過度加權，卻沒人有意為之。
- **虛假精度**：保留兩位小數的加權得分（0.71）所暗示的嚴謹程度，超過了利益相關者在 0–10 量表上的評價所能支撐的，而這些評價中評分者之間的變異往往完全沒有報告。
