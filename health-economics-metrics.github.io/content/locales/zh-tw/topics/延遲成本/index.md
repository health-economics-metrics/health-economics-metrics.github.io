# 延遲成本（CoD）

延遲成本是指某項功能、產品或服務在*未*交付期間，每單位時間所損失的經濟價值。它是軟體交付指標與健康經濟學之間最強有力的橋樑：能將"我們交付晚了"這句話，轉化為貨幣價值——或轉化為QALY。

## 為何重要

Reinertsen法則："如果你只量化一件事，那就量化延遲成本。"大多陣列織知道一個專案要花多少錢，卻不知道延遲一個月要付出什麼代價，於是它們在最佳化預算的同時，正持續流失著時間價值。對醫療軟體而言，賭注是真真切切的：一項路徑改進每延遲一週，病患就要在更差的健康狀態下多等一週。延遲成本是向NHS利益相關方展示時最有力的數學框架，因為它為你軟體的"缺席"本身定了價。

## 計算方法

```
延遲成本 = 未交付期間、每單位時間所放棄的效益   （£/周 或 QALY/周）

總延遲損失 = 延遲成本 × 延遲時長

關於優先順序排序，參見wsjf-and-cd3.md：CD3 = 延遲成本 / 時長。
```

對於臨床軟體，應同時以健康與貨幣兩種單位計價：

```
延遲成本_健康 = 每週受影響病患數 × 每名病患的QALY獲益
延遲成本_貨幣 = 延遲成本_健康 × λ (支付意願閾值，£20,000–30,000/QALY)
              + 每週被放棄的營運節省
```

## 實例演算

**營運場景**：某軟體在一條診療路徑上為每名病患節省£200；某信託機構每週處理50名此類病患。

```
延遲成本 = 200 × 50 = 每週£10,000
一次10周的採購延遲，會造成 200 × 50 × 10 = £100,000 的可避免浪費。
```

**臨床場景**：某項分診改進使每週100名病患的等待時間縮短5周（效用值從0.68提前提升到0.80）：

```
每名病患的QALY獲益 = (5/52) × 0.12 ≈ 0.0115
延遲成本_健康 = 100 × 0.0115 = 每週1.15 QALY
延遲成本_貨幣 = 1.15 × £20,000 ≈ 每週£23,000的健康價值
```

一次6個月的部署延遲，其"代價"約為30個QALY——這一論證能將一次IT系統上線延期，重新定性為一起臨床事件。（作為規模參照：Black Swan Farming著名的馬士基案例研究發現，單個功能的延遲成本可高達約每週$200,000，且該功能已等待了38周。）

## 與軟體工程的聯絡

延遲成本是能讓[DORA前置時間](../DORA指標/)與[流動效率](../流動指標/)在財務上變得可讀的指標：前置時間 × 延遲成本 = 在佇列中被白白燒掉的金錢（或健康）。其用途包括：

- **優先順序排序**：按延遲成本/時長（參見[WSJF/CD3](../WSJF與CD3/)）對工作進行排序，而非按誰的嗓門最大來排序。
- **流程經濟學**：與持續交付相比，一個2周的釋出節奏預期會帶來約1周 × 每個功能的延遲成本這樣的額外延遲成本——為這種"批次交付"定價。
- **採購**：NHS長達6–18個月的採購週期本身就有延遲成本；把這一點展示出來，能改變關於緊迫性的對話（可負擔性方面的對應概念，參見[預算影響分析](../預算影響分析/)）。

## 陷阱

- **假設延遲成本是線性的**：有些工作的價值呈"截止日期"形態（監管日期——過期後延遲成本趨於無窮大，之前則為零），有些則呈遞減形態（先發優勢視窗）。在相乘之前，應先判斷其緊迫性剖面屬於哪一種。
- **對無人想要的產出計算延遲成本**：只有當事物本身具有價值時，延遲才會產生代價；延遲交付一堆垃圾，代價為零。
- **重複計算延遲成本與貼現**：[貼現](../貼現與時間偏好/)本身已經為跨越多年時間範圍的時間因素定了價；延遲成本是同一時間範圍*內*、營運層面的版本。應在按周/月計算時使用延遲成本，在按年計算時使用淨現值調整。
