# ต้นทุนของความล่าช้า (CoD)

ต้นทุนของความล่าช้าวัดมูลค่าที่สูญเสียไปในแต่ละสัปดาห์ (หรือเดือน) ที่การส่งมอบฟีเจอร์หรือการแทรกแซงล่าช้าออกไป

## ทำไมจึงสำคัญ

ต้นทุนของความล่าช้าเปลี่ยน "เราควรทำสิ่งนี้ให้เร็วขึ้น" ที่เป็นนามธรรมให้เป็นตัวเลขทางการเงินที่เป็นรูปธรรม ซึ่งช่วยให้สามารถจัดลำดับความสำคัญอย่างเป็นกลางระหว่างความคิดริเริ่มที่แข่งขันกัน

## คณิตศาสตร์

```
ต้นทุนของความล่าช้า = มูลค่าที่สูญเสียต่อสัปดาห์ × จำนวนสัปดาห์ที่ล่าช้า
```

## ตัวอย่างที่คำนวณแล้ว

ฟีเจอร์ที่จะสร้างมูลค่า £10,000 ต่อสัปดาห์ซึ่งล่าช้าไป 8 สัปดาห์ มีต้นทุนของความล่าช้า £80,000 — แม้ว่าต้นทุนการพัฒนาของฟีเจอร์เองจะไม่เปลี่ยนแปลงก็ตาม

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

แนวคิดพื้นฐานในการจัดลำดับความสำคัญของการพัฒนาซอฟต์แวร์; ดู [WSJF และ CD3](../wsjf-and-cd3/) สำหรับการนำไปใช้ในการจัดลำดับความสำคัญอย่างเป็นระบบ

## ข้อผิดพลาดที่พบบ่อย

- **การคำนวณต้นทุนของความล่าช้าโดยไม่พิจารณารูปร่างของการกระจายมูลค่า (เชิงเส้นเทียบกับลดลงอย่างรวดเร็ว)**
- **การสับสนระหว่างต้นทุนของความล่าช้ากับต้นทุนการพัฒนา**
