# AI监管评估

医疗领域AI监管框架——美国FDA的"软件即医疗器械"（SaMD）制度及其**预定变更控制计划（PCCP）**，以及诸如NHS"医疗与照护AI奖"这类真实世界评估项目——及其在经济上的成本与可实现价值。

## 为何重要

监管既决定了**进入市场所需的证据成本**，也决定了**此后每一次模型更新的成本**——对AI产品而言，后者往往更为关键。FDA传统模式（锁定模型；每次变更都需重新审批）使持续改进在经济上极为艰难。**PCCP指南（2024年12月定稿）**改变了这一经济格局：制造商可以预先获得对*特定*未来模型更新的授权——包括对计划中修改内容的说明、修改协议（每次修改将如何被验证）、以及影响评估——从而使经批准的改进无需新的申报即可上线。目前已有超过1,000款AI赋能设备获得FDA授权；FDA现在也开始探索真实世界性能监测（预先设定的指标：基线假阳性/假阴性率、校准漂移、领域偏移指标）。

## 计算方法

PCCP本质上是将[DORA前置时间](../DORA指标/)经济学应用到受监管模型上：

```
每次模型更新成本（传统模式）  = 重新申报成本 + 审查延迟 × 延迟成本
每次模型更新成本（PCCP范围内）= 仅协议执行成本

产品全生命周期内的更新经济学：
  N次更新 × (申报成本 + 审查月数 × 每月延迟成本)
  对比：一次性PCCP撰写成本 + N次协议执行成本
```

对于NHS AI奖这类模式而言，其指标体系比单纯的准确率更广：独立的真实世界评估会同时考察临床表现、工作流程/实施层面的影响以及经济影响——这实质上是将完整的[效力 → 实效 → 成本效果](../AI与开发者生产力/)链条制度化。

## 实例演算

某放射影像AI供应商计划在3年内每季度进行一次模型改进（共12次更新）：

```
传统路径：12 × (£80,000申报费 + 4个月 × £50,000/月的延迟收益成本)
        = 12 × £280,000 = £336万
PCCP路径：£250,000一次性PCCP撰写成本 + 12 × £30,000协议执行成本 = £61万
节省约 £275万——且患者能提前约4个月获得每一次改进带来的收益：
12 × 4个月 × 每次更新的临床获益，这本身就构成独立的一条QALY收益线。
```

PCCP是监管机构对"**部署频率本身具有临床价值**"这一本书核心因果链条的正式认可。

## 与软件工程的联系

把PCCP做好本质上是一个软件工程问题：预先设定的评测套件、有版本管理的数据集、自动化验证流水线、漂移监测——这正是持续部署在受监管场景下的对应版本，只不过其"部署关口"是经验证的协议，而非代码评审。拥有成熟评测基础设施（[AI质量指标](../AI质量指标/)）的团队，能以较低成本获得PCCP；缺乏这种基础设施的团队则会发现，所谓的监管约束其实是工程成熟度的约束。对于进入NHS市场的产品，与之平行的技术栈是DTAC（临床安全、数据保护、互操作性）以及[NICE证据标准框架](../NICE证据标准框架/)的证据分级——二者都应作为市场准入的[总拥有成本](../总拥有成本/)一并预算。

## 陷阱

- **对PCCP范围抱有过度幻想**：只有*明确列明*的修改类型才获得预先授权；架构变更或新的预期用途仍需完整审查。
- **真实世界漂移未被监测**：上市时的授权性能表现 + 悄然发生的人群漂移 = 产品在已获批准的使用范围之外运行；监测既是监管要求，也是自我保护。
- **混淆获批与价值**：FDA/UKCA获批 ≠ 会有人为此付费——那是[卫生技术评估](../卫生技术评估/)这道单独的门槛。
