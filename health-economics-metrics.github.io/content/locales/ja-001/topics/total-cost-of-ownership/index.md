# 総所有コスト(TCO)

TCOとは、システムの生涯にわたる完全な費用のことです:取得または構築、統合、運用、保守、サポート、トレーニング、そして廃止です。居心地の悪いベースライン:**保守はソフトウェアTCOの50〜80%**を占めます — 生涯費用のおよそ4分の3が、稼働開始*後*に発生します。

## なぜ重要か

医療技術評価はずっと前に、医薬品の価格はその費用ではないことを学びました — 投与、モニタリング、副作用の管理はすべてモデルに含まれます。構築/ライセンス費用だけを数えるソフトウェアのビジネスケースは、この素朴な医薬品価格の誤りを繰り返し、それが供給するすべての[ICER](../incremental-cost-effectiveness-ratio/)と[予算影響](../budget-impact-analysis/)の費用側を体系的に過小評価します。NHSの調達にとって、TCOの規律こそが、デジタル製品の費用効果の主張を正直にするものであり、そこで安く見える選択肢が負けるのです。

## 数式

```
TCO = 初期費用(構築/ライセンス+統合+データ移行+トレーニング)
    + Σ_t [運用+保守+サポート+インフラ+アップグレード
           +コンプライアンス/保証]_t / (1 + r)^t
    + 廃止費用(撤退、データ抽出、並行運用)

評価期間:商業的には3〜5年、臨床インフラはシステムの寿命
r:公共部門3.5%(グリーンブック)、商業8〜12%
基準値:年間保守 ≈ 構築費用の15〜20%;生涯TCOの約78%が稼働開始後;
廃止とベンダーロックインを無視することは、それ自体が値段です。
```

## 計算例

eオブザベーションシステムの2つの選択肢、5年間の評価期間:

```
                        ベンダーSaaS    自社構築
0年目(ライセンス/構築)  £250,000        £900,000
統合+トレーニング        £180,000        £150,000
年間運用(1〜5年目)      £120,000/年     £190,000/年(ホスティング+1.5FTEの保守)
撤退/廃止                £60,000         £30,000

割引前TCO                £1,090,000      £2,030,000
```

構築オプションのエンジニアリング見積もり(£90万)は、実際のTCOのわずか44%にすぎませんでした — そして構築の見積もり自体が典型的には30〜40%超過します([内製か購入か](../build-vs-buy/)を参照)。自社構築の選択肢が実質的に異なる*アウトカム*をもたらさない限り、[費用最小化](../cost-minimization-analysis/)のロジックが適用され、SaaSが約£94万の差で勝ちます。

## ソフトウェア工学との関連

エンジニアは、構築を提唱するとき、自分たちの分野自身の保守データを過小評価します:構築費用の15〜20%という年間保守のルールは、£100万のシステムはそれぞれ、静かに年間£15万〜20万の将来の容量をコミットすることを意味します — これは[技術的負債](../technical-debt/)と同じ心の貸借対照表に属する負債です。TCOはまた、このリポジトリのあらゆるメトリクスの費用側でもあります:デプロイあたりの費用、[クラウド単位経済学](../cloud-unit-economics/)、そしてHTAが医薬品スポンサーに課す分母の規律です。あなたの製品の価格が異議を唱えられたとき、既存のシステムの真の運用費用を含むTCO比較は、通常、利用可能な最も強力な再構成です。

## 落とし穴

- **稼働開始費用への固定**:0年目の費用で選択肢を比較すること。順位は3年目までに逆転します。
- **無料の社内労働という誤謬**:「チームはすでにいるから」という理由で自社保守の費用をゼロとすること — [機会費用](../opportunity-cost/)を参照してください。
- **撤退費用を無視すること**:データの持ち出し、契約解除、並行運用こそが、「安い」SaaSが高くつく場面です。
- **異なる評価期間の混用**:3年のSaaS TCOを10年の構築の償却と比較すること([評価期間](../time-horizon/)を参照)。
